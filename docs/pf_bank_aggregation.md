# PFバンクの「本数を増やしても壊れない」表現 — 集約特徴/セットエンコーダ(今後の実験メモ)

> 2026-07-06 の議論のメモ。**未実験**(①③をいずれ試す)。基準は train OOF CV ≈7.0([[v28-self-nbr-gbm]])。

## 問題
LightGBM に PF を何本も列として並べると精度低下(v20: 7本→OOF≈8.0 で v9 超えず / v24 悪化)。
原因は相関そのものではなく:
1. **PF列を並べる=モデル内で per-region の「PF選択」をさせている**。選択は全信号で失敗確定
   (v20 signal_compare: 各PFの当たり外れ≒ノイズ)→ ノイズから選択を学ぶ=train過学習。
2. 各PFは train チューニング済みなので、**1本足すごとに増えるのは共通信号でなく train固有の癖**。
   K本の微妙な差分=癖の差分を木が拾うと悪化。

→ 対策の本質 = **モデルに個々のPFを識別させない(選択をさせない)表現**にすること。

## やること(採用候補)

### ① 集約特徴化(permutation-invariant summaries)【GBM向け本命・面白い】
K本を K列でなく**並べ替え不変な固定次元統計量**にして入れる(本数が9本でも50本でも列数一定):
- 位置: median / trimmed mean(**素朴meanは双峰の谷に落ちるので不可** — v22バンク平均7.859の教訓)
- 散らばり: std / IQR / range / 「median±2ft以内の本数」(合意度)
- **★双峰系(核心)**: K本を2クラスタに分けて `μ1, μ2, |μ1−μ2|, p(勢力比)` — 平均が壊す双峰を壊さずに
  「2モードの位置と勢力比」という分布情報だけを渡す
- baseline差: median − pf_ancc(tw) 等
- 実績: v28 の `pf_agree_std`/`pf_self_mean`/`pf_self_pstd` はこの縮小版で害なく効いた。
- 素材: v19 _re バンク(r0〜r8)+v9 pf1/2/3 の12本など。

### ③ v29 NN の PF軸 set-encoder(DeepSets / attention pooling)【面白い】
各PF軌跡を「集合の要素」として**重み共有エンコーダ**→PF軸に mean/attention プーリング。
並べ替え不変で**本数任意**(推論時に本数が変わってもOK)。①と違い「どの統計量が有効か」自体を学習できる。
v29(train_nn_v29)の入力前段に挟む形で実装可能。

## やらないこと
- **② PFごとに別モデル→出力アンサンブル: 過去に実験済みでダメ(ユーザー確認済)。却下。**
- **④ PCA/SVD で PFブロック直交化: 見送り**(分散基準でtarget基準でない、双峰情報を保てない)。

## oracle の読み方(_re バンク, 2026-07-06)
- check_bank_oracle_re で **oracle ≈ 5.0(CV)** が出たが、2つの割引が必要:
  1. **順序統計**: K=12本なら誤差が独立ノイズでも per-well min は大きく下がる(v18 oracle4.62 到達不能の教訓)。
  2. **_re バンクは in-sample チューニング**(r1〜r8 は対象井戸を直接目的化)→ train内の「勝ち」は転移しない公算大。
- **★安い診断(未実施)**: r0 を seed だけ変えた12本の oracle を出す。それも~5.5まで下がるなら
  _re バンクの oracle 5.0 は seedノイズの min 取りでほぼ説明でき、固有の相補性は薄い。
  6.5 程度に留まるなら本物の相補性あり → ①③で分布情報として回収を試す価値が上がる。
