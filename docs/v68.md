# v68 — GF-MR: 多表現マッチテンソル × 学習emission × 微分可能グリッドベイズフィルタ

> 発端(2026-07-14 ユーザー): 「GR の表現(neighbor/self/tw、MD-10間引き、grid、MA/EMA)で予測が変わる。
> 全表現を入力に与えれば GR 自己相似性を解きながら精度大幅向上できるのでは。単一メソッドで oracle を目指したい」。
> 私の設計提案 → v68 として実装。プロジェクト自身の「残る軸=生画像CNN/候補生成」(v47)・hengck23「候補生成=DETR系」と一致。

## 仮説
GR の自己相似性(±15-25ft Milankovitch cycle → 双峰 datum)は**単一表現では解けない**(v47/v50 の ~56% 枝判別壁)。
だが **真 δ は tw+self+nbr の全表現で合意/偽 δ(cycle alias)は tw だけ合う** なら、**全表現の joint 合意**で判別できる。
→ 全表現を1つのモデルに融合し、branch-commit oracle(v50 実測 5.17)方向を狙う。

## 設計(`v68/gridfilter_v68.py`)
- **多表現マッチテンソル** `[MD, δ, channel]`(δ=struct中心 ±DR):
  `tw-raw / tw-MA / self / self-valid / nbr / nbr-valid / struct-prior` の 7ch(拡張自由: EMA/複数grid/複数nbr…)。
  self=自prefix、nbr=近傍train(≤1500ft・≤3・LOO)を共通TVTグリッドへ median 集約。
- **学習emission**(小さい共有MLP C→H→1): (MD,δ) 毎に全ch融合 → emission logit。**全 (MD,δ)・全井戸で共有=並進不変・過学習面小**。
- **微分可能グリッドベイズフィルタ**: forward-backward、遷移=Gaussian(dip連続 prior、σ学習)、emission=softmax。
  δ の posterior γ → **posterior-mean δ 出力**(双峰ヘッジ, error_anatomy §4)→ `TVT = struct_tvt + pmean`。
- **物理(フィルタ)は転移する構造、学習は emission だけ** = v64 全CNN(LB9.46, field過学習)を避ける設計。v40/v48/v51-52 の系譜。

## 追加: GF-IMG(画像法, `v68/gridimg_v68.py`)+ struct有り無しトグル
GF-MR は各(MD,δ)セルを**点ごと**にMLPで見るだけ=「δ帯がMD方向に連なる/孤立」の2D文脈を使えない。
→ **match tensor を画像 (B, C, H=MD, W=δ) とみなし 2D UNet に通す**版を追加(ユーザー依頼「画像的に」)。
- CNN が「同じδ帯が多数のMD行で一貫して光る=本物 / チラつく=cycle alias」を**2D空間で**判別 → emission を鋭く(disambiguation)。
- **v64 との差**: 入力が生GR窓でなく **struct/anchor で δ 整列済みの match tensor** = 条件が良く汎化が期待できる。UNetは δ(W)を全解像度維持・MD(H)のみdown/up(oracleのδ分解能を保つ)、norm無し小容量(過学習ガード)。
- **HEAD**: `filter`(既定, CNN emission→gf.bayes_filter=dip連続) / `direct`(softmax→pmean, 純画像=多様性脚)。
- **メモリ実測**: stride4/IMG_BATCH4 で **peak 0.39GB**(点MLP版と同等に軽い。VRAM∝B×T×c)。

### ★struct有り無し両対応(GF-MR/GF-IMG 共通 `STRUCT` env)
- `STRUCT=1`: 窓中心=struct s_tvt、struct-prior ch込み(7ch)、δ=±DR(45)。出力=s_tvt+δ。
- `STRUCT=0`: 窓中心=**base_free=末端既知TVTの水平保持(flat hold≈naive15, 有界)**、6ch、**δ=±DR_FREE(150)/DSTEP_FREE(2)=広く粗く**(構造残差を包む=well-posed)。出力=base_free+δ。
- 1つのcacheで両対応(グリッドは両モードを包む GRID_MARGIN)。cacheに `base_free` を格納。
- **スモーク実測(40坑井, well)**: struct-free は well-posed 化(anchor 11.79 / δ-oracle 0.57)。
  **GF-IMG struct-free=12.85(≈anchorで踏み止まる, 頑健)vs GF-MR struct-free=54.35(点フィルタは錨無しで drift=v67純GR漂流の再現)** →
  **struct-free では画像法(2D文脈)が点フィルタの drift を抑える** = 画像法の存在価値。struct-free は本質的に難(既知)、画像/directが正解パス。

## ★転移ガードレール(成否の分かれ目)
- **leave-field-out 必須**(XY を KMeans で N_FIELDS 化 → **5-fold GroupKFold on fields**、holdout field は train に不在)。
  井戸 GroupKFold は field 指紋過学習を見逃す(v34墓標 in4.99/OOF6.75/LB7.28)。**field-out で struct を超えれば転移確定**。
- emission は**小容量MLP**(HID~24, 2-3層)。容量を上げたくなるのを我慢(過学習を殺す)。
- posterior-mean 出力(双峰ヘッジ)。単峰commit は field-out で判別率>56% を確認後。

## 使い方
```bash
# 0) cache(gf/img 共通。stride と STRUCT モードに依らず1つで両対応。cache名に stride を埋込)
EVAL_STRIDE=4 .venv/Scripts/python.exe v68/gridfilter_v68.py cache
# 1) GF-MR(点MLP+フィルタ)  struct有り / struct無し
CV_MODE=field STRUCT=1 EVAL_STRIDE=4 .venv/Scripts/python.exe v68/gridfilter_v68.py train
CV_MODE=field STRUCT=0 EVAL_STRIDE=4 .venv/Scripts/python.exe v68/gridfilter_v68.py train
# 2) GF-IMG(2D UNet 画像法)  struct有り / struct無し / 純画像(direct)
CV_MODE=field STRUCT=1 EVAL_STRIDE=4 .venv/Scripts/python.exe v68/gridimg_v68.py
CV_MODE=field STRUCT=0 EVAL_STRIDE=4 .venv/Scripts/python.exe v68/gridimg_v68.py
HEAD=direct  CV_MODE=field EVAL_STRIDE=4 .venv/Scripts/python.exe v68/gridimg_v68.py
```
共通env: `CV_MODE(field) STRUCT(1) N_FIELDS(16) EPOCHS(15) LR(2e-3) DR(45) DSTEP(1) GSTEP(0.5) GR_SIG(15)`
`TRANS_SIG0(2) MA(10) MAXNBR(3) NBR_DIST(1500) EVAL_STRIDE(4) N_WELLS(0=全) DR_FREE(150) DSTEP_FREE(2)`
GF-MR専用: `BATCH(8) HID(24)` / GF-IMG専用: `IMG_BATCH(4) HEAD(filter|direct) CH(16,32,48) IMG_EPOCHS IMG_LR`
- **★EVAL_STRIDE はキャッシュ時に効く**(cache名に `s{stride}`)。stride を変えたら cache/train で同じ値。
  eval行を stride 間引き→T(逐次ループ長)を 1/stride に=**時間もメモリも∝1/stride**。stride4≈1.5h/stride8≈46min(GF-MR, EPOCHS15×5fold)。
- **メモリ**: GF-MR は build_channels (B,T,D,7) が VRAM∝B×T → **BATCH=8据え置き**(48で溢れる)。GF-IMG は stride4/IMG_BATCH4 で 0.39GB。速度はstrideで稼ぐ。
- fold は 5(16fields→5-fold)なので学習は5回。進捗は20秒ごとに `ep 12/77b rows.. eta..` を出力。

## スモーク実績(2026-07-14, 40坑井/stride4, 実装検証)
- **端到端 OK**: cache・マッチテンソル・微分可能グリッドフィルタ(forward-backward)・emission MLP・leave-field-out・OOF・oracle算出。学習収束(fold rmse 13.8→7.4)。
- **★δ格子 oracle = 0.29ft**(δを最適選択すれば ほぼ完璧)= **表現が豊か。disambiguation さえできれば oracle に届く**ことを実証(金脈の存在)。
- leave-field-out overall 9.93 vs struct 8.62 = **in-sample 7.5 < struct だが out-of-field 9.93 > struct = フィールド過学習**
  (3-6フィールドの極小スモークゆえ。まさに転移の壁を早期可視化)。**本学習(773坑井/16fields)で field 汎化するかが本番判定**。

## 判定と次
1. **本学習(773坑井, `EVAL_STRIDE=2`, EPOCHS 15+)を leave-field-out で**。見るのは:
   - **field-out overall が struct(~7ローカル)を超えるか**(= 転移する disambiguation を学べたか)
   - **oracle 0.29 との差がどれだけ縮むか**(= branch commit がどこまで効くか。5.17 方向)
2. 超えれば oracle 路線が開通。超えなければ **diversity 脚として GBM(v52)に供給**(posterior-mean を特徴化)→ どちらでも無駄にならない設計。
3. 強化レバー(field汎化後): EMA/複数grid/複数nbr の ch 追加 / 遷移に dip drift / mixture出力(双峰の質量を明示)。

## 実装メモ
- 出力 = `struct_tvt + posterior_mean_δ`。emission が無情報なら posterior は δ=0(struct)に寄り ≈struct(安全な退化)。
- oracle は δ格子で真に最も近い δ を選んだ RMSE(到達不能上限, DSTEP=1で~0.3)。struct基準・oracle を毎回併記。
- 資産流用: struct=[[v66-struct-upgrade]] pkl / self-nbr grid=v52 `_bin_grid` 思想 / field分割=[[v67-arf-neural-filter]] / 微分可能grid=v40。
