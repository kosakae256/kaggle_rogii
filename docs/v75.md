# v75 — v69_4 の PF に v73 部品を注入した tabular/TCN(単純比較)

## 仮説
[[v73-pf-ml-parts]]で確定した単体PF改善(structgate −1.14 / +NN emission W0.01, 計 8.665→7.107)を、
**v69_4 と同一のチェーン(create→tabular/TCN→submit)に注入**すれば v69_4(CV6.448/LB6.6)を更新できるはず。
**v69_4 との単純比較**: PFパラメータは同じ p_1..p_5(5本, n_seeds=32, lag16, 錨なし, DEC全1)。変更はPFエンジンへの v73 部品注入のみ。
(※v74はGRフリー診断の別ラインで使用済みのため v75)

## 変更点(v69_4 → v75) — PF生成コアへの注入のみ
1. **段a structgate**: `rate ← mom·rate + K_t·(struct_dip − rate) + noise`、K_t=0.02·exp(−0.5(σ/6)²)。
   - dip/σの出所=**v38 struct_prior_train.pkl**(v73と同一, ev行整列tvt/sig)。dip=clip(rollmed21(grad(tvt+z,md)),±2)。prior欠損/行数不一致はK=0。
   - **tw/self/nbr 全15ランに適用**(遷移レベル=ソース非依存)。
2. **段b NN emission**: 重み更新のみ `w ← w·lk·exp(0.01·sim)`(sim=v51/artifacts_v51/sim_rows_v51.pkl, struct帯±45ft·0.5ft刻み181bin, 帯外sv=−1)。
   - **twラン(pf_ancc_1..5)のみ**(v73実証範囲。self/nbrには混ぜない)。
   - **log_lik(seed合成)は純GR lkのまま**(v73忠実仕様: avg=(w·lk)を先に累積)。
- K/SGATE/W_NNはv73確定値のまま無調整(=単純比較)。特徴スキーマはv69_4と同一(train系はパス差替)。

## 実装(パッチ点 — create_candidates_v69_4.py 基準の行構造)
- `v75/_build_v75.py`(生成器) → `v75/create_candidates_v75.py`:
  1) パス: artifacts_v69_4→(v75/)artifacts_v75、PFキャッシュ名 pfpass_cache_v69→v75(stale防止)
  2) `_attach_anchor` の直後に `_attach_v75(x, wid, use_sim)` を追加: rtq(dip目標)/rtk(K_t)/stq(帯中心)/simt(181bin f16)を x に付与。
     _V75_SP=v38 struct_prior_train.pkl / _V75_SIM=sim_rows_v51.pkl をモジュール先頭でロード
  3) `_v26_pad`: rtq/rtkt(0既定)・stq(0)・simt(−1, f16) をパディング
  4) `_v26_smoother_core`: 伝播に `+ rtkq[:,i][:,None]·(rtq[:,i][:,None]−rate)`(clip前)、重み更新の lk に
     `jj=round((v−stq)/0.5)+90 → sv(帯外−1) → lk2=lk·exp(0.01·sv)`(avg/log_likはlkのまま)。simt未提供時は素通し
  5) `run_smoother_ext`: 新テンソルの rep 受け渡し(simt は W側のまま wmap=arange(w).repeat_interleave(S) で索引)
  6) バンクループ3箇所: `_attach_anchor(...)` → `_attach_v75(_attach_anchor(...), wid, use_sim=<twのみTrue>)`
  7) DEC>1ガード: v75はDEC全1。_decimate_inp に rtq/rtk のmean集約を追加、sim使用時DEC>1はassert
- train_tabular_v75.ipynb / train_nn_v75.ipynb: v69_4のパス差替コピー(artifacts_v69_4→artifacts_v75)
- submit_nn_v75.ipynb: v69_4 submit に同コアパッチ。test側: structgate= submit内 test-struct dict(v46_build_test_struct, v38系)を_V75_SPに流用 /
  **test側sim= v50エンコーダ(stageA_enccapaug_f*.pt)をtest坑井GRに前向き実行して帯simを構築(v52 submit_tabular_v52.ipynbに機構あり=移植)**。
  Kaggle添付物: 既存+v50エンコーダckpt(5fold)+struct_prior系。

## ★★LB結果(2026-07-21): **6.95 = 転移崩壊**
CV 6.1006 → **LB 6.95(Δ+0.85)**。v69_4(CV6.448→LB6.6, Δ+0.15)より**LBで悪化**。
**v69_3(錨)と同型の struct 転移崩壊が、structgate(遷移レベルのdip引き戻し)でも発生**。
読み: ①train側prior=LOOでも**同fieldの隣接坑井は残る**=坑井GroupKFold CVはfieldリークでstruct品質を過大評価
②test側struct(v46場クエリ)は空間外挿で劣化し、系統偏りdipへの引き戻しは毒(v73精度→効果曲線の「構造誤差=毒」がtestで発現)
③σゲートはtrain σ分布で較正(SG6)されておりtestの外挿σを捕まえない。
→ **struct系の採否判定は leave-field-out が必須**(v34/v68の教訓が伝播レバーにも適用)。
