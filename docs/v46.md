## 仮説
v41(錨PF pfA 単体)は tabular で LB7.994(CV7.4, 転移率1.08)= 錨を焼くと v36 の GR増幅転移が死ぬと判明。
一方 v28 の物理無しPF(pf_1/2/3)は素直に効く。**物理錨(pfA)と物理無し(r0/pf_3)を1つの特徴表に同居**させ、
GBM に「錨あり/なし両方の PF 証拠」を渡して選ばせる。錨=tail(硬い核), 物理無し=median の二正面を GBM 内で合成する狙い。

## 変更点(v41 → v46)
- **PF を3バンクに**: `PF_BANK = ["pfA", "r0_seed32", "pf_3"]`(接尾 _1/_2/_3)。
  - `pfA` = v38 錨付き調整済み(struct×mult30, `v38_submit_pack.json`)= **物理錨 ON**。
  - `r0_seed32` = v25 の r0(LB6.786基盤PF, use_phys=False)= **物理無し**。
  - `pf_3` = v28 の pf_3(物理無し)。
  - パラメータは全て **v28 PF_LIB / v38 pack のまま**(そのまま流用, 新規チューニング無し)。
- **バンク別錨**: `PHYSICS_BANKS = {"pfA"}` を追加し `_attach_anchor(x, wid, physics=...)` 化。
  pfA だけ struct錨 ON(anc/ancs 添付, mult=30)、r0/pf_3 は `ancs=1e9`=錨OFF(尤度に無影響)。
  smoother の tw/self/nbr 3パスとも `physics=(p["label"] in PHYSICS_BANKS)` で切替。
- **smooth lag = 16**(v41=192)。実験段階は生成が重いので軽量化。**本番は192で再生成**推奨。
- 出力先/キャッシュを v46 に(`pfpass_cache_v46.npz`)。
