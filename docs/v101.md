# v101 — per-seed 候補を L5 機構で「取る」

> 狙い: 今の PF 出力は **seed=32 の尤度加重平均**(pf_banks_v95.py:554-560)。この平均で潰れている情報を
> L5(cross-attention soft-ensembler)の機構で拾い直し、精度を上げる。
> ★L5/選択路線の過去知見と突き合わせて「効く角度」と「壁」を最初に確定してから実装する。

## 仮説(ユーザー案)
- 現状 = seed 平均。もし「良い軌跡」を正しく取れれば精度が大きく上がるはず(per-seed oracle は非常に低い)。
- L5 と同じ機構(候補トークン→cross-attention→凸結合)を **per-seed 候補**に適用すれば、良い軌跡を選べるのでは。
- **入力(何を候補トークンとして渡すか)が肝**。

## 過去知見との突き合わせ(先に壁を確定する)
1. **per-seed oracle は蜃気楼**([[candidate-oracle-selection-bottleneck]] [[datum-direction-wall-final]]):
   v99 50候補 well-oracle 2.51 / row-oracle 1.30 だが、**achievable な選択 probe(GBDT well選択)= 6.55 で L5(5.80)に負ける**。
   gap の正体 = **datum 枝(±15ft 双峰)の判別**が幾何/GR全表現/運動学/空間の全4軸で AUC~0.50(+文献2件)= **情報限界**。
   → 「良い seed を当てる」= この oracle を取りに行くこと = **構造的に到達不能**。ここに期待値を置くと必ず外す。
2. **L5 は選択器でなく soft-ensembler**([[l5x-candidate-crossattn]]):
   top-k5=+0.313 / prune58=+0.107 / シャープ化・選択強化(L5x cross-attn)は全悪化。**全候補 softmax が最適**。
   → per-seed を L5 に素で渡すと L5 は**平均し直すだけ**。しかも同バンク内 seed は同一パラメータで相関が高い
   (near-duplicate)ので、32本の soft平均 ≒ 今のバンク平均。**素の per-seed 露出では利得ほぼ無し**。
3. **平均は多峰で壊す**(v19/v22, [[v88-likelihood-self-composite]]):
   双峰 datum 井では 32 seed が2枝に割れ、尤度加重平均は**谷(midpoint=両枝とも外す)**に落ちる。
   → **これが唯一、per-seed が平均に勝てる場所**。枝構造を保持できれば soft加重を谷から優勢枝へ寄せられる。
4. **v34 の前例**(per-seed dump → モードゲート posterior-mean)= LB 5.930(当時ベスト, +0.039 転移)。
   → per-seed 候補 + soft posterior は **小さく本物の転移**をしたことがある(oracle の -2〜3ft ではなく ~-0.04)。

## 結論(方針)
- 期待値を **oracle(-2〜3ft)ではなく v34 規模(~-0.04 LB)** に置く。それでも現ベスト(v99 LB5.637 / v100 CV5.5871)に積める。
- 効く角度は **「良い seed を選ぶ」ではなく「平均が壊す枝構造を L5 に渡して谷回避させる」** の1点に絞る。

## ★入力設計(肝)— 3案
候補トークン = L5 の入力。ここで per-seed の"何を"渡すかが全て。
- **A. 素の per-seed(32×15=480 token)**: ❌ 冗長(同バンク相関高)・巨大・過学習。L5 は再平均するだけ=利得無し。**却下寄り**。
- **B. モード集約(推奨)**: 各バンクで 32 seed を **datum枝で K=2 クラスタ**(offset 符号 vs バンク平均 / last_known での arrival δ で分ける)。
  各モードの token = {モード平均カーブ(L5曲線トークン), モード質量=seed比率, モード内分散, モード間gap}。→ **2×15=30 token**。
  枝を保持したまま冗長を消す = **平均が壊した情報だけを L5 に渡す**。v34 の思想を L5 の cross-attn 機構に載せた新結合。
- **C. B + 不確実性**: B に加え per-position の seed分散(既存 `std`)を confidence チャネルとして各 token に付与。
  L5 が「分散の大きいバンク/モードを per-row で down-weight」できる。B の上乗せ、低コスト。

**推奨 = B(必要なら C まで)**。理由: 壁(datum判別)を越えようとせず、平均の谷回避という achievable な利得だけを取りに行く設計。

## 実装メモ
- per-seed dump は既存 `run_smoother_ext(..., capture=True)` の `ps(S,T)`(pf_banks_v95.py:508/565)を流用。新規PF不要。
- forward バンク(v96/v97/v100 = 15本)に対して capture 実行 → モードクラスタリング → 30 token を seqfeat/L5 入力に追加。
  - 現 train_combo の PF 出力は平均済み。**capture 再実行が必要**(cache 流用可)。bwd は今回は対象外(まず forward で純増分を測る)。
- L5 は既存アーキ(cross-attention 凸結合)をそのまま使い、**トークン数だけ 15→30 に増やす**([[feature-combo-beats-ensemble]] の「候補トークン増=−0.127」の系譜)。

## 検証計画
- ablation: 現行L5(15 bank-avg token)→ +モード token(30)。**overall CV(GroupKFold5)で純増分**。
- 健全性: per-well で「双峰井だけ」改善しているか(谷回避が効いた証拠)を分離集計。
- 転移注意: NN脚は CV 非転移の前科(v52 TCN/v62 L5/v64 img)。**CV改善が出ても LB 判定まで採否保留**、L5単体でなく blend で見る。

## 結果(2026-08-04, exp_seed_modes_v101.py, pf_1, 全773井)
単体PF(pf_1, tw, emission無し)の seed=32 集約を「平均 vs 2枝選択」で比較(overall RMSE, pfw=PF自体):

| 集約法 | RMSE | vs base | 種別 |
|---|---|---|---|
| baseline(seed平均・現行) | 9.560 | — | — |
| dominant(質量大mode) | 10.521 | +0.96 | GR内部信号→**悪化** |
| minspread(分散小mode) | 11.914 | +2.35 | GR内部信号→**大悪化** |
| **anchor(錨に近いmode)** | **8.971** | **−0.59** | ★独立信号→**改善(oracle42%回収)** |
| oracle2(真値近mode) | 8.146 | −1.41 | 天井 |

- 双峰井 244/773(31.6%), gap中央値 12.0ft(=datum ±15ft 両義)。双峰井のみ oracle2 改善 mean 2.58ft。
- グラフ: `artifacts_v101/seed_modes_pf_1.png`。ps(smoothed)もほぼ同値(base9.52/anchor8.93/oracle8.10)。

### 結論(★この実験の答え)
- **「良い seed/mode を選ぶ」= datum枝を当てる問題**。GR内部信号(dominant/minspread)での選択は**全滅**(壁は本物, [[datum-direction-wall-final]])。
- **しかし GRフリー錨(独立第2推定器, OOF・非リーク)で枝選択すると −0.59 = oracle の42%回収**。**枝判別の外部信号は実在する**=ユーザー案(L5でmode選択)に本物の脚。
- 現パイプラインが取れない理由: **バンク→seed平均(谷)→L5** の順で、L5が見る前にモードが潰れている。L5は錨を特徴で持つが「谷の微調整」しかできず錨整合枝へジャンプ不可。
- 期待値較正: PF単体 −0.59 は blend(CV5.5871)通過で希釈 → 現実天井は **v34規模(per-seed mode+学習ゲート→LB +0.039)**。

### 結論(★v101 seed集約 最終)
- **oracle(mode/per-seed とも)は蜃気楼**。per-seed oracle 5.43/3.96 は「どの seed がたまたま正しい枝&ノイズで当たったか」=順序統計の運=学習不能([[candidate-oracle-selection-bottleneck]])。取りに行けない。
- **ハード選択(1本/1mode を選ぶ)は全部 baseline に負ける**。アンサンブル効果喪失+間違い枝への過剰コミット。
- **唯一生きる achievable = per-seed を「尤度×錨」でソフト再加重 = −0.23**(τ6最適)。まさにユーザーの「L5的ソフト凸結合」。効く信号は**錨(独立推定器)のみ**で、GR内部信号は全滅。
- emission が既に錨を使うため、mode-anchor選択は二重で過剰=死。per-seed soft は残差の錨信号を穏やかに拾うので生き残る。

## 次アクション(推奨・更新)
- 単体PF −0.23 は blend(CV5.5871)通過で希釈 → 現実天井 v34規模(~-0.04 LB)。**小さく risky なレバー**。EV大は依然 脱相関バンク(v100)/ bwd脚。

  1. **最安**: run_smoother_ext の seed 集約重みを `ww *= exp(-d_anchor²/2τ²)` に(1行)。要 per-bank 検証(emissionバンクは二重懸念)。
  2. **筋良**: 各バンクに「尤度平均」+「錨再加重平均(ps_combo)」の2集約を L5 候補トークンで出す([[feature-combo-beats-ensemble]] 候補増、錨信号運搬)。L5がsoft-weight。
- 検証は overall CV 純増分、NN脚CV非転移前科ありで blend 採否・L5単体判断しない。

# ★bwd(逆方向PF特徴)最終結論(2026-08-04): 使えない
現行 v100(K=71 飽和)に bwd を入れる実験を尽くし、**bwd は不採用**と確定。
- **バグ発見・修正**: build_backward の warm-init が tw で `pf_tw` 参照(正=`pf_ancc`)→ **tw全滅(RMSE164/corr0.09)**。修正で tw 復活(RMSE7.01/corr0.888=最強)。self/nbr等は元々正常(corr0.73-0.80)。[[bwd-tw-warminit-bug]]。
- **L5候補追加**: 壊れtw込みK101=+0.14 / 正常のみK95=+0.099、**どちらも悪化**、blend重み0。
- **脱相関診断(決定的)**: 正常bwd consensus の誤差は forward L5 誤差と **corr 0.729=脱相関せず**(forwardの自バンク0.65より高い)。warm-init=forward答えに条件付け([[v10-backward-pf-helps]])+同坑井同GRで同じ硬い坑井を揃って外す。fwd-bwd不一致→L5誤差 corr 0.21=弱く既存agree_std/stdと冗長。
- **効かない根本理由(ユーザー分析, 実測一致)**: v93で効いたのは base K=14 の非飽和ゆえ(少候補には多少精度低い脚を足しても効く)。今は K=71 飽和で、相関0.73・単体弱いbwdを足すと希釈([[l5x-candidate-crossattn]] 飽和則)。
- **措置**: bwd 打ち切り。ローカル full-bwd 再生成は保留。バグ修正は資産として保持(将来 anchor-init 等を試す場合有効)。EV大の v102 ps_combo / 脱相関バンク路線へ回帰。
- 資産: v101/run_l5_bwd_exp.py(seqfeat+L5 ドライバ)、merge_bwd_v101.py、blend_bwd_v101.py、probe_bwd_raw_v101.py。train_combo_bwd.parquet(bpf60列結合済)。
