# v20

> **v10 を「物理ゲートPF × 複数本(バンク)」に置き換えた版**。
> v10流(各PFの pf_* 特徴 → GBMアンサンブル → apply_pp補正 → 提出)はそのまま、
> PFを **v19の物理PF(lk_phys)** に差し替え、PFセットを **v19バンク + v9 の最大7本**にし、**使うPFを選択可**にした。
> 最終更新: 2026-06-30

## 仮説 / 狙い
- 単一PFでは壊滅坑井が残るが、**複数の(別傾向)PFの pf_* 特徴を持たせれば GBM が坑井ごとに使い分け**られるのでは。
- v19の確認: v19 4本 + v9 3本 = 7本の **oracle=5.76 / >10=46**(単純平均8.24は弱い=選択が肝)。
  GBMに各PFの特徴を入れることが「選択」を学習する一形態。ただし**特徴7倍=過学習に注意**(v10で実証済み)。

## v10からの変更点
- **PFに物理項を追加**: `_pf_core` に `lk_phys = exp(-0.5*((rate − dip_prior)/phys_sig)^2)` を実装(v19と同じ)。`dip_prior`=既知ゾーン回帰。
- **PFセット = バンク**: `v19/artifacts_v19/pf_bank.json`(各ラウンドbest) + (任意で)v9 pf_1/2/3。`_make_pf_params` で raw→p 変換、物理キー(`PF_USE_PHYS`/`PF_PHYS_SIG`)付与。
- **選択可**: `SELECT_PFS`(ラベル list, None=全部)。ラベル= v19は `r0,r1,..` / v9は `v9_pf1/2/3`。
- **順方向のみ**(逆方向bpf_/cmp_なし)。
- 非PF特徴(KNN/beam/NCC/幾何)は v9 build_well のまま。

  - ★ `FWD_SEEDS / INCLUDE_V9 / SELECT_PFS` は **create と必ず同じ**(列一致)。現状 create=`INCLUDE_V9=False, SELECT_PFS=None, FWD_SEEDS=32` → submit cell[3] も同値。
  - ビルダー: `scratchpad/build_submit_v20_v2.py`(v9/pf_bank を変えたら再ビルド)。

## 注意 / 論点
- **特徴爆発(7×pf_*)で過学習リスク**。CV-LB乖離を監視。効かないPFは `SELECT_PFS` で外す/特徴選択。
- **n_seed感度**: バンクは8seedで調整。`FWD_SEEDS` は **train/test で必ず同じ値**に。大きくし過ぎると尤度加重が別モードに寄り悪化しうる([[v19-pf-bank-boosting]])。
- physは全PFで弱め(Optuna判断)だが、v9(物理OFF)とv19(物理弱)の差自体が相補に効く。
- v9 build_well は exec 再利用(FI/DI は DATA_DIR/train で fit)。test も同関数で生成可。

## 結果(2026-06-30)
- **Public LB**: 物理PF r0〜r3 + v9 pf1/2/3 の**7本=7.012** / 物理バンク r0〜r4 の**5本(INCLUDE_V9=False)=7.145**。
  → **v9 pf1/2/3(物理OFF)を足した方が良い**(7.145→7.012)＝物理バンク単独は弱い。いずれも **v9 6.946 に届かず**=PF系統頭打ち。
- 7本PF特徴(INCLUDE_V9=True時)で **691特徴 × 378万行**。**GBM OOF ≈ 8.0 ≈ v9 OOF 7.99**(→apply_pp で~6.9)。物理PF＋多PFでも v9 を明確に超えず。
- メモリ注意: 691特徴×378万行で `df`+`X` が ~21GB → クラッシュ。train は **ROW_FRAC で行間引き(0.5で実害ほぼ無, 行は隣接でほぼ重複)** ＋ float32 ＋ df解放 ＋ 学習済みfold skip(再開)で回避。
- **PF選択の実験(`v20/pf_selector_simple_v20.ipynb`)は失敗**: 各PFを(GR当てはまり+パラメータ+井戸レジーム)でスコア→最良選択しても **的中率0.19(≒ランダム)・selectorは平均8.6に負け**。
  = 入れた信号が全部GR尤度系で、**GR尤度≠真値**ゆえ「どのPFが正しいか」が学習できない。
- **直交信号も全滅(`v20/signal_compare_v20.py` 実行済)**: mean 8.189 に対し A知ゾ9.754 / B krige9.651 / C consensus8.421 / D dipdev11.126 / E rough9.176 / META8.499 / oracle5.658。
  **全信号が mean に負け**、本命の A(既知ゾーン答え合わせ)が最悪級。→ **「どのPFが正しいか」は識別不能、選択路線は完全に死亡**。
- **次の本命**: kriging を**選択器でなく baseline置換**として使う(近傍坑井→ geo_z 空間補間→評価ゾーン geo_z 直予測→ TVT=geo_z−Z, GR非依存)。`v17/kriging_prior_v17.ipynb` の数値安定版が資産。[[v19-pf-bank-boosting]]
