# v63 — 合成井戸(pseudo)による事前学習/DA の実験土台(v47系チェーン)

> 方針(2026-07-14 ユーザー):
> - NN脚のCV積み増しはLBに転移しない(v52 TCN上乗せ/v61 img/v62 L5 LB6.588 の3連続実測)。
>   → **LB-CVが一致している v47(tabular+TCN単純構成)を土台**に、合成井戸の事前学習/DAで攻める。
> - まず**合成が全く絡まないベースライン**を作り CV/LB を確定 → その後 pseudo を絡める。
> - v63 はしばらく簡易実験に使う。データは使い回さず create からやり直す。

## v47 からの変更点
1. **smooth無し**: `SMOOTH_LAG=0` → smoother コアで `pts_s=pts_f`(=純フォワードPF、「普通のPF」)。計算が軽い。
2. **r4_seed32 除外**: 6バンク(pf_1/2/3, r0_seed32, r1_seed32, pfA)× tw/self/nbr = 18ラン。列は `pf_ancc(無印=v9内部の代表)+ pf_*_1.._6`。
3. **PSEUDO モード**: 合成井戸ディレクトリを同一パイプラインに通せる(PF/beam/self/nbr など**実井戸と同じ特徴を合成井戸にも生成**)。

## pseudo 生成器の設計(ユーザー指示への対応)
- **3D面マッピング(指示①)**: train全773坑井の (X,Y)→ANCC..BUDA 6面を 250ft格子にラスタ化(穴埋め+平滑)。
  合成真値は v56 恒等式 **TVT=(ANCC−Z)+b**(実測で行間std≈0.01ftの厳密恒等式。bはdonorから算出)。
  - `surface` モード: donor軌跡をXYジッタ(±1500ft, データhull内)して面から地層トップ・真値を再構成。
  - `reskin` モード: v55方式(donor軌跡・真値を継承しGRのみ再合成)。`MODE=mix`(デフォルト surface 70%)。
- **neighborの扱い(指示②)**:
  - create側: manifest の **donor を近傍プールから除外**(reskinの正解漏れ防止)。プールは常に実train坑井。
  - 生成側: 面の平滑成分(近傍由来)に**共有の独立残差場 R(x,y)**(相関長900ft, σ5ft=v56の短波長起伏実測に整合)を
    加算 → 近傍は「役立つが完全ではない」= 実データと同じ情報量に。スモーク実測: pf 4.8ft / self 2.1 / **nbr 9.9ft**。
  - struct錨(pfA): reskin=donorのprior流用(軌跡同一なので正当)/ surface=錨OFF(honest)。
- **GRノイズ(指示③)**: 完璧/現実/強ノイズの3水準 σ={1.5, 6, 11} を比率 NOISE_MIX=(0.25,0.5,0.25) で井戸ごとに抽選し
  **manifestに記録**(後で水準別ablation可能)。分解能平滑r=2、**donorのGR欠測(NaN)パターンも継承**。
- fold規律(学習側): pseudo は **donorのfoldに帰属**。donorがvalのfoldではその pseudo を使わない(train_nn_v63 が manifest から自動処理)。

## 実行手順
```bash
# ① ベースライン(合成なし)
.venv/Scripts/python.exe v63/create_v63.py                      # → artifacts_v63/data/train.parquet(数時間)
# train_tabular_v63.ipynb 実行(→ models_fwd, gbm_v41_oof.npy, features.json)
# train_nn_v63.ipynb 実行(PSEUDO_MODE 未設定=off)             # → nn/, blend評価
# submit_tabular_v63 / submit_nn_v63 で LB(dataset: rogii-v63-artifacts に artifacts_v63 を丸ごと)

# ② pseudo 生成 → 同じ特徴を create
.venv/Scripts/python.exe v63/make_pseudo_v63.py                 # TAG=p1 NSYN=200 (env: MODE/RES_FT/NOISE_MIX/JIT_FT...)
PSEUDO_DIR=v63/artifacts_v63/pseudo_wells_p1 OUT_PQ=v63/artifacts_v63/data/pseudo_p1.parquet \
  .venv/Scripts/python.exe v63/create_v63.py

# ③ 事前学習 or DA(TCN)
PSEUDO_MODE=pretrain PRE_EPOCHS=20 で train_nn_v63.ipynb        # pseudoで事前学習→realでfinetune
PSEUDO_MODE=da DA_RATIO=0.5 で train_nn_v63.ipynb               # realにpseudo井戸を混入
# ckpt/結果キーは RUN 名に _pretrain-p1 等が付きベースラインと分離される
```

## スモーク実績(2026-07-14)
- make_pseudo: 面 541×737格子(観測23,358セル)、4井戸 surface 4/4 生成・棄却0。
- create PSEUDO: 4井戸 → 17,938行 × 724列(pf_ancc.._6/self/nbr/beam/donor/is_pseudo)。近傍あり2/4(donor除外動作)。
- PF品質(4井戸): pf_ancc 4.78ft / r0 3.76 / self_1 2.13 / nbr_1 9.87 = 実井戸並みの難易度感。

## ベースライン確定(2026-07-15)
- **CV blend_pp 6.4467 → LB 6.421(Δ−0.026 ≒ 1:1転移)** — v47系の CV=LB 性質を v63 改変(smooth撤去・6バンク・tabular3本)後も維持。
- 比較: v47 GBM×TCN 6.405 → v63 6.421(+0.016)= smooth(lag16)+r4+GBM6本分の代金は LB でわずか 0.016。
- **含意: pseudo 実験は CV だけで判定してよい**(転移が 1:1 なので提出枠を消費する必要があるのは CV で >0.05 級の効果が出た時のみ)。

## 結果(2026-07-15, p1=300本 デフォルトノブ)
- **DA: 悪化 / pretrain: +0.03 ≒ 誤差** → p1 の TCN 向け pseudo は無効。
- 解釈: PFチェック(5井戸ペア比較)の通り、pseudo は「解ける難易度だが**難しさの出どころが実と別物**」
  (surface=実の datum 両義を消す / reskin=warp の人工難)。TCN の入力は**エンジン出力特徴**なので、
  pretrain が教えるのは「pseudo上のエンジン失敗パターン」= 実と不一致で転移しない。DA は equal weight で
  その不一致行を注入するため悪化(pseudo行の gf=0埋めがドメインフラグになる問題も)。
- **v55 の教訓「合成の難しさは消費者依存」の再確認**: エンジン特徴消費者(TCN/GBM)は合成に最も厳しい。
  次の一手候補: ①pseudo を画像系消費者(v61 UNet / v50 emission)の事前学習に転用(3位Tuckerの本来の形。
  p1 は GR+ラベルだけで流用可・create不要)②硬さ現実化バッチ p2(RES_FT=10, THICK/WARPFT増, noise high寄せ)
  ③pseudo-for-TCN closed → lag192+逆方向DA のLBレバーへ。

## v63u = v64 UNet特徴の注入実験(2026-07-17)
- 仮説: v64 UNet(PF-free脚, 単体8.30, v63相関0.645)を**出力ブレンド(w0.15で6.3542)でなく特徴量として注入**すれば、
  行条件付き重み付け+不確実性列の分だけ上乗せできる(v28 self/nbr・v48 gf の勝ちパターン。v24 の「仕上げ済み予測大量注入」とは
  列数8・低相関の点で異なる)。
- **特徴8列**(`v64/make_unet_feats_v63.py` → `unet_feats_u.npy`, OOF・parquet行整列・充足率100%):
  unet_delta / unet_dh / unet_std / unet_ent / unet_pmax / **unet_top2gap(双峰距離)** / unet_p2 / unet_vs_pfancc。
- **u系として完全分離**(ベースライン非破壊): `train_tabular_v63u.ipynb`(models_fwd_u, features_u.json, gbm_v41_oof_u.npy)
  → `train_nn_v63u.ipynb`(RUN=combo_u, feat_rank_nn_u.json)。実行順: tabular u → nn u。
- **判定**: blend_pp(combo_u) vs ベースライン 6.4467 / 固定ブレンド 6.3542。固定ブレンドを明確に下回れば特徴注入採用。
  test側(submit)への組み込みは CV 勝利後に構築(v64画像の実行時構築+UNet推論を v63 submit に追加)。

## 注意・既知の割り切り
- **符号バグ修正済み**: 真値は TVT=(ANCC−Z)+b。(Z−ANCC)+b は誤り(初回スモークで coverage 全棄却→発見)。
- surface モードの真値は「面の平滑成分」を含み、面は全train坑井から作る → **厳密には val fold の情報を含む**。
  R(σ5ft)で希釈されるが、pseudo効果の最終確認は LB で行う(CV の pseudo 寄与は 0.0x 台なら過信しない)。
- gf 3列(v48 npy)は実train行にのみ存在。pseudo 行は正規化後0(中央値相当)で埋める(train_nn_v63 内で処理)。
- tabular の `USE_BACKWARD=False`(v47 と同じ ablation 基準)。逆方向DAを試す場合は backward parquet の生成が別途必要。
- v52系(722列)とはスキーマ非互換。v63 は v47系(tabular+TCN)専用。
