# v62 — 別表現スタッキング: Feature-Field UNet(L3)+ 曲線トークンsoft選択(L5)

> 方針(2026-07-12 ユーザー): v52特徴を転用し「別表現で多段学習→スタッキング」。
> 表現=近傍構造の選び方: L1 GBM(行単独)/L2 TCN(時間)/L3 画像(δ×時間格子)/L4 再訪整合/L5 曲線トークン/L6 スペクトル/L7 ranking(未)。

## 実装
- `build_field_v62.py`: v52列(pf_ancc±std×6, self/nbr×3, beam, sc, gf, v50b, lk)を δ枠の柔らかい尾根に描画
  + v61生GR6ch → imagesF_v62.pkl(24ch)。UNetは v60 トレーナ流用。
- `build_seqfeat_v62.py`: 同じ16本を bin単位の (D=δ, S=幅, C=文脈) に → seqfeat_v62.pkl。
- `train_l456_v62.py`: L4=自己相似バイアスTransformer / **L5=曲線トークンcross-attention(16本の凸結合+微小残差)** / L6=多重スケールConv。

## 採用案(CV 6.083 → 5.83, −0.25)
- **v52チェーンに L5 を第3脚として追加**: blend' = (GBM×TCN blend の代わりに)TCN×L5 の 1:2、または既存blendにL5を残差ブレンド。
- 提出化: L5 は v52 submit が計算済みの列だけ消費・モデル極小(DIM64)→ ノート追加コスト小。
- 残課題: ①L5 の3seed平均(採用前の安定化) ②L7(listwise ranking損失版)の余地 ③pp再調整(新blend向け)。

## メタスタッカー比較(2026-07-13, ユーザー「7モデルの選択問題では?」への回答)
| 方式(全てメタOOF) | overall |
|---|---|
| **固定重み** | **5.8253 ★** |
| ridge(和1厳密, 負重み可) | 5.879(L4に−0.67等=in-sample相殺ゲーム) |
| gate_mlp16(凸・特徴条件付き) | 5.965 |
| FWLS | 6.06-6.16 |
| gate_lin | 6.078 |
- ★決定的観察: **ゲートを固定重みで初期化しても学習でOOF悪化** = in-sample勾配が非汎化方向を指す直接証明。
- 追試(2026-07-13): 自由形式メタ = ridge加法(+特徴)5.993 / **木メタ 12.4-14.6(v24の墓標を再現)**。
  best-leg判別(ユーザー案) = 行分類 top1 0.356(hard 6.32/soft 5.94)、**井戸分類 top1 0.250 < 多数決0.305**
  (hard 6.17/soft 5.879)。「どの脚が最良か」ラベル自体が既存特徴から予測不能。
- 結論: oracle 4.891(賞金0.93ft)は実在するが既存特徴の学習メタでは取れない=**選択の壁7系統目**。
  メタ再訪条件: 新非相関脚の追加 or 選択専用の新情報(per-seed票)。採用は固定重みスタックで確定。
- 運用メモ: メタ実験のLightGBMはnum_threads=4上限(全コア使用はユーザーのPF実行を2倍化させた前科)。

## 3seed化(2026-07-14, ユーザー要望「l4~l7を3seedで」→「seed0もフルでやり直し」)
- 60ラン(L4-L7 × seed0-2 × fold0-4, 全て VFRAC=0.85)。旧s0 ckpt(VFRAC=0.5)も温存し、**4member平均**(_s0,_s1,_s2,旧)を採用。
- per-seed観察(図: `v62/fig_seed3_v62.png`):
  - L4/L6 の fold3≈7.3-7.9 は**全seed共通=アーキ由来**(seedでは直らない)。
  - L5 は **fold単位のseed事故**あり: s1 の fold4=6.74(s0 6.02)/ s2 の fold3=7.40(s0 6.78)。±0.6-0.7級。
- 脚別 overall(4member平均): L4 6.276 / **L5 5.932** / L6 6.148 / L7 6.055(単seed比: L4 −0.07, L7 −0.05, L6 ±0, L5 +0.004 — 旧s0の5.9278は当たり draw)。
- スタック: 3seedのみ 5.8706 / **4member 5.8523(採用・saved)**。fold別 4.78/5.45/6.08/6.74/6.06。
  旧5.8253との +0.027 の解剖:
  1. 重みではない(旧重みをそのまま適用しても 5.8538。プラトー内 ±0.0015、6初期値の座標降下が全て同値に収束)。
  2. **単seed脚が持っていた独立seedノイズを、5脚ブレンドが「暗黙のseed平均」として消費していた**。脚を先にseed平均すると
     L6/L7 の重みが 0 に落ちる(多様性源として用済み)= 旧 5.8253 の一部はこの二重取り+seed運。
  3. oracle も 4.891→4.991 に縮小 = seed平均は脚を均質化し选択の上振れも削る(per-seed票=create側情報の傍証)。
- A/B半分割監査: 旧重み固定 5.8538 / cdesc再fit 5.9403(cross-half)→ **重みの再fitは追わない**。プラトー重み
  {TCN .4, L5 .775, L3img .05}(正規化で旧比とほぼ同値)で `stack7_config.json` 確定。
- 提出ノート2本は **存在するseedタグを自動検出して 4tag×5fold=20ckpt 平均**に更新済(タグ無し環境でも旧5本で動くfallback)。
- 判断: **提出は4member版**。OOF数字は旧より+0.03悪いが、旧の−0.03はseed運を含む見かけ。分散低減=LB転移の安全性を優先。
- 運用: nn62 は 165ファイル71MB(モデル極小)。dataset全体(pkl/npz除外)≈284MB。

## 教訓
- 「同じ特徴の別表現」は正義: L5 は v54(per-seed 576本の集約=崩壊)と同じ発想を**エンジン16本・曲線文脈・end-to-end**でやり直して成立。候補の粒度と文脈の持たせ方が全て。
- fold0フラッタリーは表現系の常(EV29-UNet/L3で再確認)→ 5-fold+fold一貫性が唯一の判定。
