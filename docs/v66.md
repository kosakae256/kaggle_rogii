# v66 — struct(構造prior)自体の強化(場の作り直し)

> 指示(2026-07-19 ユーザー): struct の作り方を確認し、これまでの実験を踏まえて **struct 自体を強化**する。
> 消費側(錨・gf・画像ch)はいじらない。エンジン契約 `{well:{tvt,sig}}` pkl は不変 = `V38_PRIOR=v66` で無改造 A/B。

## 仮説
struct は LB 実証済みの数少ない正のレバー(struct20 = 単体PF LB 新記録 7.881)だが、
**場そのものは v38 時点の素朴な作り**(K16固定分割 → c/proj deproject → 単純カーネル平均 → 単一κ)のまま。
場の推定品質(LOO struct RMSE **9.709 ft**)を上げれば、錨(v38/v65)・gf(v48)・画像ch(v44/v64)の
全消費者が同時に恩恵を受ける。特に v56 実測「両義性±15ft = 面の短波長起伏」に対し、
現行の場は長坑井ほど過平滑(K=16固定)で短波長を捨てている。

## 現行(v38)の作り方の確認(v38/struct_prior_v38.py)
1. 各train坑井の lateral で `R0−U`(= **累積ΔANCC** = 面の起伏)を K=16 のランプ基底で lstsq
   → セグメント毎の面の傾き `c`(ft/サンプル)
2. `c/proj`(θ0=118.4° への deproject)を点値として (segment midXY, c/proj, wi) の点群 = **場**(12,296点)。
   `|proj|>0.3` 未満のセグメントは**破棄**
3. クエリ = kNN15 のガウスカーネル(h=500ft)**単純平均**、`|proj|<0.35` の行は g=0(GATE)
4. `κ`(信頼縮小)を dd 5ビンで buffered-LOO 同時最小二乗(κ=[0.81, 0.72, 0.62, 0.37, 0.11])
5. 予測 = `ti[s] + cumsum(κ·(ndz + Dh·proj))`、σ(dd) 8分位ビンの LOO RMS(clip[3,40])

## さらなる改善アイデア(v66.1+ バックログ, 2026-07-19)

> 指導原理(v66 の実測): **場の強化 = 平均値を賢くすることではなく、信頼度申告(σ)の解像度を上げること**。
> 平均値側の「賢い推定」は6連敗(適応セグ/2Dベクトル/QW/Huber/異方性/κ分離)、
> 勝ったのは trust 側(σ par/perp 分離・PGATE 学習係数)のみ。よって優先度は trust 系 > 新情報 > 平均値系。

### Tier 1 — σ(trust)の解像度をさらに上げる(安い・実績のある鉱脈)
| # | アイデア | 根拠と設計 | 判定 |
|---|---|---|---|
| 1-1 | **累積σ(非減少σ)** | 現行 σ(dd_row) は「その行の局所信頼度」だが、struct誤差は**積分で蓄積する**。dd~2000 の区間を 3000ft 走った後に dd~500 に戻ると σ が急に締まり、**蓄積済みバイアスへ錨が強く引き戻す**(現行最大の理論的欠陥)。σ²_row = Σ上流(κ加重ステップ分散)の累積モデルに置換(較正はステップ分散を dd ビン別に LOO でフィット)。 | LOO **NLL**(下記1-4)と PF A/B。効けば大きい |
| 1-2 | **σ(dd × ドナー不一致)** | ドナー dip の加重分散(アンサンブルスプレッド)を第2軸に。同じ dd でも「近傍が割れている」場所は信用しない。較正側だけの変更で場は不変。 | LOO NLL → PF A/B |
| 1-3 | **\|p\| の連続化(3バンド)** | perp 分割(0.35)は2値。p=0.4 の行は par 扱いだが実質グレー。\|p\| 3-4 バンド × 係数/σ(PGATE の一般化第2弾)。perp σ が SIG_MAX=40 に張り付き気味なので **perp 側だけ cap 60 に緩める**のも同時に。 | 同上 |
| 1-4 | **★Level-1 指標を NLL に変更** | 今回 LOO RMSE 同着なのに PF で −0.197 = **RMSE は錨品質の弱い代理**。錨が消費するのは (tvt, σ) なので、ガウス NLL(較正込み品質)を builder の主指標に追加する。以後の反復が速くなる測定器改善。 | 実装のみ(即) |
| 1-5 | **prefix 自己較正 σ スケール** | 既知帯(lateral 化した後半)で struct モデルを走らせ実誤差を測り、**その坑井の σ を坑井別にスケール**(合法=TVT_input のみ使用)。既知帯で外している struct は評価帯でも信じない。ヒール較正の struct 版。 | 既知帯誤差と評価帯誤差の相関を先に測る(相関が無ければ捨てる) |

## v66.1 改善ループ(2026-07-19, Opus)

> 指導原理(v66 の実測): **場の強化 = 平均値でなく σ(信頼度申告)の解像度**。これを軸に反復。

### [1-4] NLL 計装(測定器の改善) — `build_struct_v66.py` に恒久搭載
- v66 で「LOO RMSE 同着なのに PF −0.197」= **RMSE は錨品質の弱い代理**(σ を見ない)と判明。
  錨は (tvt, σ) を消費するので、ガウス **NLL = mean[½(err/σ)² + logσ + ½log2π]** を builder の主指標に追加。
- v38 baseline NLL = **3.6355**(pkl の σ で算出)。以後の σ 系施策は NLL で高速に当たりを見て、勝ちだけ PF A/B。

### [1-1] 累積σ(ランダムウォーク較正) — ★採用(`SIGMODE=cumul`)
- **理論的欠陥**: σ(dd_row) は「その行の局所信頼度」で、悪ゾーンを長く走った後の**蓄積バイアスを無視**する
  (dd~2000 を 3000ft 走行後に dd~500 へ戻ると σ が急に締まり、蓄積誤差へ錨が強く引き戻す)。
- **修正**: `Var(err_row) = base + Σ_{j≤row} ρ(bin_j)` の非負累積モデルを LOO の err² から NNLS 較正
  (bin = par の dd 5ビン + perp 専用ビン、ρ=per-row 分散増分 ≥0)。σ が**履歴依存で単調増加**する。
- 較正 ρ = [0.014, 0.024, 0.070, 0.029, 0.046, **0.418**(perp)] base σ=4.6ft = 近ドナー≈0・遠/perp で急増(期待通り)。
- **結果(tvt 不変, σ のみ差)**:

| | 錨NLL | LOO RMSE | PF A/B overall | hardcore | 坑井別中央値 |
|---|---|---|---|---|---|
| v38 | 3.6355 | 9.7087 | 7.6603 | 14.42 | 4.500 |
| v66_leanv1(local σ) | 3.6269 | 9.7029 | 7.4633 | 14.16 | 4.506 |
| **v66_leanv1cumul** | **3.5408(−0.095)** | 9.7029 | **7.4340(−0.029)** | 14.16 | **4.432** |

- **NLL −0.095 → PF −0.029 の正転移(転移率≈0.3)。RMSE は不変(σ を見ないので当然)= NLL が正しい測定器と実証。**
  利得は median 集中(坑井別中央値 4.506→4.432)・hardcore 中立・433/773 改善。**採用**(ローカル基準)。
- 通算 v38 → v66_leanv1cumul = **ローカル overall −0.226**。installed: `V38_PRIOR=v66_leanv1cumul`。
- **★LB実測(2026-07-19): struct20 で v38場 7.881 → v66場 7.991(+0.11, 同一params同一pipeline, 差は struct のみ)。**
  **ローカル −0.226 に対し LB は逆行**(ただし +0.11 は seed帯±0.2 内=統計的には「LB中立〜微逆行 while CV明改善」)。
  解釈: **struct(空間prior)改善は CV レバーであって LB レバーではない**の再確認(v39「tail改善はCVを縮めるがLBは
  median律速で動かない/隠しtestはtail希薄でpriorのtail価値が薄まる」・v41・v42・fullfield 7.963 と同型)。
  v66利得は tail/mid 集中(hardcore−0.26・中央値改善)= まさに隠しLBが薄める部分。**LB更新は依然 GR/尤度側+合法leak(self/nbr)**。
  → v66 は「CV を信じるチェーン(v63/v52 特徴供給)向けの高較正コンポーネント」として保持。**単体struct錨でのLB更新は狙わない**。

### [1-2] ドナー不一致σ / [σ cap] — ★不採用(NLL で棄却、PF不要)
- **1-2 `SPREAD=1`**: 「同じ dd でも近傍 dip が割れている場所は信用しない」を cumul に累積項として追加。
  全データで ρ_spread=6.28(正の重み)は付いたが **NLL 3.541→3.620 と悪化**。理由=**dd と冗長**(遠ドナーは
  既に dd ビンで「割れる」と分かる)、かつ cumsum(spread) が坑井長と共線 → dd ビン係数を食って較正を歪めるだけ。
- **σ cap**: `SIG_CAP` 40→60→80 で NLL 不変(3.5408)= cumul の累積 σ は 40ft cap に届かない(蓄積が緩やか)。cap=40 維持。
- 学び: **σ の解像度を上げる軸は「履歴(cumul)」であって「近傍の割れ具合」ではない**。σ 系はここで一旦打ち止め。

### [2-1 前提テスト] クロスウェル ANCC datum 整合性(`v66/diag_crosswell_v66.py`)
「各坑井は自分の進行方向の傾きしか語れない → 平行掘りで走向勾配が原理的に見えない(896型の根本原因)」
に対し、train ANCC 全行既知を使った**クロスウェル・ペア勾配**の実現可能性を診断(read-only)。766坑井375万点。
- **Q1 datum整合**: 近接クロス点(<120ft)の |ΔANCC| 中央 2.90ft / p90 14.2ft。おおむね近い。
- **★Q2 offset性(決定的)**: クロスペア差を **per-well 定数 offset で説明すると残差 0.02ft**(offset std 6.5ft)。
  = error_anatomy §1「TVT=ANCC−Z+**b_well**」の b_well が実在(std 6.5ft のクリーンな per-well 定数)と自前実証。
- **Q3 走向勾配の落とし穴**: 局所クロスウェル平面フィットで走向成分 |g_perp|=0.021 ft/ft(傾斜の0.59倍)が見えるが、
  これは **offset 未除去の生 ANCC**。offset std 6.5ft ÷ 近傍 500ft ≈ **0.013 ft/ft の偽勾配が混入** → g_perp の過半は offset 由来の可能性。
- **結論**: ペア勾配は「clean な per-well offset を**全坑井グローバルに解いて除去**してから」でないと使えない。
  さらに平行 lateral では**線形走向勾配が坑井配置と縮退**(offset に吸われる)= 回収できるのは**走向の曲率(2次)**のみ。
  → **2-1 は v67 級の別サブプロジェクト**(near-crossing で連結する offset 求解 → 共通datum点群 → 曲率場)。
  payoff 不確実(896型の線形走向は原理的に取れない)。**今回は診断で確定知見を得て保留**、σ 路線を優先。

### v38 ↔ v66 相関(`v66/corr_v38_v66.py`)— 「予測は同一、σだけ別物」の定量証明
773坑井で v38(最初)と v66_leanv1cumul(改善版)を多層で相関(read-only):

| 層 | 相関 | 意味 |
|---|---|---|
| **A 予測 tvt** | 坑井内 Pearson 中央 **0.9999**(平均0.992/relief 0.9967) | 構造予測は**ほぼ同一** |
| **B 誤差 err** | pooled **0.9947**、坑井内中央 0.9999 | 間違い方も**冗長**(ブレンド多様性なし) |
| **C 信頼度 σ** | pooled **0.498**、坑井内中央 **−0.004** | **σ だけ別物**(累積σは v38 σ とほぼ直交) |
| **D 坑井RMSE** | Pearson 0.993 / Spearman 0.994 | 難坑井の見立ては一致 |

- 予測の動き: 坑井別 平均|Δtvt| 中央 **0.15ft**、p90 0.38ft、>3ft は **8/773 本(1%)**のみ。

  PF −0.226 は全て σ 由来 = 「場の強化=平均値でなく信頼度申告の解像度」の定量証明。
  **含意**: tvt が冗長(corr 0.99)なので v66 は v38 を**置換**する(バンク多様性としての併用価値はない)。
  多様性が欲しければ tvt を本質的に変える別軸(2-1 走向勾配など)が要る。
