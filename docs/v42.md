# v42 — 空間MRF datum同時推定(mean-field変分推論)

> **状態: 実装済・実行済(train診断)。** ファイル: `v42/spatial_datum_v42.py`。
> ユーザー発案「空間priorがあれば確率的モデルが作れる」を実装。物理prior=struct(v41のPFと同じ)。

## 仮説
PF/NN/フィルタは全て坑井を独立に扱ってきた。地質は空間で共有される → 坑井をまたいで結合した
**同時確率モデル**なら、硬い核(datum両義)を「非曖昧な隣接坑井の確信」で救えるはず。

## 手法
- **base** = pf_ancc(実PF, datum-flip問題あり)。**状態** = 坑井ごとのグローバルoffset b_w。
- **データ項** C_w(b) = base+b の GRマッチ費用(z化GR, flip坑井で二峰)。
- **struct prior** = b を struct が示すoffset s_w=median(struct_tvt−base) へ引く(GR非依存datum投票)。
- **空間項** = 隣接(XY kNN=8)の b は近い(struct除去後の残差offsetが空間平滑)。
- **推論** = mean-field `p_w(b)∝exp(−E/T)`, `b_w=E[b]` を反復(posterior mean=RMSE最適, モード非commitment)。
- ★地雷回避: 絶対TVT面でなく **b=struct残差offsetのみ** 空間結合(cross-field面再構成は死=過去実証)。

## 結果(2026-07-09, train 773坑井 / 硬い核52)
| 構成 | overall | 硬い核 |
|---|---|---|
| base(pf_ancc) | 9.124 | 21.52 |
| +GR再datum(GRのみ) | 9.885 | 21.16 |
| **+struct投票** | 9.013 | **14.91** |
| +spatial(struct無) | 10.150 | 22.03 |
| **+struct+spatial** | 8.359 | 16.67 |

λ_spatialスイープ(λ_struct=0.3): overall 9.01→**8.33**(λ1.0)だが硬い核は 14.9→17.8 と上昇。

## ★結論: 確率モデルは機能、ただし「2つの別レバー」に分離
1. **struct投票(GR非依存datum)= 硬い核レバー**: 硬い核 21.5→14.9(**−6.6ft**)。struct が表裏を正しく選ぶ
   = 確率モデルの核心(GR-freeな空間datum解決)が実証。転移安全([[cv-lb-policy]]の転移率≈1.0族)→ **CV(tail)の本命**。
2. **空間結合 = median/overallレバー、tailは悪化**: 隣接平滑は多数派offsetを整えるが、硬い核ではstructの
   正しい投票を隣接が薄める。→ **LB(median)側のレバー候補**(「LB更新にはmedian改善が必要」の直接手)。
3. **空間だけ(struct無)は死** = cross-field地雷の再確認。空間結合は「structの上の微修正」でのみ生きる。

→ 2レバー分離が二正面戦略([[hard-wells-priority]]北極星)と一致: struct投票=CV(tail) / 空間結合=LB(median)。

## ★base強度の検証(2026-07-09): v42はPF改善器であって最終補正器ではない
- **base=v41 GBM(強, overall 7.41 / 硬い核 12.0)では全構成が悪化**(+struct投票 8.73、+struct+spatial 8.07、
  λ_spatial↑で7.71までbaseに戻るのみ)。GBMは既にdatum解決済み → struct投票は正しい予測をstructのdatumへ
  引き戻して壊す。空間結合はそのdamageを打ち消すだけ。
- **結論: global-offset補正は「生PF(datum誤り多い)」にのみ効く。** v42 = 「生PFのdatumをstruct+空間で直す層
  =改善PF候補の生成器」。最終の強予測(GBM/blend)には適用しない。改善PFはバンク追加/GBM特徴の材料に回す。
