# v84 — 事前区間self-tuning PF(struct不使用, ユーザー発案 2026-07-23)

## 狙いと転移論
- 各井戸の事前区間(prefix)の「開始〜MD_end−100ft」だけを既知にし、末尾100ftを疑似evalに
  **その井戸のPFパラメータをOptuna 200trialで最適化** → 得たパラメータで本番eval推論。
- ★**手続きがtrain/testで同一**(隠しtest側でも各井戸で同じprefix-optunaを走らせる)ため、
  visible trainでこの手続きを丸ごと再現したときのoverall RMSEが、そのまま**隠しtestの正直な推定値**。
  = 通常の「trainで大域チューニング→testに適用」の過学習問題が構造的に存在しない。
- struct/K16一切不使用。エンジン=pf_tuning/pf_tuning_pf01.ipynb の struct-free PF(exec取込)。

## 実装(v84/pf_prefix_tune_v84.py)
- 探索空間=pf01_balanced_core移植(24パラ, n_seeds=8固定でOptuna高速化)。
- MODE=well: 井戸ごと200trials→井戸別best→本番eval。default(PFParams())比較。
- MODE=group: ランダムN井の疑似eval pooledで共有params最適化(ノイズ減退版)。
- cut=100ft(prefix末尾=最も水平に近い=eval regimeの代理)。
- 指標=overall(行プール)RMSE=Kaggle同型。σ較正/初期dip等はカット前prefixのみ(正直)。
