# v72 — クロスアテンション・アライナー(PF/tabular/TCN非依存の新定式化)

## 仮説
tabular/TCN/PF強化のいずれでもない、**質的に別の (モデル・入力・出力)** を探す([[formulation-diag-segment]]の帰結)。
診断が与えた設計制約:
- **ドリフト(誤差の46%)=rateを逐次積分するから累積** → 新モデルは**rateを積分しない**。全域で一度に整合を取れば構造的にドリフトしない。
- 強い信号は**GR↔typewellの照合**(PF候補corr0.857の中身) → 入力を**生GR系列とtypewellテンプレそのもの**に。
- 多峰(datum両義)は**出力で表現**(MSEで平均に潰さない) → 出力を**位置の分布**に。

→ **PFの「逐次ベイズ整合」を「学習型クロスアテンション・ローカライザ」に置換**する。

## 定式化(モデル・入力・出力)
タスクの実体: well の GR(MD) は、typewell の GR(TVT) を未知の TVT(MD) で"リサンプル"したもの。TVT(MD)を復元=2系列の整合。
坑井は水平で TVT は上下に揺れる(単調でない)ので、**各行を typewell 上に localize + 平滑**という素直な形になる(DTWの単調制約は不要=よりシンプル)。

- **入力(test合法のみ)**:
  - well: 生GR(MD)、geometry(dz/dmd, Z, md_since)、既知prefixのTVT(錨・較正源)
  - typewell: 生GR(TVT) を TVT グリッド上に(0.5ft, ~1300点=出力位置軸)
  - ※struct/train限定列は一切使わない
- **モデル**: 
  - WellEncoder(conv1d文脈窓+Transformer数層) → well トークン h_w(m) 〔文脈で枝を解く〕
  - TypeEncoder(conv1d文脈窓) → typewell トークン h_t(t)  〔GR較正差を埋め込みで吸収=形状照合〕
  - クロスアテンション a(m,t)=softmax_t(h_w(m)·h_t(t)/√D)
- **出力**: TVT(m)=Σ_t a(m,t)·TVT_grid[t](ソフト位置)。**a(m,·)の二峰=datum両義**、argmax=コミット、エントロピー=信頼度。
- **なぜドリフトしない**: 各 m が typewell の**絶対TVT位置**を直接指す=rateを積まない。連続性は「WellEncoderの文脈」＋「平滑損失」で与える(積分でなく)。

## 損失
- `L_reg` = Huber(TVT_pred, TVT_true)  (評価+prefix行)
- `L_align` = CE(a(m,·), 真bin)  ← **アテンション分布を真のtypewell位置にピークさせる**(ソフトgaussianラベル±数ft)。二峰を平均に潰さず**正しい枝にmassを置く**ことを学習=commitの本質。核心項。
- `L_smooth` = Σ|Δ²TVT_pred|  (曲率罰=平滑)
- prefixはTVT既知で完全教師=GR較正と枝を学ぶ土台

## 検証設計
- GroupKFold(坑井)。理想はleave-field-out([[kaggle提出の落とし穴]]のfieldリーク回避)。まず坑井GKFで感触。
- **ドリフト回避の確認**: [[formulation-diag-segment]]診断Eの md_since 遠方RMSE伸び(3.57→5.76)が**平坦化するか**をこのモデルで測る(=積分しない効能の直接検証)。
- 単体RMSE(blendでなく)をまず見る(ユーザー方針)。argmax(commit) vs soft(hedge) の両方。

## 過去との差分
v70/v71 は iTransformer を「多表現特徴/emission画像」に当てδ回帰。**アテンション自体をアライメント(typewell位置を直接指すpointer型)にするのは未実施**。生GR系列×typewell系列の直接クロスアテンションが新規。PF候補は使わない(が転移不安なら後で補助特徴に回す余地)。
