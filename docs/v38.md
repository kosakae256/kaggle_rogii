# v38 — 構造事前分布つき物理PF(GRフリー幾何モデルを絶対TVTソフト錨に)

> **状態: 実装済(未チューニング)。** ファイル: `v38/struct_prior_v38.py`(prior生成)/
> `v38/iterative_pf_boost_v38.py`(PFコア+錨)/ `v38/tune_anchor_v38.py`(Optuna)。
> スモークテスト通過(錨がev行に整列・ON/OFFで出力変化・クラッシュなし)。

## 仮説
PFはGR→typewell相関で構築されるため、GRが両義的(bimodal datum)な硬い核で裏モードへ**飛ぶ**。
GRを一切使わない構造モデル(`検証/rogii_k16_spline_kernel_knn_adaptive_kappa.py`, LB 10.793)が出す
絶対TVT予測を**軽いソフト錨(対数prior)**としてPFに与えれば、GRが暴走したときだけ引き戻し、
GR正常な大多数には触らずに、**datum flip を推定中に潰せる**。最上位解法がPF×priorであろう、という読み。

## 変更点(v19からの差分)
- v19の物理PFコア(GPU, ancc)をコピーし、重み更新に錨項を1つ追加:
  ```
  lka = exp(-0.5 * ((TVT_particle - struct_tvt) / (ANCHOR_MULT * sig_struct))**2)
  w  *= lk(GR尤度) * lkp(dip率prior=USE_PHYS=False で死) * lka(構造錨)
  ```
- **錨の強さは Optuna で振らない。** `sig_struct` は構造モデルの実誤差(ドナー距離較正済み)。
  priorの分散として物理的に決まる量。`ANCHOR_MULT`(既定1.0)だけを定数/狭グリッドで外側選択。
  → 「Optunaが強度を極限まで下げて錨を無効化する」問題を原理的に回避。
- `suggest_params` は v19と完全同一(anchor_sig を足していない)。PF側の尤度/ダイナミクスだけ探索。

## 手法の概要
### 構造prior(`struct_prior_v38.py`)
- 原典K16モデル: 各train坑井で `R0 - U`(実TVT変化 − フラット予測 `-dZ`積分)を K=16区分線形で回帰 →
  区間dip率 `c`。脱投影 `D = c/cos(az−118.4°)` で向き非依存のdip強度にし、`(x,y,D)` を空間場に散布。
  test各区間の中点で ガウスカーネルkNN(k=15,h=500ft)補間 → `c_hat`。`kappa`(ドナー距離ビン別収縮)は
  buffered-LOO(ドナーを人為的に遠ざけて)同時最小二乗。
- **struct_tvt(row)** = `last_known_tvt + cumsum(kappa*g)`, `g = -dZ + c_hat`(gate |proj|<0.35で0)。
- **sig_struct(row)**: 全train LOO残差を**ドナー距離 dd 別に集計した RMS**(=その場所での構造の信頼度)。
  較正結果(`struct_sigcurve.json`, 全体LOO RMSE 9.709ft):
  | dd (ft) | 516 | 658 | 754 | 847 | 960 | 1106 | 1372 | 1985 |
  |---|---|---|---|---|---|---|---|---|
  | sig (ft) | 7.33 | 7.17 | 7.47 | 8.09 | 10.32 | 9.54 | 11.89 | 13.74 |
  近傍ドナーが密 → σ小(強めに信頼)、遠 → σ大(自動的に軽く)。SIG_MIN/MAX=[3,40]でclip。
- 出力: `struct_prior_train.pkl`(LOO, 773坑井, チューニング用)/ `struct_prior_test.pkl`(full-field, 提出用)。

### PF(`iterative_pf_boost_v38.py`)
- `build_cache` が pkl から `anc`(=struct_tvt)・`ancs`(=sig_struct)をev行順に添付(len一致を検査、
  欠損坑井は sig=1e9 で錨OFF)。`_pf_core` が USE_ANCHOR フラグで錨を乗算。cacheは常に錨を保持し、
  ON/OFF比較は `pf.USE_ANCHOR` トグルだけで可(再構築不要)。

### チューニング(`tune_anchor_v38.py`)
- 全usable坑井の overall RMSE を Optuna 最小化(錨ON固定)。最良paramで **錨ON/OFF × overall/硬い核** を
  両方測って表示(錨の価値はtailに集中するので overall だけでなく硬い核で確認)。

## 事前診断(この設計を選んだ根拠, scratchpad測定)
- 硬い核52坑井で構造モデル(11.17)が我々のGBM(15.65)に**勝つ**。全体でも一律ブレンドb=0.2で−0.176。
- datum-flip 34坑井で構造がバイアスを **12.7ft→7.0ft に半減、29/34で改善**(完全回収例多数)。
- ただし corr(gbm_bias, str_bias)=+0.61 = 独立オラクルでなく減衰器。5坑井は構造が逆に悪化 →
  **錨は軽く**が必須(σ=構造実誤差で自動的に穏やか)。
- 学習型selectorで狙い撃つ路線は「struct_wins を当てる可視特徴が無い(disp corr −0.06)」ため死。
  → prior(逐次推定中に効く物理項)としてのみ活かす、が結論。

## prior銀行(2026-07-08 汎用化, ユーザー構想「事前分布を集めて各priorでPF調整→複数特徴化」)
- `v38/make_priors_v38.py` が追加priorを `{well:{tvt,sig}}` pkl として量産(`artifacts_v38/priors/`)。
  σは各priorのLOO残差を信頼度プロキシビンで較正(=v38原則: 強度をOptunaに渡さない)。
  | prior | 情報源 | LOO RMSE | σ(近→遠) | 特性 |
  |---|---|---|---|---|
  | struct(既定) | K16 dip場 | 9.7 | 7.3→13.7 | 最強。mult30で単体8.13 |
  | dense | dense ANCC krige(tvt_dense_d) | 23.5 | 11.8→51 | 中距離まで有効 |
  | formation | 地層面kNN(tvtF_ANCC) | 47.3 | 22.8→60 | 弱いが独立情報 |
  | selfdip | 自坑井dip外挿(tail300 robust) | 127.9 | 12.8→60即頭打ち | ヒール近傍のみ、遠方は自動無効(σ上限) |
- エンジン/チューナーは環境変数で切替: `$env:V38_PRIOR="formation"; $env:V38_MULT="30"; python v38/tune_anchor_v38.py`
  (studyは `v38_{prior}_mult{M}` で別管理。既定=struct/mult30で従来互換)。
- **結果: dense / formation は空振り**(2026-07-08 ユーザー実行)。prior RMSE(23.5/47.3)が datum gap(±15ft)に対して
  大きすぎ、flip判別の票にならない。**priorに必要なのは低RMSEでなく「flip坑井で正しい側に偏っていること」**で、
  それを持つのは現状 struct のみ。

### 錨の累積方式(2026-07-08 追加, ⑤wellmean)
毎行独立掛け(row)は priorの自己相関誤差をT回数える**証拠の水増し**で、mult=温度補正はその経験的修正
(mult²≈T/T_eff)。理論的に正しい形として **⑤ telescoping 井戸レベル錨** を実装:
```
粒子ごとに D_t = running_mean(TVT_particle − anc)
w *= N(D_t;0,σ_b)/N(D_{t-1};0,σ_b)    ← 比(telescoping)。累積=exp(-0.5 D_T²/σ_b²) の1回分
σ_b = 坑井のprior σ平均 × V38_BMULT(既定1)
```
- multノブ消滅・水増しゼロ・**定数オフセット(=datum flip)だけを狙い撃ち、局所はGRに完全に委ねる**。
- `V38_AMODE=wellmean` で有効(既定 row)。study名 `v38_{prior}_wm{bmult}`。**リサンプリング時にDもgather**(実装済)。
- スモーク(未調整PF8坑井): OFF21.7 / row30 8.65 / wm1 19.2 / wm0.5 13.5 = 機構健全。wellmeanは設計上
  「坑井バイアス1回分」しか証拠を出さないので未調整PFは救えない(仕様)。**勝負はチューン後、判定は row の
  正直値8.13 vs wellmean(特に硬い核)**。
- **プロトコル: チューニングseed(20250707)固定、報告・比較は必ず別seed(777等)**。
- 参考: 検証/A002(fast local GR alignment)は**train再現で overall 59.7/中央値24.5**(原典コードでも同値=再現正確)。
  flat基準(≈15)より悪い。※「LB7.2」はユーザーの勘違いと判明(2026-07-08)→ 単体では弱いエンジンで確定。
  A002のtrend部=selfdip priorはこの枠組みに吸収済み。`local_unc`(best-2ndコスト差=行レベル曖昧度)は別途特徴候補。

## hold prior(last_known 保持錨 / 2026-07-09 追加)
ユーザー提案: **v28 graft の hold(=最終既知TVTを保持)を PF の事前分布(錨)に落とし込む**。
`make_priors_v38.py` に `hold` prior を追加(selfdip の傾き0版)。
- `tvt(ev) = last_known_tvt`(定数保持)。**σ = 最終既知点からの MD 距離ビン別 LOO 残差**で較正
  → **近傍(dist小)=強い錨・奥(dist大)=σ増で自動的に弱まる**(検証: σ 5.8ft@300 → 14ft@5000)。
  ユーザーの「奥ほど弱める」は距離較正で自動達成。`V38_HOLD_DECAY>0` で σ*=(1+DECAY·dist/1000)を上乗せ(手動ノブ)。
- **test安全**(TVT_input と MD だけ・近傍/K16場不要)。struct が外す硬い核の頑健フォールバック錨を狙う。
- 実行:
```
python v38/make_priors_v38.py                                  # hold/selfdip/formation/dense を生成
$env:V38_PRIOR="hold"; $env:V38_MULT="20"; python v38/tune_anchor_v38.py   # hold錨でPF再チューン(study=v38_hold_mult20)
# 奥をさらに弱める: $env:V38_HOLD_DECAY="1.0"; python v38/make_priors_v38.py で再生成
```
tune_anchor は無改造(`V38_PRIOR=hold` で `priors/prior_hold_train.pkl` を読む)。錨ON/OFF×overall/硬い核で効きを確認。

## prior注入方式バリエーション(v38p / 2026-07-10 追加)
現行の入れ方(row=毎行重み乗算, mult=温度補正)とは別に、**priorをどこに注入するか**を変えた
4方式を実装: `v38/iterative_pf_prior_v38.py`(エンジン)+ `v38/tune_prior_v38.py`(チューナー)。
現最良= struct×row×mult20(`v38_anchor_mult20_current.json`, 調整seed 7.485)を超えるかの検証。

| PMODE | 注入先 | 機構 | 狙い |
|---|---|---|---|
| `row` | 重み | 従来と同一(検算用) | 基準 |
| `gate` | 重み(選択的) | 行ごとに GR尤度の判別度 `amb=mean(lk)/max(lk)` を測り `lka^amb`。GR判別的→錨消滅/GR曖昧・欠損→錨フル | 「GR暴走時だけ引き戻す」の行単位自動化。GR正常行に触らない=mult温度補正の必要性自体を減らす |
| `trob` | 重み(裾) | Student-t錨(自由度 V38_TNU=3) | ガウスの二乗尾はstructが外れる坑井で引きずり続ける→t裾は大外れをGRに委ねる |
| `guide` | ダイナミクス | OU緩和 `pos += β(anc−tvt)`, `β=(dm/GLEN)·S0²/(S0²+σ²)` ≤0.25 | 重み枯渇ゼロ・証拠水増しゼロ。無情報区間だけ構造へ緩やかに寄る |
| `jump` | ジャンプ再生成 | jumpの飛び先を「現在地+ノイズ」→ **prior分布 N(anc,σ) のドロー**に(jump_prob=再生成率はOptuna探索) | 裏バンドルに嵌った粒子群をprior枝へテレポート、生存判定はGR尤度=flip回収の王道 |

- v38原則維持: σ=較正済LOO誤差、外側定数(V38_MULT/TNU/GLEN)のみ、Optunaは従来と同一のPF空間だけ探索。
- prior欠損行は全方式で自動OFF(row/trob/gate: σ=1e9→lka≈1 / guide: β→0 / jump: ノイズジャンプへフォールバック)。
- study= `v38p_{prior}_{gate_m10|trob_m10_nu3|guide_L1500|jump|row_m20}` で別管理。
  **★warm-start**: 空studyなら現最良(mult20)の best_params を enqueue して探索を近傍から開始。
- 実行例:
```
$env:V38_PMODE="gate";  $env:V38_MULT="10"; python v38/tune_prior_v38.py
$env:V38_PMODE="trob";  $env:V38_MULT="10"; python v38/tune_prior_v38.py
$env:V38_PMODE="guide"; $env:V38_GLEN="1500"; python v38/tune_prior_v38.py
$env:V38_PMODE="jump";  python v38/tune_prior_v38.py
```
- 見立て: gate は錨害(GR正常行への干渉)を構造的に消すので mult を 5〜20 で数点。guide/jump は
  重み系と誤差系統が変わるはず=単体で勝てなくても selector/バンク素材の多様性価値あり。
  **報告・比較は必ず別seed**(プロトコル)。

## 所感(実行前の見立て)
- 錨の価値は転移で増幅する族(DA同型: robustnessはtrain-OOFで過小評価)。overall がほぼ同じでも
  硬い核が縮めば採用価値あり。**overallが悪化しない範囲で硬い核RMSE最小の mult** を選ぶ(tail-aware選択)。
- 錨ON でチューンした best は v9/v19バンクに**別系統PF**として足せる(selector素材の多様性)。
- 次: mult選択 → test prior で提出チェーンへ / 錨を粗適用(数十行ごと)にして速度・安定を見る。
