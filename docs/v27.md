## 仮説
一部の坑井は **typewell が実質同一（ファイル名だけ違う）** で、horizontal well(HW) だけ異なる。
train HW は eval 区間も真値 TVT が既知なので、**同一typewellを共有する train HW の GR と test HW の GR を直接マッチング**すれば、
test HW の eval 区間 TVT を現行 PF/GBM とは別系統で高精度に当てられるのでは、という仮説。
※同一typewellを持たない坑井は対象外＝現行パイプライン（v25/v26/7.191系）で処理。

## フェーズ1（このノートの範囲）= train/valid 分割まで
1. 全 train typewell を**全列・全行の完全一致**でグルーピング（`to_csv` 全内容を sha1 で束ね、**`pandas.equals` で完全一致を検証**）。typewell は名前が違うだけで中身が全く同じ、という前提（丸めなし）。
2. **グループサイズ≥2**（同一typewellの相方あり）の坑井のみ対象。**グループ内 leave-one-well-out (OOF)** で
   `valid坑井 ↔ 参照train坑井` ペアを生成。
   - valid: test 模擬（GR全区間 + TVT_input既知prefix のみ。eval区間TVTは採点用の隠し真値）。
   - 参照: train全既知模擬（GR + **TVT全真値**、eval相当も既知）。
3. アクセサ（`valid_arrays`/`ref_arrays`）＋**採点土台**（eval行プールの overall RMSE）。
   照合は `match_predict(va, refs)` スタブ（現状 None→ベースライン `last_known保持` にフォールバック）。

## 実装した照合(セル7-9)

## 結果 / 所感（2026-07 スモーク検証）
- **グループ実測**: 同一typewell多坑井=**13群34本**(全体4.4%)。**10本群×1＋2本ペア×12**。
- **カバレッジ**: eval行の **73.4% が参照TVT範囲内、残り26.6%は必ず“トゥ(最深)”**。ペアは片方がトゥ超過で未カバー。
- **★M1(幾何datum転写)は失敗**: 10本群 LOO プールで **hold 22.29 → M1 32.64（悪化）**。勝つのは 3417285d(34→16)等の少数だけ、大半は悪化(例 6ae68655 5→38)。ペアは単独参照でdip転写不能→hold止まり。
- **診断**: 同一typewell = 同一**層序(GR-TVT)**であって同一**dip/幾何**ではない。空間的に離れた別ラテラルのため、**MD整列は水平区間でdip差を積分して破綻**。
- **含意**: 照合は幾何(MD/datum)でなく**層序(GR)空間**で、かつ**トラッカー(≒PF)の中**でやる必要。ユーザーの「これもPFになる」直感が裏付けられた。
- **次手**: ① M2 の prior に**現行パイプラインのPF出力**を渡す、② 参照(GR,TVT)で **typewell尤度を augment した PF**。どちらも ORACLE と現行PF(この34坑井)との比較で価値判定。

## ★PF + 疑似typewell混合（セル10-11, 本命）
- **発想（ユーザー）**: 参照train HW の実測 (GR,TVT) を **GR(TVT)曲線＝「疑似typewell」** に変換し、本物 typewell に **w_hw で混ぜて PF の尤度gridにする**。混合 vs 非混合(typewellのみ) を同一PFで A/B。
- **実装**: `build_grid_mixed` が参照HW GR を step一定TVT gridにビン平均→疑似typewell化→カバー帯で `w_hw*疑似 + (1-w_hw)*typewell`（未カバー=typewellのみ）。typewellの間隔は再構成するので不問。
- **PF = v25 r0 torch/GPU 忠実移植**（`_pf_smoother_core`/`run_smoother_ens` を verbatim、grid以外はv25と完全同一。尤度加重seed, `N_SEED=32`, `SMOOTH_LAG=192`, N=400）。GPUバッチ(CHUNK=16)。
