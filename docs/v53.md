# v53 — Evidence Fusion Field(全証拠の (時間×δ) 場を単一モデルでデコード)

> **状態: 実装済・スモーク通過(2026-07-11)。create/train はユーザー実行待ち。** 目標: 単体 6.x → v52 統合で 5.5 圏。
> スモーク: create(3坑井×1バンク)end-to-end 56秒で通過。部分キャッシュguard(v52の教訓)実装済み。
> 根拠となる過去実験: v34(事後を細かく渡すだけで gate 最高 LB5.930)/ v50B(スカラー集計は死・場のままConvは生)/
> v51(NN-emissionで全バンクの事後が鋭利化)/ Stage C(618井戸でのスカラー検証器は崩壊→場+バンクdropoutで対抗)。

**アプローチ図: [pipeline_v53.svg](pipeline_v53.svg)**

## 設計原則
1. **事後を捨てない**: PF は mean/std でなく「行別 粒子質量ヒストグラム(δ場)」を出力する。
2. **陪審員は場として提示**: 多エンジンの合意/分裂を (時間×δ) の多チャネル画像にして Conv に読ませる
   (スカラー集計にした瞬間死ぬ、が Stage C の教訓)。
3. **soft出力**(δ分布→posterior mean)。hard 選択はしない(v29/v34)。
4. 増強 = **バンクdropout**(PF場チャネルをランダムに落とす)+ ノイズ。混合の過学習への直接対抗。

## 証拠テンソル EV23(チャネル設計, stride16・struct±45ft・0.5ft格子 = v50 と同一座標系)
| ch | 内容 | ソース |
|---|---|---|
| 1-10 | v50 evidenceB3 の10ch(OOF学習類似度/生尤度/prior/δ座標/σ/FB事後γ/self整合/self有/nbr整合/nbr有) | 既存 `evidenceB3_v50.pkl`(train)/ submit内再構築(test) |
| 11-28 | **★PF事後場 18ch = 6バンク(pf_1/2/3, r0, r1, pfA)× {tw, nbr, self}** の行別粒子質量ヒストグラム。NN-emission付き(W=0.02, pfAのみ0.01+struct錨)、16seed平均、forward事後 | 新規 create(PFコアに hist scatter を追加) |
| 29 | v50B(combo デコーダ5本平均)の事後 P̄ | 既存デコーダで計算 |
- ★self フレーバー採用(2026-07-11 ユーザー決定。バンクdropoutが冗長を吸収する前提)。r4 は除外。EV=29ch。
- サイズ: 29×nb×181 fp16 ≈ 3.0MB/井 → 全773井 ≈ 2.3GB pkl。train/submit はチャネル数を自動追従。

## モデル(DecoderC = v50B 実証アーキの拡張)
- 入力 (23, nb, 181) → Conv2d(23→128, 5×5) → 時間dilated блок×5(dil 1,2,4,8,16; δ方向等方k5; GN+residual)
  → 時間bi-GRU 大域文脈(δ平均→放送)→ 1×1 → δ181 logits + ±2ft 回帰精緻化ヘッド(REFH)。
- 損失: soft CE(真δビン σ=2bin)+ 0.02×行数重み付き posterior-mean MSE(v50B と同一)。
- 増強: **バンクdropout**(ch11-22 の各場を p=0.15 で独立にゼロ化)+ 入力ノイズ 0.02。
- fold: v50 と同一(sorted wells の [f::5])→ 既存エンジン群と正直に統合可能。
- VRAM: TOKMAX=1200・VFRAC=0.5 で 6-7GB 以内。

## ファイル構成と実行手順
```
# 0) 前提: v52 create 済(sim_rows_train.pkl / evidenceB3_v50.pkl / combo デコーダは既存)
python v53/create_evidence_v53.py        # ①PF事後場12ch生成+EV23組み立て → artifacts_v53/evidenceC_v53.pkl(GPU ~2h)
# ② train_v53.ipynb                      # DecoderC 5fold 学習 → nn53/*.pt + 全坑井正直RMSE + v53_feature.npy(v52 parquet整列)
# ③ Kaggle: artifacts_v53(nn50/ + nn53/ + struct_field_v38.npz)→ submit_v53.ipynb(v53単体提出)
```
- create は v51 nnpf 機構ベースの自己完結(6バンク×2フレーバー×16seed、PFコアに hist を追加)。
- train はノートブック。最終セルで v53_feature.npy(delta/std/margin/maxp)を v52 parquet 行に整列
  → **v52 tabular/TCN への特徴注入がそのまま可能**(スタック統合の入口)。
- submit は v9特徴ビルド不要の軽量チェーン: test struct → sim自己生成 → PF事後場 → EV23 → DecoderC(5本平均)
  → z = struct + δ̂ をそのまま提出(pp/SGなし)。

## ★リーク事故と修正(2026-07-12)
- **初回 create にリークあり**: ch29(v50B事後 P̄)を train 井戸にも「combo デコーダ5本平均」で計算していた。
  井戸 w(fold f)にとって OOF は decoder f の1本だけで、**残り4本は w を学習済み=in-sample でほぼ正解を記憶**
  → ch29 に正解が漏れ、DecoderC は「ch29 を写す」だけで val でも当たる。
  症状: **fold0 RMSE 4.296(基準 v50B fold0 5.771 から −1.48 の良すぎる値)**で発覚。
- 修正: `create_evidence_v53.py` の assemble を **train=OOF(自foldデコーダ1本のみ)** に変更
  (v52 `v50b_feature_v52.py` と同じ流儀)。**test(submit)は5本平均のままで正しい**(隠しtestはどのデコーダも未見)。
- 他チャネルは無事: PF hist の sim は OOF(sim_rows_train.pkl)、10ch 証拠は OOF 構築済み、
  self/nbr プールは既知行のみ(test 時と同一の情報量)。
- リーク済み成果物は `*_LEAKED.*.bak` にリネーム(evidenceC pkl / decC_f0.pt)。
  **再実行手順: create(hist キャッシュ全カバー済みなので PF パスはスキップ→assemble のみ・短時間)→ train**。

## リスクと対策
- チャネル冗長(NNバンク間 corr 0.7-0.86)→ バンクdropout。
- 較正ずれ(hist は forward 事後で γ より鋭い)→ モデル入力なので学習が吸収(固定FBに掛けるのではない)。
- test 側の PF hist は submit 内で自己生成(エンジンに hist patch)— 経路は train と同一コード系。
