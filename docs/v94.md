# v94 — 逐次脱相関でゼロから新PFバンクを構築（v93非参照の独立環境）

> 参照: v93の全知見は [v93_summary.md](v93_summary.md)。v94はそこから独立した新環境として作り直す。作成 2026-07-29。

## 仮説
- 良いアンサンブルは「精度」より「**互いに脱相関した推定器の束**」で決まる（[[v77-k16-anchor-lattice]] 第2推定器実証, v93 warm逆走の脱相関blend −0.13）。
- 既存6PFは相互相関が高い（平均0.725, [[v93_summary]] §4）。**最初からゼロで、各PFを直前まで採用した全PFと corr≤0.7 になるよう逐次に作れば**、設計的に脱相関した束が得られるはず。
- ★v93の engine mismatch 教訓（[[v93_summary]] §5）: 脱相関は「調整＝本番」同一エンジンで測らないと転移しない。→ **v94は全てforward PFで統一**し、相関を apples-to-apples で測る。

## 変更点（v93 → v94）
1. **完全独立環境** `v94/`（v93非参照）: `pf_engine_v94.py`（v93複製・ART=`artifacts_v94`）、錨pkl複製。公式データ `rogii-wellbore-geology-prediction/` のみ共通参照。
2. **ゼロから逐次構築**: 既存6PFとの比較をやめ、**v94内で採用したPFのみ**を比較対象にする。
3. **比較対象が増える**: 各PF採用後にその**全773井の誤差**を `pf_{i}_errs.pkl` に保存。次PFは保存済み誤差を現在の600井にインデックスして相関を測る（priorを毎回再走させない）。
4. 旧予定（v93 anchor付き600井調整）は**キャンセル**＝このv94逐次に置換。

## 手法
- エンジン: `pf_engine_v94`（forward, 非smooth, NN-emissionなし）。**全て同一エンジン**なので脱相関が転移可能。
- チューナ: `v94/tune_v94.py`（PF 1本＝1起動、IDX自動＝既存 `v94_pf_*.json` 数+1）。
  - **well = ランダム600井**。**seed は PF idx ごとに変える**（`seed_{idx}.txt` に保存＝resume安定, 生成は `os.urandom`）。
  - **trials=200 / n_seeds=32固定 / gs_scale 1.0-2.0**。
  - **PF#1 = 相関制約なし**（純 overall RMSE 最小）。**PF#2以降 = 採用済み全v94 PFと |corr|≤0.7**（ソフト罰則＋feasible-best採用, 誤差ベース相関A）。
  - **物理anchor 順序 = off, on, off, on, ...**（idx 奇数=off / 偶数=on）。
- 出力（`v94/artifacts_v94/`）: `v94_pf_{idx}.json`（params+相関）, `pf_{idx}_errs.pkl`（全井誤差）, `optuna_v94_pf{idx}.db`, `seed_{idx}.txt`。

## ★corr閾値 0.7 vs 0.8 の実測(2026-07-30)
PF#3(off, vs PF#1,2)の限界ブレンド利得を、閾値別に3本ブレンド(全別シード777/314159/271828, n_seeds32, 全井)で測定:

| PF#3版 | 単体RMSE | corr(vsPF#1) | 3本blend重み | 3本RMSE | ★PF#3限界利得 |
|---|---|---|---|---|---|
| corr≤0.7版 | 10.45(弱) | 0.655 | 0.10 | 7.4966 | −0.037 |
| **corr≤0.75/0.8版** | **9.71(強)** | 0.701 | 0.20 | **7.4339** | **−0.0996** |

- **緩めると利得2.7倍**(−0.037→−0.10)。強いPF#3は少し相関上がっても重み倍付きで寄与大。0.7は制約キツすぎでPF#3を弱くしすぎ。
- **→ CORR_MAX=0.8 採用**(ユーザー指示2026-07-30)。v93の7番bank(0.759無効)は「大smoothアンサンブルに冗長追加」で別物=クリーン小アンサンブルでは0.75-0.8有効。
- 2本(PF1+PF2)=7.5335 → 3本(0.8版)=7.4339。**弱いPF#1も含め3本で7.43**。

## 目的関数の試行錯誤(2026-07-30) → 結論: corr≤0.8下でRMSE最小
経緯を記録(後の教訓):
1. **「min単体RMSE s.t. corr≤0.8」**: 0.8の余裕で相関を上げる小改悪(9.70/corr0.777 vs 旧9.71/corr0.701)。だが**強いPFは出る**。
2. **min-varブレンドRMSE直接最小化(相関制約なし)** を試行 → ★**弱くて極端に脱相関なPFに収束**(in-sample: ゴミ17.88/corr0.29がblend7.4774でgaming)。
3. **held-outブレンドRMSE**(600井2分割fit→eval) を試行 → ノイズgamingは潰れたが、**なお弱い脱相関PF(15.43/corr0.35, blend7.469)に収束**。min-varは本質的に「極端な脱相関」を高評価するため。**15.43はnaive床15より悪い予測器=選択器(oracle)endgameに無価値**。
4. **★結論: 相関制約 corr≤0.8 下でRMSE最小 に戻す**(ユーザー判断2026-07-30)。強いPF(選択器に有用)が出る。ブレンド目的の小改悪より「弱いPF量産」の方が有害。
- ＝**min-varブレンド目的は選択器endgameとズレる**(弱い脱相関を好む)。**強いPFが欲しいなら RMSE最小 under corr≤cap が正解**。
