## 手法（実装仕様）
1. **PF固定**: `P = r0_seed32 params`（全坑井共通）。カテゴリ分岐なし。
2. **Optuna探索空間 = smoothのみ**:
   - `smooth_lag`（固定ラグL, categorical 例 [8,16,32,48,64,96]）
   - `smooth_blend`（forward↔smoothed のブレンド比, float [0,1]）
   - ※ v23 の `suggest_smooth` がそのまま使える。
3. **n_seed = 32**（★r0のチューニングregimeと一致。128は間違いモード寄り＝[scores.md]の実証）。
4. **目的関数**: overall RMSE（全行プール）。
   - ★**out-of-fold（GroupKFold by well）が本筋**（[analog_competitions.md] grouped-CV-by-well、v22/v24過学習の反省）。
     ただし smoothは2paramで過学習しにくいので、まずは v23同型の in-sample overall で回して**forward-only（=r0素）から smooth で下がるか**を確認 → 効けば out-of-fold で締める、でも可。
5. **出力に forward-only と smoothed の両方**を出す（v23 tuner は既に `fwd`/`smo`/`blend` を表示）。**smo < fwd なら平滑が効いている**。r0素の overall（forward）が基準。

## 実装の近道（速度）
- PF（r0）は固定なので、**前向きは各坑井1回計算**すれば十分。smooth_lag/blend を変えても前向きは同じ → 前向きの per-seed 軌跡＋系譜バッファ（最大ラグ Lmax）を**キャッシュ**して、smooth読み出しだけ振れば**探索が速い**。
  - 簡易版: v23 tuner をそのまま（毎trial forward再計算）でも、探索空間が2次元なので N_TRIALS 少なめ（30-60）で十分。
- 固定ラグは GPU軽量（v23記載: L=32で実用2〜3倍。窓NCC等の重い機構は入れない）。

## 期待 / 検証観点
- **基準 = r0素の forward overall**（≈ r0_seed32 の train overall。LBは 7.098）。
- **smooth で overall が下がるか**。下がれば Particle Smoother が本物 → 提出（submit_heuristic_v22 相当に smooth を後乗せ、または v25 提出ノート）。
- `smooth_blend` が 0 に張り付く → smooth無効。1側/中間に伸びる & `smooth_lag` が大きめ → 未来Lステップが効く＝look-ahead本物。
- **注意**: v23 の固定ラグは**系譜退化**があるので L 過大は逆効果。研究の本命は本来 **FFBSi（後ろ向きサンプリング）**。固定ラグで効くなら、次段で FFBSi版に発展（別途）。

## FFBSm（Forward-Filter Backward-Smoother, 平均直出し）: `v25/tune_ffbsi_r0_v25.py`
> 固定ラグの「全未来を使うほど良い」の**極限**を、**系譜退化なし・メモリL非依存**で取る。2026-07-03 実装済み（未実行）。

### なぜ FFBS か
- 固定ラグ（パス空間平滑）はL過大で系譜退化。FFBS は **forward の粒子雲を使い回して後ろ向きに重み付け直す**ので退化しない。研究([analog_competitions.md])の**最優先**。
- **逆向きに新PFを走らせるのではない**（=v10逆向きPFの「トゥにアンカー無し→datum誤り相続」問題を回避）。forward粒子はヒール錨付きのまま。

### アルゴリズム（FFBSm = marginal, 平均直出し）
- forward を n_seed=32 で回し、各 t の粒子 (pos,rate) と正規化フィルタ重み `w_t`(リサンプル前)を保存。
- 後ろ向き再帰: `w_{t|T}^i = w_t^i Σ_j w_{t+1|T}^j f(x_{t+1}^j|x_t^i)/Σ_l w_t^l f(x_{t+1}^j|x_t^l)`、平滑平均 `Σ_i w_{t|T}^i (pos_t^i−z_t)`。
- 遷移密度 `f = N(rate'; α·rate, (vn·inflate)²)·N(pos'; pos+rate'·dm, (pn·inflate)²)`。jump/clip/roughening は非計上（標準近似）。
- FFBSi(M本サンプリング)ではなく **marginal（平均を直接）**。RMSEは事後平均で測るのでこちらが最適・ノイズなし。

### n_seed
- **32のまま**。backwardは forward雲を使い回すだけで新seedを足さない（`ffbs_forward_well`→`ffbsm_backward_well`）。

### 肝 = `TRANS_INFLATE`（LAGSと同じスイープ役）
- r0は vn=0.00063 / pn=0.005 と**プロセスノイズ極小＝遷移がほぼデルタ** → 忠実(inflate=1)だとFFBSmが系譜スムーザーにほぼ一致。
- **遷移カーネルの帯域を膨らませる `TRANS_INFLATE`** が実質のsmooth強度ノブ（大=退化を崩し未来を広く使う）。
- ★**実測(2026-07-03, 序盤6坑井)**: `inflate=1.0` は遷移が尖りすぎて**数値退化**（well5で坑井RMSE 15→**85に爆発**、vj≈0で重み暴走）。`2.0/4.0` は安定かつ forward を大きく下回る（well4 4.47→2.53, well6 5.00→2.09、走行overall fwd9.08→@2 7.78）。→ **1.0/2.0を捨て `TRANS_INFLATE=[4.0,8.0,16.0]` に変更**。

### フォールバック・クランプ（ヘビーテール対策=最重要）
- FFBSは**大勝ち＋たまに大惨事**のヘビーテール分布。overallは二乗プールなので**1本の爆発坑井が overall を丸ごと壊す**（しかも blend は全坑井共通の1個＝1本の爆発を避けようと blend↓すると全利得が消える）。
- → **`CLAMP_FT`（既定60ft）**: FFBS平滑予測が forward から ±CLAMP_FT 超で外れた**行だけ forward に戻す**。爆発(数百ft)の下振れをキャップ、datum修正(~数十ft)の大勝ちは残す。発動行数を per-well 表示に `[clip@..=n]` で出す。

### 構造 / 出力 / 実行
- STEP1: forward1回/坑井 + inflateごとに後ろ向き平滑 → STEP2 in-sample Optuna(inflate,blend) → STEP3 OOF。全部 precompute+解析blend。
- 出力 `v25/artifacts_v25/ffbsi_r0.json`（forward_baseline / insample_best / per_inflate / oof）。
- 実行 `rogii_claude/.venv/Scripts/python.exe v25/tune_ffbsi_r0_v25.py`。
- **注意**: 後ろ向きは O(T·N²·S)/坑井で重い。まず `TRANS_INFLATE=[1.0]` で1本試す→2.0/4.0を足す。OOMは N_SEED/n_particles を下げる。
- 判定: `oof.overall_ffbs < oof.overall_forward` なら退化なしで全未来が効き汎化もする＝本物。固定ラグの−0.229をどのinflateで超えるかが見どころ。

### ★LB結果（2026-07-03, `submit_ffbsi_v25.ipynb`）＝ 7.020（単体最良）
- **v25 FFBS(r0固定+FFBSm+clamp+blend1+apply_pp) = LB 7.020** vs v22 heuristic r0_seed32 = 7.098。**−0.078 で現状の単体最良**（v9 6.946 に更に肉薄）。

### ★★LB新ベスト = smoother(lag192) + beam + hold = 6.786（2026-07-03, `submit_smoother_v25.ipynb`）
- **固定ラグ系統スムーザー(r0固定, L=192, blend1) + カテゴリ別 beam+hold + apply_pp = LB 6.786**。
- **ついに v9(6.946) を突破**（−0.16）＝**コンペ通じて初の 6.9 割れ**、現状ベスト。
- **判明した重要事実**:
  1. **beam/hold の寄与が平滑より大きい**。train診断(15坑井): fwd 8.819 → ffbs 8.188(−0.63) / fwd+beam+hold 7.798(**−1.02**) / ffbs+beam+hold 7.384(−1.44)。**beam+hold単体(−1.02) > FFBS単体(−0.63)**、かつ**ほぼ加算的**(別々の誤差を直す=beam:大域DPでdatum解決 / hold:アンカー収縮でドリフト分散圧縮 / 平滑:未来GR)。
  2. **FFBS提出7.020が微増止まりだった正体 = beam/hold(−1.0の価値)を捨ててFFBS(−0.63)だけ足した→ほぼ相殺**。beam/holdは捨ててはいけなかった。
  3. **固定ラグはFFBSの下位互換ではない(「下位互換」は誤り, 訂正済)**。**固定ラグ+beam+hold が FFBS単体を破った**。固定ラグ=実粒子パス(jump/clip/roughening込み)の忠実平滑、FFBS=inflateで広げたガウス遷移(jump/clip落とし)＝別ターゲット。**hidden testでは忠実さが効いた可能性**。
  4. **ヒューリスティックがGBM(v9)を上回った** ＝「単一頑健推定 + 軽い後段(beam/hold/OOF調整)」路線がGBMより強いことをLBで実証。GBM化(FFBS特徴→LightGBM)の優先度は↓。
- **直接対決の結果（2026-07-03）**: **FFBS+beam+hold = LB 6.886** < smoother+beam+hold **6.786**（−0.10 で smoother 勝ち）。両方 v9(6.946)突破。
  - **★パラドックス**: train gain は FFBS(−0.6) ≫ smoother(−0.229) なのに **LBは smoother が勝つ** ＝ **FFBSの train-LB乖離（過学習）**。FFBS=inflate32 で広げたガウス遷移(jump/clip/roughening落とし)＝train過剰fit→hidden testで目減り。固定ラグ=実粒子パス(jump/clip込)の忠実平滑→素直に転移。**「train削りすぎる手法ほど転移悪い」**の一貫パターン。**忠実さ(固定ラグ)＞平滑力(FFBS)** が hidden testの判定。
- **次の一手(優先)**: ①**FFBS+beam+hold 提出**(6.786と直接対決=忠実さ vs 平滑力)。②**beam/hold重みを平滑土台でOOF再チューン**(今の値はforward用=ズレを取ればさらに削れる)。③**smoother⊕FFBS⊕beam の mode-aware 合成/選択**(素朴平均禁=双峰を潰す)。

### ★転移診断の結果（2026-07-03, 実施済）＝強い転移シグナル
- **適当な(未適応な)PFパラメータでも FFBS はほぼ改善する**（一部PFは悪化するが大方良い）。
- 解釈: 改善は「未来GRがforwardを締める」**メカニズムそのもの**であり、特定PFのtrain fitに寄生してない → **test regime(r0が未適応に振る舞う)でも効く筋が濃厚**。r0(LB7.098の汎化PF)は"大方良い"多数派に入る想定。
- 「一部悪化」= FFBSは雲が覆えない真値を復元できない（雲が退化/誤datumロックのPFは未来GRも同じ罠→誤差相関で悪化）。**PF選びは依然重要**（壊れてないPFなら効く、という条件付き）。
- 結論: **LB前の転移見込みが大きく上がった**（保証ではないが強い事前確率）。最終確定は OOF→LB。

## pseudo-satellite 反復（研究#7）＝ボツ（2026-07-03, `tune_pseudosat_r0_v25.py`）
- 狙い: FFBSの平滑軌跡を prior に forward を再走行（アンカー項 `w*=exp(-0.5((tvt-ref)/sig)²)`）→再FFBS で support不足を埋める（EM的二周目）。
- **結果: iter1(anchor再走行) は iter0(=pure FFBS) を超えない**（fwdよりは良いが FFBS単体が天井）。ANCHOR_SIG を振っても改善せず。
- **なぜ**: ↑の転移診断で「未適応PFでもFFBSが効く」＝**forward雲は既に真値を覆えてる＝support不足が起きてない** → 埋めるものが無い。アンカーはGR駆動の多様性を削りバイアスを足すだけ。r0が良い汎化PFゆえ二周目に伸びしろ無し。
- 教訓: **FFBS単体が天井**。反復EMは不要（研究#7は"could"止まり=想定内の外れ）。次の探索は #8(dip系統バイアス回帰, cat4狙い)/#2(beamコスト項別) だが、まず FFBS を OOF→LB で確定させるのが先。
