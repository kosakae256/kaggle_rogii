# v23 — PFの代替/派生フィルタ群（グリッド / APF / 平滑 / GSF）

> PFの頭打ち打破に複数のフィルタを試す。グリッド系=見送り、APF=ダメ、
> **Particle Smoother=あり(見込み)**、Gaussian Sum Filter=実装済み(実験待ち)。
> 最終更新: 2026-07-01
>
> 早見表:
> - グリッド/HMM(1D/2D/RBPF) … **見送り**（PF超えられず）
> - Auxiliary PF … **ダメ**（粒子枯渇でなくGR尤度≠真値が壁）
> - **Particle Smoother(固定ラグ) … 【あり】**（未来GRを使う唯一案。fwd8.79→smo8.70）
> - **Gaussian Sum Filter … 実装済み・実験待ち**（双峰を明示追跡→posterior mean, 決定論・seed不要）

## 仮説 / 狙い
- 状態が1次元(TVT位置)なので、PF(モンテカルロ近似)よりグリッドの厳密事後の方が向くのでは。
  リサンプリング無し・粒子退化無し・seed不要(決定論)・look-ahead・posterior-mean hedge を狙った([[pf-alternative-algorithms]])。
- カテゴリ別(selectorの6分割)に Optuna でチューニング。

## 作ったもの
- [v23/tune_grid_filter_v23.py](../v23/tune_grid_filter_v23.py) … **1Dグリッド**(posのみ)。dip は固定パラメータ。
- [v23/tune_grid2d_v23.py](../v23/tune_grid2d_v23.py) … **2Dグリッド**(pos×dip格子)。dipを状態化。
- [v23/tune_grid_rbpf_v23.py](../v23/tune_grid_rbpf_v23.py) … **Rao-Blackwellized**(pos格子＋セル毎dip Kalman, moment-match)。

## 結果（見送り）
- **1Dグリッド**: dipを状態に持たないため、`proc_sigma`大で蛇行(~35)、小で「**傾きが固定で間違った直線**」(cat0 best **14.21**)。
  GR特徴(wiggle)はほぼ拾えず＝**ほぼ直線**。flat(16)とconstant(9)の間で、line oracle(6.6)に届かない。grid系の中ではこれが最良。
- **RBPF(B)**: 実行したが **ダメ**（1D 14.21 にも及ばず）。moment-matching の近似が崩れたか、dip推定が効かず。
- **2Dグリッド(A)**: コードは用意したが、(B)がダメ・1Dが直線止まりの時点で **grid路線ごと見送り**（Aの結論的検証は未実施）。
- **結論**: グリッド/HMM は PF(~9, cat0)に届かず（grid最良=1Dの14.21＝ほぼ直線）。**この問題ではPFの粒子表現(2D状態pos×dipを効率追跡)が優れている** → 見送り。

## 学び（グリッド系）
- 1D格子は dip固定で「正しい傾きの線」になれない（過外挿）→ 直線止まり。
- 2D化(dip状態化)は理屈は正しいが、実装上(格子粗さ・近似・平滑)PFを超える精度が出ず、**「軽くて速くて正確」の同時達成は崩れた**。PFが使われる理由(粒子で2D状態を効率表現)に回帰。
- → PF頭打ちの打破は**アルゴリズム置換でなく**、別レバー（カテゴリ別PFチューニング v22 / 双峰hedge=posterior mean / selectorへのGPU PF投入 / 構造）に戻る。

## Auxiliary Particle Filter (APF) — 派生PFのチューナー（2026-07-01 追加）
- [v23/tune_apf_v23.py](../v23/tune_apf_v23.py) … **APF を v22 と同じ枠組み（6カテゴリ別・Optuna・再開可）でチューニング**。

### 仮説
- グリッド置換（別アルゴリズム）は負けた。が、**PFの粒子表現は残したまま「リサンプリングだけ賢く」**するのが APF。
  尤度が鋭い坑井で **粒子枯渇** を抑えれば、同じ粒子数で事後をよりよく保てる → 硬い核/多峰tailで効く可能性。

### 通常PF（v19/v22）との差分（エンジン `_apf_core` のみ）
- 通常: 伝播 → 尤度で重み → (ESS低下時)リサンプリング。
- APF: 各観測ステップで **先読み**。
  1. 決定論的予測点 μ＝`pos + mom·rate·dMD`（過程ノイズ無し）
  2. 一段目重み `g = w·p(y|μ)` で**祖先を系統リサンプリング**（次に尤度が高くなる粒子を先に増やす）
  3. 祖先（+`rp`/`rr`ジッタ）からノイズ伝播
  4. 二段目重み `w ∝ p(y|x)/p(y|μ_anc)·phys`（先読み分を不偏に補正）
- 観測の無い act ステップは通常通り「ノイズ伝播のみ・phys重み」。
- 読み出し（事後平均）・シード尤度加重アンサンブルは v19/v22 と同一。
  log_lik は APF 不偏予測尤度 `gsum × mean(w_e)`（emission のみ＝v19 と整合、`likelihood_scale` 範囲を流用可）。

### パラメータ空間
- v22(=v19) の空間 **＋ 先読み専用パラメータ2つ**を追加。
  - **`apf_lookahead`（β, 0.5〜2.0）= 先読みの強さ**: `g = w·p(y|μ)^β`、二段目補正 `w ∝ p(y|x)/p(y|μ_anc)^β` も β で揃える。
    β<1=穏やか／β=1=標準APF／β>1=攻撃的（鋭い尤度で枯渇をさらに抑えるが、GR尤度≠真値だと間違ったモードへ先回りして悪化もありうる）。
  - **`apf_mu_drift`（κ, 0.5〜1.5）= 先読み予測点の外挿量**: μ = `pos + κ·(mom·rate)·dMD`。
    κ<1=控えめ外挿／κ=1=素直に外挿（現状）／κ>1=強め外挿。dipの変化が速い坑井で「どこを覗くか」を調整。
  - どちらも `P.get(..., 1.0)` なので **v22 の best をそのまま投入しても β=κ=1（標準APF）として動く**（ウォームスタート互換）。
- ただし **`resamp` は APF では未使用**（毎観測ステップで先読みリサンプリングするため）。`rp`/`rr` は祖先ジッタ（正則化）として使用。

### 出力 / 実行
- 出力: `v23/artifacts_v23/per_category_apf.json`（code→best params）。グリッド系とは別 db（`optuna_apf.db`/`state_apf.json`）で衝突しない。
- 実行: `.venv/Scripts/python.exe v23/tune_apf_v23.py`（6カテゴリ自動・再開可）。

### 結果 — ダメ（見送り, 2026-07-01）
- **APF は効かなかった**（ユーザー判定）。通常PF（v19/v22）を超えられず。
- 解釈: この問題の難所は**粒子枯渇ではなく「GR尤度≠真値」**。APFの先読みは「次の観測で尤度が高くなる粒子」を先に増やすが、
  その尤度自体が間違ったモード（双峰tail等）を指しているため、**先読みは"間違った方向に賢く先回り"するだけ**で精度に寄与しない。
  β・κ（先読み強度・外挿量）を振っても本質は変わらず。→ **リサンプリングの賢さでは頭打ちは抜けない**（grid置換がダメだったのと同根）。
- 教訓の更新: **PF系内のアルゴリズム改良（grid置換／APF）は両方ダメ**。残るレバーは「PFの中身」でなく**外側**（baseline置換＝構造prior / 双峰hedge / 入力情報の追加）。

## Particle Smoother — 固定ラグ系統スムーザー（2026-07-01 追加）
- [v23/tune_smoother_v23.py](../v23/tune_smoother_v23.py) … 前向きPFに**後ろ向き（未来を使う）平滑**を足し、v22枠組み（6カテゴリ別Optuna・再開可）でチューニング。

### 仮説（他のPF改良と"質的に違う"理由）
- grid置換もAPFもダメ＝**GR尤度を信じて整えるだけ**では「GR尤度≠真値」の壁に同じくぶつかる。
- 平滑は**唯一"新しい情報の使い方"が増える**: 評価ゾーンは look-ahead 合法なので、中間ステップ t の予測に
  **未来 y_{t+1:t+L} の GR** も使える。forward は過去しか見ていない → 中間ステップ（アンカーから遠いが、さらに先のGRで縛れる所）を未来情報で締める狙い。

### 実装 = 固定ラグ系統スムーザー（fixed-lag genealogy smoother）
- 前向きPFを走らせ、リサンプリング時に**系譜**で過去Lステップの位置バッファを現在粒子に整列。
  ステップ i で t=i-L の平滑事後平均 = `Σ_n w_i^n · (粒子n の t時点の位置)`。末尾Lは最終重みで flush。
- **全部GPU**（バッファ・gatherもdevice上）。**固定ラグにしたのはGPU不可だからではなく VRAM/計算量の都合**:
  全長FFBSは `(B,T,N)` 保持でVRAM溢れ＋後ろ向きO(N²)×全T×250trで日単位 → 固定ラグは `(B,L,N)` で12GBに収まり O(B·N)/step。
- 注意: 系譜は**ラグ大で退化**（祖先が少数化）するので L を上げ過ぎると効果頭打ち/逆効果 → `smooth_lag` を探索。

### パラメータ
- v22(=v19) のPF全空間 ＋ スムーザー2つ: `smooth_lag`（L=先読みステップ数, {8,16,32,48,64,96}）、`smooth_blend`（forward↔smoothed ブレンド比, 0〜1）。
- **v22 best を warm-start で enqueue**（既知の良いPF設定から出発、+lag32/blend0.5）。
- objective = **blended の overall RMSE**。記録に forward-only / smoothed-only も残し**平滑の寄与が見える**。
- 出力 `artifacts_v23/per_category_smoother.json`、別db `optuna_smoother.db`。実行 `.venv/Scripts/python.exe v23/tune_smoother_v23.py`。

### 結果 — 【あり】見込みあり（2026-07-01）
- 初手 cat0: **fwd=8.79 → smo=8.70**（blend=8.73）。**smo < fwd で平滑が効いている方向**。ユーザー判定「あり、精度は上がりそう」。
  - 0.09差はノイズ床(±0.2)内だが、**符号が一貫して smo<fwd** なら小さくても本物（trialをまたいで要確認）。
- **forward部分は v22 のPFと完全に同一**（`fwd` は v22 PFそのものの値）。スムーザーは**読み出しを1つ足すだけ**:
  forward=「`w_t` で `x_t` を平均（過去のみ）」/ smoother=「**`w_{t+L}`（未来反映の重み）**で `x_t` を平均」。粒子の動き・リサンプリングは不変。
- コスト: 追加は「系譜の並べ替え O(B·L·N)（リサンプリング時のみ）＋読み出し O(B·N)」。
  倍率 ≈ `1 + (2 + L·f)/C_fwd`（C_fwd≈18, f=リサンプリング頻度）→ **L=32で実用2〜3倍**、L=96・高頻度で最大6倍。
  全長FFBSは後ろ向き O(N²)＝~30倍級なので、固定ラグで N² を回避した形。

### 課題と運用（2段チューニング）
- **実行時間が長く全パラメータ同時調整は大変**（forwardが2〜3倍遅い × 全空間）。
- → **2段方式**: ①PFを smooth無し（=v22, forward-only, 速い）で調整 → ②**PFを固定して smooth_lag/blend だけ**を調整。
  - スムーザーは forward を変えない純粋な読み出し追加なので、**forward最適のPF設定は smooth後乗せの良い出発点**（厳密な同時最適とは僅かにずれうるが、速度のため許容）。
  - 実装: `tune_smoother_v23.py` の **`SMOOTH_ONLY=True`** で、v22 best をPF固定値として読み、`smooth_lag`/`smooth_blend` の2次元だけ探索（別db `optuna_smoother_only.db`）。トライアル数も少なくて済む。

## Gaussian Sum Filter (GSF)（2026-07-01 追加・実験待ち）
- [v23/tune_gsf_v23.py](../v23/tune_gsf_v23.py) … 事後を **K個のガウス混合**で表すフィルタ。v22枠組み（6カテゴリ別Optuna・再開可）。

### 仮説（この問題の理屈に最も合う）
- error_anatomy の本丸 = **双峰datum（±15ft の2位置）**＋「**確定より posterior mean が勝つ**」「worst10%=全誤差の40%」。
- GSF は **双峰を別成分として明示追跡**でき、**読み出し=重み付き平均=posterior mean** を自然に出す → tail狙い撃ち。
- dip(rate) は各成分の Kalman が畳み込む（Rao-Blackwell的に分散減）。
- **決定論（seed不要）**: 成分配置は決定的 → PFの「32seed×粒子」のノイズ床(±0.2)が消え、Optuna も安定・**むしろ速い**。

### エンジン（_gsf_core, W×K バッチ・全GPU）
- 状態 = (pos=geo_z, rate=dip) の2Dガウス × K成分（mean 2, cov 2×2, weight）。
- predict: 線形ガウス遷移 `rate'=α·rate, pos'=pos+rate'·dm`、`P'=F P Fᵀ+Q`（F=[[1,dm],[0,α]], Q=diag(pn²,vn²)）。
- update: 観測 `h(pos)=typewell GR@(pos−z)` をグリッド局所傾き s で**EKF線形化**。ゲインを **`ekf_gain`倍**して平均をGRへ引き寄せ、共分散を縮める（0=RBPF寄り/1=フルEKF）。重みは PF流の較正済み `exp(-0.5(|y|/gs)^gr_power)`（+任意 phys）。
- 多峰維持: 初期に K成分を TVT方向へ `init_span` で散らす＋ESS低下時に成分を系統リサンプリング（固定シードのジッタ=決定論）。
- 読み出し: `TVT=Σ w_k^read_temp·(pos_k−z)`（read_temp<1=hedge, >1=commit）。

### パラメータ / 出力 / 実行
- 主要: `n_components`(K), `init_span`(双峰被覆), `ekf_gain`(GR引き寄せ), `read_temp`(hedge↔commit), `resamp`/`jitter_*`, 共通GR/grid。
- 出力 `artifacts_v23/per_category_gsf.json`、別db `optuna_gsf.db`。実行 `.venv/Scripts/python.exe v23/tune_gsf_v23.py`。

### 結果
- （実験待ち）。観点: **v22物理PF(~9, cat0)・Particle Smoother(8.70)と比較**。
  - GSFが効くなら **双峰の硬い核**で per-well が改善するはず（posterior mean が midpoint を取る）。
  - `read_temp` が <1（hedge側）、`init_span` が大きめ（双峰を被覆）に落ちれば「双峰仮説が本物」のサイン。
  - 懸念: 観測h(GR)が wiggly で EKF線形化が不安定なら `ekf_gain`→0 に張り付く（=RBPF化）かもしれない。その場合は成分配置と重みだけで多峰を担う形。
