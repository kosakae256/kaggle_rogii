# v91 — 物理制約による事前分布(地質面サンプリング)で候補生成を作り直す

## 背景/動機(ユーザー方針 2026-07-26)
- 現行(v90まで)は **GRマッチの精度限界(~6.4壁)** に到達。物理制約が無いことが原因。
- hengck23スレッドの核心: **TVT = 地質面(ANCC面) − Z + b**。地質面(stratigraphic surface)は滑らかな傾斜面で、
  区分線形でモデル化しサンプリングすると、**線形plane oracle 4.82ft / 区分線形でさらに下**。
- 目標: **物理事前分布を複数候補として出力、oracle RMSE ~4.0**。GRマッチの限界を候補生成で突破。

## 制約(厳守)
- **他井戸の情報を参照しない**(nbr禁止)。自井戸の Z/MD/XY/最終既知TVT と typewell(TVT範囲拘束)のみ。
- **GRは候補生成に使わない**(生成は純幾何。GRは後段のスコアリングで)。
- 事前分布=複数候補(particles)。oracle(最良候補)~4.0 が望まれる。

## 手法(スレッド準拠)
- 各井戸 eval区間(最終既知h_ps以降)で、地質面の傾斜profileをサンプリング:
  - candidate_tvt(md) = TVT_last + change(md) − (Z(md) − Z_last)   ← dTVT = d(地質面) − dZ
  - change = 区分線形(制御点 K本, 各点でランダム傾斜増分の累積)。change(0)=0(最終既知で錨).
- 拘束: typewell TVT範囲[t_min,t_max]内 / 最初~30点は最終既知の±3ft(連続) / 傾斜有界。
- N粒子(~300-1000)生成 → oracle = 真値に最も近い候補のRMSE(全行プール)。

## 実験計画
1. 物理候補生成器(v91/physics_prior_v91.py): 区分線形plane サンプリング → oracle測定。
2. パラメータ(制御点K/傾斜range/N)を振って oracle を ~4.0 に。線形 vs 区分線形 比較。
3. oracle良好なら: 候補スコアラ(SDF CNN等, スレッド)で選択 → 実RMSE。合成augmentation(sim GR)も試す。

## ★全773井 + 楽観性検証 (2026-07-26) — oracleは幻、選択が壁
- 全773井(K=4,N=3000): **oracle 4.06 / GRマッチ選択 22.40 / base(dip外挿) 43.33**。

- 理由: 物理候補はdip幅広く±100ft超に散り、**GRサイクル縮退で多数候補が誤マッチ**→間違ったdip選択。base外挿は累積誤差43ft。
- 対照: 現PFはGR誘導生成で候補がGR整合に集まり選択容易。純幾何物理priorは広がりすぎGR選択破綻。
- **結論: 候補生成は簡単、選択が壁([[v47-selection-ceiling]])。oracle3.3-4は選択器なしでは幻。**
  物理priorの価値は強力な選択器(SDF CNN+合成aug+noise modeling, hengck23全体)に依存=本当の難所。or 物理×GR誘導併用。
