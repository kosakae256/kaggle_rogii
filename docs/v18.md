# v18

> **PF出力(パーティクル)からどれを選ぶかを学習する**(セレクタ)アプローチ。
> PF出力の oracle(各坑井で真値に最も近い候補を選択)が overall **~5.0** に達することを確認済み
> = 「生成(PF)は十分良い。あとは選択」。v18 はその選択を学習で行う。
> 最終更新: 2026-06-30

## 仮説
- PFの各出力軌跡を候補とすると、**正解に非常に近い候補が必ず含まれている**(oracle ~5.0)。
- よって「アンサンブル平均」ではなく「**正しい候補を選ぶ/重み付ける**」ことができれば、
  現状(PF lik-アンサンブル ≈ 9前後)から oracle(~5)へ大きく近づけるはず。
- 選択は **特徴量 → LightGBM 等**で学習可能ではないか(各候補のGR当てはまり・滑らかさ・幾何・他候補との一致など)。

## 方針(v10 を参考・逆方向なし)
- v9 の GPU 順方向PF([v9/pf_gpu_run.py](../v9/pf_gpu_run.py))を再利用。
- **アンサンブルせず**、paramセット(pf_1/2/3)×シードの軌跡を**1本ずつ候補**として事前生成・保存。
  - 候補数 = `len(PARAM_SETS) * N_SEEDS`(既定 3×32=96本/坑井)。
- 後段の特徴量/セレクタ用に、評価ゾーンの md,z,GR,真TVT,typewell も保存。

## ファイル
- [v18/generate_particles_v18.py](../v18/generate_particles_v18.py) … パーティクル生成(本ステップ)。
  - 出力: `artifacts_v18/particles/{wid}.npz`(`cand[n,T], loglik, setid, seedid, md,z,gr,gr_raw,true,ev_index,tw_tvt,tw_gr`)+ `meta.json`。
  - 実行後に **ORACLE / lik-ensemble の overall RMSE** を表示(生成物の健全性確認。oracle≈5を期待)。
- (次) セレクタ: 候補ごとに特徴量を作り LightGBM で「良い候補」を学習(別ファイル予定)。

## セレクタの設計メモ(次ステップ)
- 各候補(well×cand)を1サンプルとし、**目的変数 = その候補の(真値に対する)RMSE or ベストか否か**。
  - 回帰(各候補のRMSEを予測→最小を選ぶ) / ランキング(LambdaMART) / 重み学習(softmax)など。
- 特徴量候補:
  - **GR当てはまり**: 候補TVT上で typewell GR と観測GRの残差(平均/分位/窓NCC)。
  - **尤度**: PF内部 loglik(候補ごと)。
  - **滑らかさ/幾何**: 候補の dTVT, 曲率, dip と既知ゾーン dip の整合。
  - **他候補との一致**: 候補間の中央値からの距離(コンセンサス)、近傍候補密度。
  - **坑井メタ**: eval長, 既知長, GRノイズ(gs)。
- 評価は **overall RMSE(全評価行プール)**、CV は **GroupKFold by well**。
- リーク注意: 目的変数(真値RMSE)は学習時のみ。特徴量は test 由来列のみから作れること。

## 結果
- **生成 sanity(3セット×32シード=96候補/坑井, 2026-06-30):**
  - **ORACLE(単一候補/坑井) overall RMSE = 4.619** ← 選択の到達下限。生成は完成。
  - lik-ensemble(現状PF) overall RMSE = 9.354。
  - **伸びしろ ≈ 4.7。oracle 4.62 < v9 LB 6.946 なので、セレクタが 9.35→6.9 まで縮めるだけで v9 超え。**
