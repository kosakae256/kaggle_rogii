# v98 — 全部載せ(combo特徴 + 両PF強化 + 双方向DA + smooth192 + 5seed)

## 仮説
これまでの最良は **v96+v97の特徴結合(combo, CV 5.8881)**。伸びしろは「候補生成の質×多様性」と
「脱相関した学習データ」にある([[feature-combo-beats-ensemble]] / [[v36-backward-da]])。v98では
combo の土台に、**(a)両パイプラインのPF強化・(b)双方向のデータ拡張・(c)smooth192の長ラグ平滑**を
同時投入し、TCN/L5の2脚(tabularは情報過多で頭打ち→不使用)を5seedで学習して底上げする。

## 変更点(combo=v96+v97結合 からの差分)
1. **v96(v95パイプライン)のPFも強化** — v97同様の頑健尤度(Student-t)＋tempering を v95バンクに移植。
   各バンクに適した ν/β を **全井で自動探索**して採用(v97知見: ν≈5近傍, β<1)。
2. **逆方向DA(既存, v36再現)** — evalゾーンのみ抽出→行反転(MD'=MDmax−MD)→toe側K行を疑似既知帯
   (TVT_input:=TVT, K=min(既知帯行数, n_ev//2), 下限30)→残り n_ev−K 行を予測。`is_backward=1`。
3. **順方向DA(新規)** — 反転なし。既知帯を **eval区間の前半(n_ev//2行)まで延長**(TVT_input:=TVT)し、
   **後半 n_ev−n_ev//2 行のみを予測対象**とする(中点開始)。`is_fwdaug=1`。
4. **smooth 16 → 192** — 両パイプライン(v95/v97)を長ラグ平滑に。PF実行時 chunk=20(VRAM対策, `PF_WELL_CHUNK=20`)。
5. **学習は TCN + L5 の2脚のみ(GBM廃止)**。TCN 3→**5seed**、L5 も **5seed** に拡張。

## 手法の概要
### PF強化(step1) = robust側パラメータ【だけ】を調整
- **base PFパラメータは現状のまま(正しい)を固定**し、**robust側 ν(`robust_nu`)/β(`temper_beta`) のみ**を調整する
  (過去 tune_v94 は base を弄るので不適 → v98に専用チューナ `tune_robust_levers_v98.py` を新規作成)。
- 評価は create と同一経路(pf_banks_v95.run_smoother_ext)を **普通のPF=lagなし(smooth_lag=0)** で回し、
  tw表現の overall RMSE(全井プール)最小化。**n_seeds=32・ランダムseed**(ぶれ対策)。
- **適用済みの値だけを試す最小グリッド**(細かい探索は不要・過学習回避): stage1 ν∈{0,5}(β=1) →
  stage2 ν*=5なら β∈{1.0,0.85}。**精度改善するバンクだけ採用**(baselineが勝てば強化なし=自己選択)。
  バンク毎に (ν*,β*) を pf_banks_config(v95) へ焼く(base不変)。ν5/β0.85=v97実績の適用値。
- v97側は既存の適用値(pf_1=ν5β0.85 / pf_2-4=ν5)を維持。両config smooth_lag=192。

### create(step3) — combo を 3系統生成
各系統で **v95 create + v97 create → id順hstack** で combo parquet 化(既存 build_combo_parquet 流用)。
- **通常(順)**: 実trainそのまま → `train_combo.parquet`(学習+検証に使用)。
- **逆DA**: 反転CSV → `train_aug_bwd_combo.parquet`(`is_backward=1`)。
- **順DA**: 中点開始CSV → `train_aug_fwd_combo.parquet`(`is_fwdaug=1`)。
- DA系統の錨は full-FOLD_ART アンサンブル(train専用・検証されないのでOOF不要)。lag192・chunk20。

### train(step4) — TCN + L5 を 5seed
- 学習データ = 通常combo(該当foldのtrain側) **＋ 双方向DA(該当foldのtrain側のみ)**。
- **検証/OOF = 通常(順方向)のみ**。DAは絶対にvalidationへ入れない。
- **GroupKFold は井戸単位**。DA井は元井と同じfoldの train側に配属(元井がvalの回はDAも除外)=リークなし。
- TCN 5seed / L5 5seed。書込中parquetの混入防止(サイズ安定＋pyarrowマジック検証)。

### submit(step6)
- Kaggle ノートブック `submit_v98.ipynb`(全コード%%writefile直書き)。持出しは **artifacts_v98 相当フォルダのみ**。
- test時: FOLD_ART錨ロード(GRU再学習なし) → v95/v97 PF(強化・lag192) を **2×T4マルチGPU**(`PF_NGPU`自動) →
  combo hstack → TCN(5seed×5fold) + L5(5seed×5fold) blend。DAはtest推論には無関係(学習時のみ)。

## データ配置
- `artifacts_v98/data/train_combo.parquet` — 通常(順), 全fold(train+val用)。
- `artifacts_v98/data/train_aug_bwd_combo.parquet` — 逆DA(train側専用, `is_backward=1`)。
- `artifacts_v98/data/train_aug_fwd_combo.parquet` — 順DA(train側専用, `is_fwdaug=1`)。
- 3ファイルとも同一列スキーマ(combo)。DAは元井 `well` を保持しfold整合。

## 結果
- **PF強化(robust tune, 全井n_seed32, lag0)**: 改善バンクのみ採用(自己選択)。
  - pf_1=baseline / pf_2=baseline / **pf_3=ν5β0.85(−0.32) / r0_seed32=ν5(−0.37) / r1_seed32=ν5β0.85(−0.15) / pfA=ν5(−0.03)**
  - ★小規模スモーク(6井n_seed8)ではpf_2が−3.86等と出たが全井n_seed32で消滅=「ぶれ」。n_seed32必須を実証([[pf-robust-likelihood]]更新)。
  - v97側は既存適用値(pf_1=ν5β0.85 / pf_2-4=ν5)を維持。
