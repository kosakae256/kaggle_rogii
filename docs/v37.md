| RUN | 種別 | 設計意図 |

- 候補27本・チャネル7ch・META13次元は f_runmean と完全同一(C1/C2は v34 と同じコード)。
- 固定fold = `v34/artifacts_v34/ranker_folds.json` を共有。

  **e2e型(g_e2e/h_row)はモデル自前の集約をそのまま評価**(グリッド選択なし=楽観が乗らない)。
- foldチェックポイント `v37/artifacts_v37/v37_{RUN}_f*.npz`(スコア型は q、e2e型は est を保存)。

## 実装上の注意(しっかりポイント)
- **候補軌跡の散発NaNは cons で埋める**(nan_to_num の0埋めだと「TVT=0ft」の壊滅候補が生まれ、
  e2e系が拾うと事故る)。
- 候補のオフセット順ソートは全プリセット共通(スコア型には無害、j_img には必須の局所性)。
- e2e損失は井戸等重み(pooled指標は行重み)— 学習と評価の重みが僅かに違うが影響は二次的。
- EPOCHS=20 共通。g_e2e/h_row は最適化が難しめなので、lossが下がり続けていたら30に伸ばして良い
  (fold checkpointを消してから)。

## ディープリサーチ(2026-07-07, Sonnetワークフロー13エージェント・検証付き)
**問い**: 候補軌跡集合の学習型選択・集約のベストプラクティス。5角度(combination puzzle / MBR・N-best /
IMM追跡理論 / motion forecasting候補スコアリング / Kaggle実戦)。要点:
1. **g_e2eの失敗は文献的に既知の現象**: forecast combination puzzle(候補が相関・性能差小のとき
   重み推定分散がバイアス低減を上回る)+ NMT文献の "metric overfitting"(集約指標の直接最適化が
   人手評価を悪化させる実証)+ 2段階推定の検定力喪失定理。**e2e路線は撤退が理論的にも正当**。
- **処方箋の実測**: prune→consensus(peLASSO/2段構成型)=✗(best M=4 6.780 < softmax 6.7485に届かず)。
  **等重みshrinkage=✓: w=0.9·softmax+0.1·等重み → 6.7346(−0.014, λ0.8-0.9プラトー)→ 提出ルールに採用**
  (export/submitに反映済)。分散適応shrinkage=✗(一律で十分)。
2. **行レベル重みの正しい形はIMM/HMM構造**(追跡理論): 自由な学習行重み(h_row)でなく、
   truth-freeな行別尤度(GR残差)×粘着Markov遷移のforward-backward。→ **m_immプリセット追加**
   (学習なし・パラメータはp_stay×温度の9点粗グリッドのみ)。Indoor優勝の離散joint探索とも同型。
3. 候補スコアリングhead(独立エンコード+softな距離ラベル)は**業界標準そのもの**(TNT等)=base_klの設計は妥当。
   set-attentionの効果は文献でも小(HPNet 2-3%)→ k_attnは低期待で確認のみ。hard WTAは文献でも一貫して劣る。
4. 候補プール前処理の提言(未実施): 近接重複のNMS間引き(EDA)/発散候補の品質フロアゲート(品質保証つき
   生成が集約の前提条件)/特徴・候補選択は精度順でなく**多様性優先**(MIRAのモデル選択実証)。
5. Kaggle実戦: M5勝者=等重み+**メンバーシップ選択をmean+fold分散の両方で**判定/構造的平均
   (同一モデルのseed平均=ランカー自体の3seed平均は未試行の安定化レバー)。
- 検証段が落とした出典エラー(著者名・節番号・用語)は記録済み — 「M4で単純平均が常に学習型に勝つ」は
  過大一般化として**反証された**(M4優勝はハイブリッド単一モデル)点に注意。

## 結果(2026-07-07 進行中)
- **g_e2e: ★正味の効きなし(ユーザー判定)**。fold0は 6.045 vs KL 6.406 と大勝に見えたが、
  他foldで逆転し合計はf_runmean(6.7485)と同等以下。
  **解釈: e2eの「打ち消し混合」はtrain井戸のフィールド固有パターンで、未見井戸に汎化しない。**
  KLの順位学習が保守的ゆえに強かった(bias-variance)。fold単位の勝ちを信じない教訓の再確認。
- 対応: **g2_hyb(e2e + 0.3·KL の折衷)** をプリセット追加(2026-07-07)。順位錨で分散を抑えて
  混合の自由度だけ残す最後の確認。これがダメなら e2e系(h_row含む)は撤退し、
  i_pair / j_img / k_attn(KL系)へ。
- 注意: h_row は e2e損失前提なので、g2_hyb の結果を見てから(ダメなら h_row も hyb損失に変えて1回だけ)。
