## 狙い / 仕様（ユーザー指示）
- **特徴量 = v20相当**（v9 build_well: pf_ancc/pf_z/beam/formation/NCC/GR統計…）を **smooth PF** で生成。
  - v20は物理ゲートPFバンクだが、v28は **v25 r0 単一 smooth PF**（=LB6.786の r0）を tw grid で注入。
- **★v27の self / neighbor を特徴として追加**（混ぜない・単に実行した出力。※self/neighbor は v27由来、smooth PFエンジンとr0パラメータは v25由来）。出力だけでなく **std・tw不一致・一致度・近傍メタまで**足す:
  - self（自分の既知prefix GR(TVT_input) を疑似typewell化した grid の smooth PF）:
    `pf_self`, `pf_self_std`, `pf_self_delta`(−lk), `pf_self_vs_tw`(−pf_ancc), `pf_self_vs_nbr`。
  - neighbor（XY近傍train坑井のGR を疑似typewell化した grid の smooth PF。**近傍<2本(MAX_DIST1500,NEED_REFS2)は通常実行=tw にフォールバック**）:
    `pf_nbr`, `pf_nbr_std`, `pf_nbr_delta`, `pf_nbr_vs_tw`, ＋近傍メタ `pf_nbr_has`(実際に近傍使用=0はfallback)/`pf_nbr_nndist`(最近傍距離=信頼度)/`pf_nbr_nrefs`(本数)。
  - 3PF一致度: `pf_agree_std`, `pf_agree_range`（tw/self/nbr の食い違い=不確実性proxy）。
  - **★最有力信号 = `pf_self_vs_tw` / `pf_nbr_vs_tw`**（baseline tw からのズレ→GBMが「どこで self/nbr を信じるか」を学べる）。
- **★Z傾斜 `z_grad`**（dZ/dMD の移動平均, 半径ZGRAD_R=25。断層影響を避けるため移動平均）。self は傾斜で精度が変わるための補助。

## create の構成（`build_dataset_v28`）
1. **tw smooth PF**（r0）→ `run_pf_ancc` に monkeypatch 注入 → v9 build_well が v20相当特徴を生成。
2. **self smooth PF**（`build_inputs_self`: gg の prefix帯を自分prefixで置換, MIX_W=1.0）→ `_SELF_ENS[wid]`。
3. **neighbor smooth PF**（`build_inputs_nbr`: gg のカバー帯を近傍trainで置換。refs無し=tw）→ `_NBR_ENS[wid]`。
   近傍は `neighbors_of`（train重心 XY, MAX_DIST1500, K5, ≥2本, train時は自分除外）。
4. **Z傾斜** `z_gradient_eval`（np.gradient(Z,MD)→移動平均→eval行）→ `_ZGRAD[wid]`。
5. `one()` で build_well df に self/nbr の **出力+std+delta+tw不一致+一致度+近傍メタ**（上記全列）＋ `z_grad` を列追加（eval行順で整列）。`_SELF_ENS/_NBR_ENS` は dict(mean,std) を保持、`_NBR_META[wid]`=has/nn/nref。

## ★★2エンジン: smooth PF + FFBSi(FFBSm)（2026-07 追加）
- **smooth PF(`sm_*`) と FFBSi(`fb_*`) の2エンジンで、tw/self/nbr × pf_1/2/3 を各々実行 = 計18回**。生成特徴は両エンジン対称（同じ種類）。
- **FFBSi** = v25 tune_ffbsi_r0 の `ffbs_forward_well`＋`ffbsm_backward_well` を inline（前向きPF雲→FFBSm後ろ向き平滑, seed尤度加重, CLAMPでforward復帰）。設定: forward=pf_1/2/3, `FFBSI_INFLATE=32`, `FFBSI_N_BWD=128`, `FFBSI_CLAMP_FT=60.0`。入力は smooth と同じ `build_smoother_inputs`。
- **build_well を engine毎に2回**走らせ、**値が異なる列(=PF注入由来)を `sm_`/`fb_` タグ、同一列(非PF=beam/NCC/formation/GR統計/pf_z)は共有**（差分検出。per-well seed で決定性を担保）。self/nbr は `one()` で両engine分を直接生成。`pf_ancc` は apply_pp 用アンカーとして sm(無ければ先頭engine)の別名を残置。
- **学習/推論の採否トグル**: train の `USE_ORIGIN` に **`sm`/`fb`** 追加（`origin_of`: `sm_*`→sm, `fb_*`→fb）。→ **smooth単独 / FFBSi単独 / 両方 を A/B可能**（例: FFBSi単独=`{"sm":False,"fb":True}`)。submit は features.json で自動選択（生成は両engine=superset）。
- 実装: `create_train_parquet_v28.py` を直接パッチ（builder再生成なし, scratchpad/patch_ffbsi_create*.py）。submit_v28/graft はエンジン再埋め込み。**注意**: (a)実行が重い(18 PF + build_well×2)、(b)非PFの確率的特徴が万一あると差分検出で誤って二重化しうる→**生成後に sm_/fb_ 列数を確認**推奨。

## ★PF は pf_1/2/3 の3セット × tw/self/nbr = 計9回（2026-07 変更, ※上の2エンジン化で各engine内の話に）
- **tw / self / nbr すべて `PF_BANK=["pf_1","pf_2","pf_3"]` の3パラメータで smooth PF を回す（＝9回）。** 各 param 別に特徴を出す。
  - self: `pf_self{suf}`/`pf_self_std{suf}`/`pf_self_delta{suf}`/`pf_self_vs_tw{suf}`(=−pf_ancc{suf})/`pf_self_vs_nbr{suf}`（suf="", "_2", "_3"）。
  - nbr: `pf_nbr{suf}`/`pf_nbr_std{suf}`/`pf_nbr_delta{suf}`/`pf_nbr_vs_tw{suf}`。
  - 一致度: `pf_agree_std{suf}`/`pf_agree_range{suf}`（tw/self/nbr の各param不一致）。
  - **param間集約**: `pf_self_mean`/`pf_self_pstd`/`pf_self_mean_vs_tw`、`pf_nbr_mean`/`pf_nbr_pstd`/`pf_nbr_mean_vs_tw`。
  - 近傍メタ(param非依存)は1組: `pf_nbr_has`/`pf_nbr_nndist`/`pf_nbr_nrefs`、`z_grad`。
    - **★`pf_nbr_nndist`=最近傍train坑井までの実距離(上限なし, `_nearest_dist`)**。MAX_DISTで打ち切らず、**フォールバック坑井でも実数(孤立度)を返す**（①案）→ sentinel/NaN不要。`pf_nbr_has`(0/1)がneighbor PF実使用を別途担う。
- **バグ修正(同時)**: (a) tw ループが `Praw`(=pf_1固定)を使い pf_ancc/_2/_3 が同一になっていた → `p["_raw"]` で param別に。(b) `z_grad = col(_ZGRAD)`(辞書を配列colへ渡し KeyError) → `col(_ZGRAD.get(w))`。
- `_SELF_ENS/_NBR_ENS/_FWD_ENS` は `(wid, pf名)` キー。近傍探索は param非依存で1回、PF実行のみ param別。

## 結果 / 所感（LB 実測）
- **★v28 GBM（tabular）単体 = LB 6.026 = 大幅新ベスト（前ベスト v27 6.697 を −0.671 更新）。**
  - **決定打 = self/neighbor を"混ぜる"のでなく"GBM特徴"にしたこと。** v27 では self を heuristic 出力ブレンドに足すと有害だった（6.697→6.823, hold/pp と二重計上）が、**特徴にすれば GBM が自動で重み付け**して大勝。pf_1/2/3 各々の self/nbr（計9回）＋ `pf_self_vs_tw`/`pf_agree*`/`nndist`(孤立度)/`z_grad` が効いたと見られる。
  - **graft（本気: 0.3v28 + 0.7v27heur + 射影/gold）= 6.191 で v28単体に負け（+0.165）。** ＝ **v28 GBM が heuristic を上回ったので、0.7 で heuristic を混ぜると劣る側に引っ張られる**。凝った下流(射影/gold)も純 v28 には及ばず。
  - v27 self+beam/hold/pp = 6.856（self系はヒューリスティック内では単独でも baseline6.786 より悪い）。
- **現状の最適 = v28 GBM 単体（submit_v28.ipynb, 6.026）。** 次の一手候補: (a) graft の heuristic 比を下げる/外す、(b) **"生・多様"な信号を GBM特徴に追加**（近傍の不一致度/GRマッチ品質/別PF/粒子分散など。CV が信用できるので回しやすい）、(c) v28 の特徴/モデル深掘り。
  - **★heuristic 予測のスタッキングは不可**: v24 で heur/beam/gsf を GBM特徴にして 8.026（v20 7.012 より悪化）＝**仕上げ済み予測は冗長＋過学習で落ちる**。self/nbr PF が効いたのは"生の別視点の推定値"だったから。**足すのは生の多様な信号のみ**。過学習注意（[[overfit-policy]]）。
