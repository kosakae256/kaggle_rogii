# v32 — 硬い核(全PF>10, per-well Optunaでも救えない52井戸)の原因解剖

> **状態: 診断ノート実装済(未実行)。** ファイル: `v32/diagnose_hardcore_v32.ipynb`(生成: scratchpad/build_v32.py)。
> 対象 = v19 _re カスケード終了時点の未解決52井戸(`artifacts_v19_32seeds_re/state.json`)。**新規計算なし**
> (refs_cache / datum_scan / unsup_meta / v30 preds_signone / OOFブレンド = 全部既存アーティファクト)。

## 目的
5つの PF パラメータ+per-well Optuna でも RMSE>10 のまま残る井戸が**なぜ**外れるのかをラベル付けする。
「PF のパラメータで救えるか / 原理的に無理(双峰・tw不適合)か / 別の入力が要るか」の切り分けが v32 以降の設計指針になる。

## 検証する仮説と測定量
| # | 仮説 | 測定量 |
|---|---|---|
| ① | 双峰datumの裏モードcommit | 誤差のバイアス寄与率 mean(e)²/mse、バイアスの±分布、NCC第2峰が真に近いか |
| ② | 断層/急なdip折れ | 真 geo_z=TVT+Z の最大ジャンプ、rolling dip の std |
| ③ | typewell表現力不足 | **oracle適合 r_true = corr(観測GR, typewell(真位置))** — 真に置いても合わない井戸 |
| ④ | typewellレンジ外逸脱 | 真TVTがtypewellカーブ実在範囲の外に出る行割合(PFは原理的に追えない) |
| ⑤ | 幾何 | 評価ゾーン長 / 既知帯行数 / 真ドリフト量 |
| ⑥ | 孤立 | 最近傍井距離 / typewellファミリー所属 |

## ノート構成(全部グラフ)
1. hard vs rest の誤差の形(バイアス寄与率・バイアス±分布・blend per-well RMSE)+ hard上位8井戸の軌跡
2. ②〜⑥の hard vs rest 分布比較(2×4ヒストグリッド)+中央値表
3. **ルールベース原因ラベル**(④tw範囲外 / ③tw不適合 / ②断層 / ①バイアス=裏モード疑い / dip暴れ / その他)
   → 集計バーチャート + `artifacts_v32/hardcore_diag.csv` + 井戸別ラベル一覧
4. **deep-dive セル**: `WELL = "..."` を書き換えて1本を系列で解剖 —
   軌跡(true/blend/smoother + twレンジ線) / 真geo_z(折れ確認) / **GR系列: 観測 vs typewell(真位置) vs typewell(予測位置)** /
   oracle適合散布図 / NCC走査(峰と真datum) / 誤差系列(一定=バイアス, 増加=dip)

## 結果(2026-07-06 実行済)
- ラベル集計(52本, 重複あり): その他/複合28 / **①バイアス(裏モード疑い)16** / ②dip暴れ7 / ③tw不適合5 / **④tw範囲外=0(仮説死)** / ②断層=ほぼ無し。
- **blend(GBM×NN)が52本中23本を既に救済** → 真の残存核 = **29本**。うち **27本が|bias|>8(符号+13/−14の対称)** = 裏バンドルcommit。
  峰間median 28ft ≈ biasの大きさ(10-25ft)と一致。孤立ではない(29本中18本は近傍<800ft)。
- **参照3本(tw/self/nbr)のバイアス突合(27本)**:
  - **(1)どれかの参照が正解側 ≈ 9-10本**(nbr当て4-5: 708caea9/b32902c0/48c1f673/8612b37f等、self当て4-5: b8c49c1a/efe96181/c1708b88/43b06c70等)
    → **答えは特徴の中に既にあるが per-well の選択ができていない**。
  - **(2)全参照が同じ裏側 ≈ 17本**(e32da4ec/91db7070/4ed93db6等) → 手持ち情報から還元不能。hedgeのみ。
  - 86454a6f は bias −45 が全参照共通=バンドルずれでは説明不能の別種異常(deep-dive対象)。
- nbrカバレッジ 14/27(MAX_DIST=1500)→ 距離緩和で(1)群を広げる余地。

## vote-hedge(参照投票ゲート付きhedge)— OOF検証済・submit実装済
- ルール(真値不使用): `d_ref = mean(median(pf_nbr−blend)[nbr有効時], median(pf_self−blend))`、
  `6 <= |d_ref| <= 45` なら `out = blend + 0.4·d_ref`(井戸一律)。`v32/vote_hedge_v32.ipynb` で粗グリッド選択。
- **OOF: 6.8711 → 6.7960(Δ−0.075)**。gated 45井戸(改善23/悪化18)、**硬い核6本で合計−15.5 / 正常井戸の被害+4.2**。
  悪化筆頭 73348914 は「全参照が同じ裏側」型=原理的に防御不能。>10本数は72→71。
- **cl96(v30)との重ね掛けは加算的: hedge+0.3·cl96 = 6.7319(Δ−0.139)** — ただしユーザー判断で cl96 パスは submit に入れない。
- **`v32/submit_v32.ipynb`**(submit_v29b ベース): blend残差 → apply_pp → **hedge(gap6-45, λ0.4ハードコード)** → geo_robfit(USE_GEO=True) → SG。
  hedge入力は test_df の pf_self_mean/pf_nbr_mean/pf_nbr_has のみ=test完全再現。ルール保存= artifacts_v32/vote_hedge_rule.json。
- 注意: λ/gap は同一OOFで選択=軽い選択楽観。LBで確認。
- **★LB結果(2026-07-07): 6.153 = blend(5.969) から +0.184 の大幅悪化(hedge+geo_robfit込み)**。
  OOF −0.075(hedge)/−0.06(geo)が隠しtestで逆噴射。分解は不能だが hedge が主犯候補:
  疎な介入(train では45/633井戸)に大きな井戸一律シフトを掛ける方式は、隠しtest(~200井戸)で
  ゲート特徴(pf_self/nbr と blend の datum差)の分布がずれると誤爆し、tail 支配の overall を直撃する。
  **教訓: 井戸レベル定数シフト系の後処理は OOF で勝っても転移しない(v24 のスタッキング死と同族)。
  後処理は pp(+sg) のみに回帰(ユーザー判断)。** v33/v34 の学習ゲートを submit に載せる場合も
  この転移リスクを前提に設計する必要がある(soft/連続・小λ・保守的ゲート、または特徴として GBM/NN に還流)。

## 含意(対策の優先順)
1. **参照投票ゲート付き posterior-mean hedge**: tw/self/nbr の datum が割れた井戸だけモード間を投票加重で hedge
   (blind gateと違い「参照不一致」という物理的ゲートがある)。回収余地 ≈ 9本×15-30ft。
2. (2)群は当てにいかない(mdn2混合平均が既に部分対応)。
3. nbr の MAX_DIST 緩和(幾何転写は死だが GR照合経由の nbr は伸ばせる可能性)。

## 期待される使い方
- ①が多数 → posterior-mean/hedge 強化や nbr 証拠での解消(提案③)へ。
- ③④が多数 → **typewell 自体の差し替え/拡張**(self/nbr 疑似 typewell を tw の代わりに使う等)が正攻法になる。
- ②が多数 → jump 対応(PFのjump_prob/検出)や区分推定。
