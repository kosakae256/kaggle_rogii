# v45 — Segformer SDF-CNN に物理prior(struct)を注入(train/valid完結・実生行RMSE内蔵)

> **状態: struct第4ch注入 実装済・forward/データ整合を検証済(本学習は未)。** ユーザーが v45 に置いた
> `cnn-sdf-training-random90.ipynb`(Segformer MiT-B0 ベースの SDF-CNN, 90/10 ランダム分割, PF不使用)の
> train/valid を **v44 と同じ物理prior(struct)入り**に改修。PF は元から不使用(除外要件は自動的に充足)。

## 元notebookの正体(v44 との違い)
- backbone が **Segformer MiT-B0**(v44 は U-Net系)。画像 = `concat([t_gr1, h_gr1, history])` の **3ch**
  (typewell-GR / horizontal-GR / 既知履歴パス画像)を入力し、**SDF `(h_tvt−t_tvt)/40`**(clip±3)を回帰。
  ゼロ等値面 = 境界 = TVT。損失 = masked MSE。
- **単一窓で未来全帯をカバー**(H_STEP=48→H_S=12, H_F=704bin×12≈8448行)。**marching不要**(v44 の発散問題が無い)。
- **実生行 overall RMSE 評価が内蔵**(cell25 `calc_valid_actual_rmse`): 予測SDF→argmin行→t_seg_tvtでTVT復元→
  元CSVのfuture全行へ補間→ `np.sqrt(np.mean(err²))`。**コンペ指標(全行プール)に一致**。← v44 より honest。

## 物理prior注入(ユーザー依頼「今の物理prior入りでやるイメージ」)
- **struct-SDF を第4チャネルとして追加**。`history`(未来列を0にした既知パス画像)の**未来列を struct 予測で埋めた版**:
  - `tvt_prior`: `[0:H_H]`=既知履歴TVT(実測) / `[H_H:]`=**struct(v38 K16 dip場)予測**。
  - `struct_sdf = clip((tvt_prior[None,:] − t_seg_tvt[:,None]) / 40, −3, 3)`(=`sdf`ターゲットの prior 版, (T,H)=(256,768))。
  - struct整列: `struct_prior_train.pkl[well]["tvt"]`(eval生行, `h_ps+1`以降と1:1)を、`resample_horizontal_by_step`
    の after 側と同じ pad/truncate/mean(`_group_after_like`, group=H_S)で bin 化 → `h_tvt1` に整列。
  - struct 無い坑井は最終既知TVTで平坦外挿(中立prior)。
- モデル: `GeoSteerNet(in_ch=IN_CH)` で `num_channels=in_ch`。forward は `batch` に `struct_sdf` があれば concat。
  pretrained MiT-B0 は `ignore_mismatched_sizes=True` で4ch stem のみ再初期化・残りは事前学習重み。

## 評価: 5-fold GroupKFold OOF(他エンジンと同じ土俵)
- 初版は 90/10 ランダム分割で **fold 構成が他エンジン(5-fold)と不一致=横比較不可**だった。
  → **`GroupKFold(n_splits=5)` を坑井universe(773本)に張り、fold 選択式**に変更。
  全坑井がちょうど1回 valid に入る **pooled OOF は分割の細部にほぼ不変**なので、v39等のOOFと実質同じ土俵。
- **env `V45_FOLD=0..4` を切替えて 5 回実行** → 各 fold の実生行予測を `artifacts_v45/{tag}/oof/oof_fold{k}.parquet`
  に保存。全fold揃ったら**集約セル**が pooled OOF overall RMSE(CNN)と **struct単体**(同坑井)を並べて出す。
- struct単体セル(CNN無し・純prior)も追加: 同じ valid で純prior の overall RMSE を出し、**CNNがGRで上積みできたか**を判定。
  - 参考: 90/10 初版 fold での実測 = **struct単体 8.33 / CNN(struct注入) future 8.09**(−0.24=まだstruct寄り)。

## ablation / fold 切替(env)
- `V45_STRUCT=1`(既定): struct 第4ch ON(in_ch=4)。 `V45_STRUCT=0`: 従来 3ch baseline。
- `V45_FOLD=0..4`(既定0), `V45_NFOLDS=5`, `V45_BS`(batch, 既定8), `V45_OUT`(出力先)。
- 出力は自動分離: `v45/artifacts_v45/{struct,base}/fold{k}/`(best/last/log)+ `.../oof/oof_fold{k}.parquet`。上書き回避。

## 高速化・警告除去(2026-07-09)
- **float32 メモリキャッシュ**(SdfDataset): 1ep目で読んだサンプルを常駐 → 2ep目以降は CSV読込/savgol/cv2.line を
  全スキップ(I/O律速を解消)。train≈618本で ~2GB(RAM20GB内)。`num_workers=0` 前提。
- **BATCH_SIZE 2→8**(GPU稼働率↑)。`V45_BS` で調整可。
- 警告の根本除去: `torch.cuda.amp`→`torch.amp` 新API(autocast/GradScaler)、`resample_horizontal_by_step` の
  `h["GR_smooth"]=` 列挿入をやめ `np.column_stack` で直接行列化(DataFrame断片化 PerformanceWarning 消去＋高速)。
