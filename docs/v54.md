# v54 — 候補集合の学習集約(per-seed 軌跡の set aggregation)

> 状態: 設計(2026-07-12)。create 実装中 → ユーザー実行 → lab(fold0→5fold)。
> 本線決定: ユーザー「Aかな」(2026-07-12)。粒度は**後から変えられる**ことが要件。集約器の形は任意。

## 仮説
- v52(tabular GBM+TCN)は条件付き平均の近似としてほぼ完成しており、**datum両義行(全行13-20%=RMSE²の72%)で
  midpoint を出す宿命**は学習器の改良では破れない。
- 破る道は「条件付き分布を鋭くする情報」= **seed平均で殺している per-seed 票**(v33 ext_vote AUC0.82)。
- 候補集合 {z_s(t)} を行レベルで soft 加重する定式化(v34 モードゲート=LBで効いた唯一の選択系の正統進化、
  hengck23「top-k path query + 選択」と同型)なら、票が揃う行はコミット・割れる行はヘッジを**学習で**選べる。

## 変更点(v52 から)
- エンジン出力を「seed加重平均1本」→「**per-seed 軌跡候補の全dump**」に変更(create_candidates_v54)。
- 新レイヤ「集約器」を GBM/TCN の**前段**に追加(まず単体評価、次に v52 特徴化/ブレンド)。

## create(候補dump)仕様
- ソース: v51 `run_smoother` の `ps(S,T)`/`ww(S)` を潰さず保存(`run_paths` ラッパ追加。PFコア無改変)。
- 粒度(最粗・全部持つ): **6バンク(pf_1/2/3, r0, r1, pfA)× 3フレーバー(tw/nbr/self)× 32seed = 576候補/行**、
  per-row(bin化しない)、fp16。+ 各(バンク×フレーバー)の per-seed 尤度重み ww。
  - NN-emission: W=0.02(pfAのみ0.01+struct錨)、smooth lag16(v52と同一)→ **v52 の平均特徴と同じ土俵**。
  - 容量見積: ~3.4M行 × 576 × 2B ≈ 3.9GB(npz, key=`{well}|{bank}|{flav}` (S,T) / `…|w` (S,))。
- キャッシュ/再開: (バンク×フレーバー)ファイル単位 + **全坑井カバレッジ判定でskip**(v52/v53 の部分キャッシュ事故対策)。
- **整列規約(重要)**: 候補 (S,T) の T は **`hw[hw["TVT_input"].isna()]`(評価行)のみ・CSV順**
  (`build_smoother_inputs` が eval 行だけで PF を回すため)。lab/統合側は同じマスクで整列すること。
- スモーク済(2026-07-12): 3井×4seed×3flavで整列・重み・散布を検証(seed散布 1.8〜9.7ft=保持したい情報が実在)。
- **粒度の可変性(要件)**: dump は最粗で固定し、**lab 側の環境変数で自由に絞る**:
  `BANKS=` / `FLAVORS=` / `SEED_STRIDE=`(32→16/8本に間引き)/ `TOPK=`(ww上位k)/ `BINIZE=`(行→stride束ね)。

## lab(集約器)仕様
- 入力(行 t): 候補値 {z_s} を **struct基準のδに正規化**(δ_s = z_s − st(t))+ 候補メタ(バンクid/フレーバーid/ww)。
- プリセット2種(形はどちらでも可、の指示):
  - `hist`: δ格子(0.5ft×±45ft)への soft-binning ヒスト + 分散/票割れ統計 → 2層MLP → 格子重み → posterior-mean
    (v34 の全モード確率加重 posterior-mean の直系)。
  - `setattn`: 候補576トークン(値+メタ埋込)に 1-2層 set-attention、行方向は軽い1D conv 文脈 → 候補重み → 凸結合。
- 損失: 行数重み付き MSE(overall RMSE 直結)。fold: sorted[f::5]。**early stop / best val loss**(標準作法)。
- **過学習ガード(v34 ランカー逆噴射の前科)**: 集約器は浅く(パラメタ数を桁で絞る)。
  leave-field-out は単一メガフィールドで縮退するため、**XY空間ブロックCV を監査**として併用。
  fold間分散を必ず表で見る(採用基準: 分散が v52 並みに小さいこと — 2026-07-12 ユーザー棄却基準)。
- 判定: fold0 で当たりを見る → 5-fold 全体値 + fold分散 → v52 GBM(6.28)/blend(6.083)と比較。
  出口は (a) エンジンとして v52 特徴化(v28法則) (b) TCN とのブレンド脚。

## train(集約器)実装(2026-07-12)
- `v54/train_agg_v54.ipynb`(5セル): ①候補ロード(粒度ノブ: BANKS/FLAVORS/SEED_STRIDE=2/TOPK)+整列検証
  ②学習なし基準線(stream別ww平均/全候補平均/median を全井戸・foldで表示)
  ③AggNet=浅いset-attention(トークン=[dz,logww]+bank/flav埋込、行文脈=候補要約統計のdilated Conv1d、
    score→softmax(+log ww prior)→凸結合。平行移動不変設計)
  ④fold学習(early stop pat12 / best val loss / plateau LR / MAXMIN40 / まずFOLDS=0)→ agg_oof.npz / v54_results.json
- 学習時は行を ROWSTRIDE=4 で間引き(評価はフル行)。VRAM軽量(DIM32)。
- 判定: fold0 で基準線(best stream / ww平均)を超えるか → 5-fold + fold分散。
