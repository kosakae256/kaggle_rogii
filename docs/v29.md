# v29 — 系列モデル(per-well TCN+Attention) on v28特徴 × v28 GBM 残差ブレンド

> **状態: 実装済(未実行)。** ファイル: `v29/train_nn_v29.ipynb` / `v29/submit_v29.ipynb`(生成: scratchpad/build_v29.py)。
> create は不要(**v28 の `artifacts_v28/data/train.parquet` をそのまま入力**)。

## 仮説
- v28 GBM(LB 6.026 / OOF CV≈7.0)は**行単位の独立回帰**であり、「offsetは井戸内で一定・dipは区分線形」という
  **井戸レベルの軌跡構造**(誤差の bias57.6%+dip31%=約88%, pp_lab診断)を原理的に表現できない。
- 井戸全体を1系列として見る NN なら「上流で self/nbr/tw が一致している区間の情報で下流のoffsetを固定する」等の
  **井戸内文脈伝播**ができ、GBMと**系統の異なる誤差**を持つ → 出力ブレンドで改善(v10×v12 で −0.16 実証済の路線)。
- look-ahead は合法(whole-trace 可)なので **非因果(両側)受容野**を使う。

## 変更点(v28 から)
- モデルを追加: **per-well 系列 NN**(入力=v28特徴のGBM importance上位192列)。GBM側は v28 のまま(再学習不要)。
- 提出は **GBM残差 × NN残差 の重みブレンド**(w は OOF で探索し blend.json に保存)→ apply_pp → per-well SG。
  **geo_robfit は含めない**(LB6.026構成と同一チェーンにして NN 効果を切り分け)。

## 手法の概要
- **アーキ**: 1×1 conv 入力射影(192ch) → 非因果 dilated TCN 8ブロック(k=5, dilation 1..128, 受容野±510行,
  residual+ChanLN) → 自己注意1層(4head, 井戸全体の大域文脈=offset整合) → ヘッド。
- **ヘッド2種**(A/B兼アンサンブル):
  - `mse`: 1ch 回帰(プールMSE=overall RMSE と一致)。
  - `mdn2`: **2成分混合密度(μ1,μ2,p,σ1,σ2)** → 推論は混合平均 `p·μ1+(1−p)·μ2`。
    = error_anatomy §4「双峰datumはモードに賭けず posterior mean」の決定理論的最適をヘッドに実装(flip井hedge)。
- **ターゲット**: v28 と同じ残差 `target = TVT − last_known_tvt`(標準化して学習)。
- **fold**: v28 GBM と**完全同一**(行順のまま GroupKFold(5) by well)→ GBM OOF と NN OOF の正直なブレンド重み探索が可能。
- **前処理の工夫**:
  - **絶対TVTスケール列の自動残差化**: corr(f, lk)>0.98 の列(pf_ancc/pf_self/pf_nbr等の絶対値系)を `f − lk` に変換
    (NNは絶対座標を扱えないため。GBMは分割で吸収していた)。
  - robust scale(median/IQR)、NaN→中央値(スケール後0)、±8クリップ。
- **学習の工夫**: channel-dropout(Dropout1d 0.1)+入力ノイズ0.02+**井戸のランダムクロップ(1024行)**の3正則化 /
  **EMA(0.999)重みで検証・保存** / cosine+warmup / bf16 autocast / grad clip / **best-epoch スナップショット**(val pooled RMSE)。
- **アンサンブル**: 2ヘッド × 3seed × 5fold = 30モデル(1モデル約2M params、RTX5070で軽量)。
- **評価**: v28 と同じ OOF overall(apply_pp)。**基準 = v28 GBM の train OOF CV ≈ 7.0(真のCV)**。
- **ブレンド**: `(1−w)·GBM + w·NN` を w=0〜0.6 で走査(mse単独/mdn2単独/全部の3候補×w)、apply_pp後 overall と
  wells>10 を併記して best を `blend.json` に保存。submit はそれを読むだけ。

## 実行手順(ユーザー)

   gbm_oof.npy キャッシュ)が出来る。`.pt` があれば skip=再開可。

## 結果
- **CV(OOF apply_pp, 2026-07-06 実行済)**: GBM単体 7.0481 / NN mse 7.1957 / **NN mdn2 7.0346**(mseに全fold勝ち, wells>10 77→72) /
  **★blend(mdn2, w=0.52) = 6.9382(Δ−0.11)**。wカーブは滑らかな凸で内点最適 → ノイズでなく本物の多様性ゲインの形。
  mdn2>mse は「双峰は posterior mean で hedge」の実証。all(mse込み)6.954 は mdn2単独に負け → mse は廃止方向。
- **Public LB: TCN(mdn2)単体 = 6.158(2026-07-06)**。GBM 6.026 と同帯域 = **NNの転移確認**(CVの関係 7.035 vs 7.048 とも整合)。
- **★Public LB: TCN(combo)×GBM ブレンド(ppのみ) = 5.969(2026-07-06)** — 同条件の v28(6.026)から **−0.057**。
  NNブレンドの上乗せをLBで実証。CV差 −0.139 に対し転移 ~4割(減衰)。geo_robfit(5.96)とは独立レバー。
  次=submit_v32(blend+hedge+geo 全部入り)で 5.8台を狙う。

## 追加実験 v29b(`v29/train_nn_v29b.ipynb`, 2026-07-06 実装済・未実行)
TCN のさらなる改善を **1個ずつ** A/B する実験環境(生成: scratchpad/build_v29b.py, artifacts_v29b, mdn2のみ)。
`RUN` プリセットを書き換えて再実行 → `results.json` に蓄積・最終セルで比較表。fold/seed固定の paired 比較。
- **CROP=2048 は棄却(2026-07-06 実測)**: base2048 = 単体 7.0625(+0.03)・>10 79(+7)、blend 6.9412(同値)。
  クロップ augmentation が弱まる方向の微悪化 → **CROP=1024 に復帰**。記録は results.json の `base2048`。
- `base`: CROP1024 = **v29 本体と同一設定なので再学習せず v29 実測値(mdn2 7.0346 / blend 6.9382)を base として登録済み**
- `b_flip`: **反転augmentation+TTA**(非因果なので正順/逆順は対称。学習時p=0.5反転+推論は両方向平均)
- `d_prefix`: **既知ゾーン(prefix)条件付け** — train CSV から TVT_input 既知帯の末尾512行(GR/TVT_rel/Z_rel/MD_rel)を
  PrefixEnc(conv+masked mean/max pool)で井戸ベクトル化し TCN 入力に注入。offset/dip較正を既知帯から直接学ばせる
- `e_gbmch`: **GBM OOF予測を入力チャネルに**(NN=学習型コンバイナ化)。**注意: スタッキングリークでCVが甘く出る** → blend/LBで判断
- `combo`: 勝った要素だけ残して最終確認
- `m_mtp`: **MTP風の補助予測**(ユーザー案)。非因果モデルでは「未来を当てる」は自明化するため、
  **多スケール局所増分 `d_k(t)=y[t+k]−y[t]`(k=4/16/64)を補助ヘッドで予測**する形に翻訳(=dipのmulti-scale直接教師、誤差の31%へ)。
  flip=ON なので b_flip と paired 比較。MTP_OFFS/MTP_W(0.1) は cell1。
判定目安: base 比 −0.05 以上で採用。順番= base → b_flip → d_prefix → e_gbmch → combo。
※ v29b は実験専用。勝ち構成の submit 統合は別途(モデル定義が変わるため submit_v29 と非互換)。

## submit 統合(`v29/submit_v29b.ipynb`, 2026-07-06 実装済)
生成=scratchpad/build_submit_v29b.py。**構成は `artifacts_v29b/submit_pack.json` 駆動**(RUN名/cfg/w_nn/正規化/アーキ/prefix統計)。
- **export セル(train_nn_v29b 末尾, cell12)**: `EXPORT_RUN`(既定 "full") の構成を submit_pack.json に書き出し。
  prefix の GR 正規化統計(gmed/giqr)は train CSV から抽出時と同一手順で再計算して保存(未保存問題の解消)。
- **チェーン**: 9GBM平均残差 × NN残差( w_nn=OOF最適, `W_NN_OVERRIDE` で上書き可) → apply_pp → **geo_robfit(`USE_GEO=True`, LB−0.07実証)** → per-well SG。
- NN推論: test側 prefix 抽出(`test/{well}__horizontal_well.csv` の TVT_input既知帯 tail512, dropna) + **flip TTA**(正順/逆順平均) + mdn2混合平均。cfg のフラグで自動 on/off。
- 要 input: コンペデータ + rogii-v28-artifacts + **rogii-v29b-artifacts**(`nn/{run}_mdn2_s*_fold*.pt` + submit_pack.json)。
- 手順: ①`full` を学習(RUN="full") → ②export セル実行(pack作成) → ③submit_v29b を Kaggle で実行。
  full が combo に負けたら export セルの `EXPORT_RUN="combo"` にするだけで提出構成が切り替わる。

## 追加実験: U2Net backbone(`v29/train_u2net_v29.ipynb`, 2026-07-06 実装済・未実行)
公開 SCA-U2Net(CV9.55, DTW特徴入り→DTWはこのタスクで死亡確認済み)の**アーキだけ**を検証:
「我々の入力(v28特徴192+mdn2+同一fold)の上で U2Net は TCN に勝つか/多様性を足すか」。生成=scratchpad/build_u2net_v29.py。
- v29b とデータ/前処理/fold/ヘッド/学習ループ完全互換。backbone のみ RSUネストU(E1..E5/D4..D1, base64/mid16)+CAM/SAM+側枝deep supervision(SIDE_W=0.25)。
- 公開版との違い: 井戸全長系列(窓512でない)/BatchNorm→ChanLN(padding汚染回避)/mdn2。**flip=ON で b_flip と paired 比較=純粋な backbone 差**。
- 結果は同じ `artifacts_v29b/results.json` に RUN=`u2net` で合流。最終セルで **GBM+TCN(b_flip)+U2Net の3者ブレンド**探索(U2Netの多様性上乗せを直接測る)。mtp トグルも共通装備。
- **★結果: 見送り(2026-07-06)。** 学習途中の精度が明確に低くユーザー判断で打ち切り(実行構成は bs256/LR1e-4=推奨1e-3の1/10 だった点は留意)。
  backbone 置換路線はここで停止、TCN(v29b combo)に集中。公開SCA-U2Netの CV9.55 と合わせ「U構造は本タスクのNNで優位性なし」。
