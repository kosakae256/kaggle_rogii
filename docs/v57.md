# v57 — hard井戸専用の二段回収(検出 → モード事後平均)

> 発端: docs/hard_wells_v52.md の地図(rmse>10=59井がRMSE²の53%、うち38井は per-seed 候補内に正解)。
> ユーザー方針(2026-07-12):「そいつらにだけ対応できれば問題ない、それが相補性になる」。

## 仮説
- hard の主因 = ww平均が悪モードseedに壊される集約失敗(A型42井, |bias|med11.5)。
- **検出**(この井戸は割れている)は枝選択の0.6壁の対象外(v33のモード存在検出=AUC0.82)。
- **回収**は per-seed 票(独立サンプル)のモード分解 + 学習スコアラの soft 事後平均(v34勝ちレシピの hard特化)。
  夜間15cの票失敗は「18 stream平均=非独立投票者」だったため。per-seed はv33と同じ土俵。

## 方法(v57/hard_recover_v57.py)
1. 整列: parquet OOF(pp後残差)→ 井戸別 eval行CSV順の chain絶対値。
2. モード分解: 候補192本(6stream×32seed)の「chainからの井戸オフセット」を1-D gap分割(>3ft)で2-4モード化。
3. 井戸特徴(ラベル不要): spread/stream不一致/chain対候補乖離/nd/surf−chain差 等 → **hard検出器**(LGBM, GroupKFold OOF, ラベル=OOF rmse>10)。
4. モード特徴: 票率(全体/nbr/self別)/wwシェア/|offset|/surf側一致/chain一致 → **モードスコアラ**(LGBM, モード単位, ラベル=真値に最近のモード, 同fold学習)。
5. 回収: recovery(t)=Σ p_m·modemean_m(t)。最終 `pred' = (1−λ·P(hard))·chain + λ·P(hard)·recovery`(全soft, λ粗グリッド)。
6. 評価: OOF overall / fold分散 / hard・easy 内訳(easyを壊さないことが採用条件)。

## ガードレール
- 井戸レベル補正はsoft限定(v32 hardシフト非転移)。検出器・スコアラともGroupKFoldでOOF。
- 隠しtestはhard比率低 → 本レバーはCV/PB向け(北極星: tail殺し=CV5台+CV-LB収束)。

## 結果(2026-07-12, 3反復)
| 版 | 構成 | overall | hard内訳 | 判定 |
|---|---|---|---|---|
| v1 | モードのみ・sharp化²・全井戸学習 | 6.188(−0.059) | **hard med 12.5→14.0 悪化**(改善13/59) | 見かけの−0.06は「数本の大事故修正の二乗利得」が中位hardの悪化を隠しただけ |
| v2 | +chain第0モード | 6.458(+0.21) | 選択正答0.36(easy多数が"chain正解"でスコアラ崩壊) | 学習分布の罠 |
| v3 | 割れ井戸限定学習+log-odds softmax+マージンゲート | 6.834(+0.59) | hard med不変なのにpooled大悪化=**少数hardへの破滅的誤commit がmed/countに隠れる** | ゲート発動が「オフセット最大の井戸」に集中し damage 増幅 |

**結論: 井戸レベルの事後スイッチ(検出→モード選択)はこの浅い形では成立しない。**
- モード選択 OOF 正答 0.36-0.66 = 枝判別 ~0.6 壁の再確認(5系統目)。per-seed票でも「井戸レベル1回勝負」の形にすると壁に当たる。
- pooled/med/count の3点セットで見ないと「隠れ破滅」を見逃す(v1 の教訓)。
