# v24 — ヒューリスティック/beam/GSF 由来特徴を足した LightGBM(v20拡張)

> **狙い**: v20(PF点推定→GBM)は「PF点推定を増やすだけ=頭打ち(OOF≈8.0≈v9)」だった。
> そこへ **PF点推定"以外"の直交信号**(不確実性・多峰・別decoderのbeam・GSF)を GBM 特徴量として足し、
> v9/v20(LB 6.9〜7.0)超えを狙う。**平均は多峰wellで崩れる**([[v19-pf-bank-boosting]])ので、
> 混ぜ方は平均でなく **GBM に学習させる**(行ごとに非線形結合)。
> 最終更新: 2026-07-02 / 状態: 3ファイル実装済み(未実行)。`create→train→submit` の順で回す。

## 仮説
1. **選択(行ごとに正解PFを当てる)は死んでいる**(signal_compare全敗, GR尤度≠真値)。しかし **GBMをリグレッサ**として
   PF/beam/GSFの出力＋不確実性を食わせるのは別物で、これは v9(LB6.9)の実証済み路線。
2. **点推定の水増しは効かない**(v20: 7PF≈v9の3PF)。効くなら **直交信号**:
   - **不確実性**(PF posterior std / GSF成分spread / scale間spread / PF間disagreement) → GBMが「PFが迷う行」を割り引ける。
   - **多峰シグナル**(GSFの2位モード重み/gap, beam-vs-PF gap) → **双峰datum([[error-anatomy-ref]] worst10%=誤差40%)の硬い核を旗立て**。
   - **別decoder**(beam=PFと独立のDTW的探索)= PFと直交。
3. これらは v9 の点推定特徴と相関が低い見込み → 足すと OOF が動く可能性。

## 変更点(v20 から)
- **PFセット**を `v24/pf_parameter.py` の `PF_LIB`(決定済み: r0〜r4, r0_seed32, un, pf_1, pf_3)に。**n_seed=128**。
  - もともとの v20 PF特徴も **n_seed=128 で再生成**(v20は32)。
- **beam / GSF / heuristic 由来の特徴を追加**。`v24/gsf_parameter.py` の `GSF_LIB`(round0/4/7)。
- **1回の生成で全特徴**(pf/heur/beam/gsf)を作る(2回生成しない)。PFは共有なので1回走らせて pf特徴と heur特徴の両方に使う。
- **特徴を"由来(origin)"で学習時トグル可能に**(生成は全部、学習で取捨)。命名規則で実現(下記)。

## ★命名規則(origin で学習時トグル)
全特徴に **接頭辞で由来**を付け、学習時に prefix でグループON/OFF:
| origin | prefix | 中身 |
|---|---|---|
| base | (v9既存名, 無接頭) | 幾何/GR/last_known_tvt/md_since 等(常時ONが既定) |
| pf | `pf_` | 各PFの点推定(pf_ancc相当, 残差)・posterior std・PF間統計 |
| heur | `heur_` | scale分布(pf_scale_X), scale間spread, hold/anchor乖離, ヒューリスティック最終予測 等 |
| beam | `beam_` | beam予測(残差), beam-vs-PF gap, beam config分散 |
| gsf | `gsf_` | GSF posterior mean(残差), 成分spread(多峰), 2位モード情報 |

学習ノートで `USE_ORIGIN = {"base":True,"pf":True,"heur":True,"beam":True,"gsf":True}` → 有効originの列だけ採用。
→ 「pfだけ」「pf+gsf」「全部」等を**列選択だけで**切替。実装が楽なよう prefix を厳守。

## 手法概要(3ファイル構成)
### 1. 特徴生成 `v24/create_train_parquet_v24.py`(→ train.parquet)
- v20 の枠組み(v9 `build_well` で base特徴 + GPU物理PF注入)を流用。**PFは PF_LIB 全部・n_seed=128**。
- **1パスで各坑井について**: PF(全セット, 多scale・std) + beam(7.191移植) + GSF(GSF_LIB) を回し、origin命名で全列出力。
- 具体的 origin別特徴(案):
  - **pf**: `pf_ancc_{name}`(= pf_ancc − last_known_tvt の残差), `pf_std_{name}`(posterior std),
    `pf_disagree`(PF間の予測分散), `pf_mean_all`(全PF平均, 参考)。
  - **heur**: `heur_scale{s}_{name}`(各PFの pf_scale_X 残差), `heur_scalespread_{name}`(sharp−soft差=不確実性),
    `heur_pred`(カテゴリ別best scale+hold+apply_pp のヒューリスティック最終, 残差), `heur_holddiff`(hold前後差)。
  - **beam**: `beam_pred`(beam ensemble mean 残差), `beam_gap_{name}`(beam − pf), `beam_spread`(config間分散)。
  - **gsf**: `gsf_pred_{name}`(posterior mean 残差), `gsf_std_{name}`(成分spread=多峰度), `gsf_gap_pf`(gsf − pf)。
  - **base**(v9): 既存の幾何/GR/last_known_tvt/md_since/spatial 等。
- 出力: `v24/artifacts_v24/data/train.parquet`(全特徴 + target=TVT−last_known_tvt + id/well/md_since 等の補助列)。
- test も同じ関数で生成(submit から呼ぶ)。**train限定列(ANCC〜/TVT)に推論時依存しない**。

### 2. 学習 `v24/train_models_v24.ipynb`(LightGBM ×fold, 任意でCat/XGB)
- `USE_ORIGIN` で列選択 → LightGBM(v20と同じfold構成/target)。**apply_pp(+sg_smooth)** で後処理。
- OOF overall RMSE を origin組合せごとに比較(どの由来が効くか)。
- 出力: models/, features.json(採用列), pp_params.json。

### 3. 推論 `v24/submit_v24.ipynb`(Kaggle, 自己完結)
- test を `create` と同一関数で1パス生成 → 学習済みモデルで予測 → apply_pp → submission.csv。
- models フォルダのみ持ち込み(v20submitと同方針)。**n_seed=128**。

## 実装メモ / 注意
- **メモリ**: PFは坑井チャンク×n_seed128 でGPU。beam/GSFはCPU(numba/小バッチ)。PFは1本ずつ順次で GPUピーク一定。
- **過学習の轍**: PFを坑井別にフルチューニングは死に筋([[v19-pf-bank-boosting]] LB実証)。v24は **単一〜少数の頑健PF出力を GBM特徴**に、が方針。origin トグルで「効く由来」を CV で見極める。
- **期待と現実**: 点推定水増しは頭打ち。**gsf_std / beam_gap / scale spread など不確実性・多峰・別decoder が本命**。効かなければ「GR尤度≠真値」の壁の再確認。
