# v19

> **反復ブースティングPFチューナー(物理モデル版・自動・再開可能)**。
> 「壊滅(RMSE>10)坑井を残差ブースティングで潰し、複数のPFパラメータを自動で得る」。
> 最終更新: 2026-06-30

## 仮説 / 狙い
- 1本のPFパラメータでは全坑井に対応できない(あるPFで壊滅する坑井が残る)が、
  **壊滅坑井に再チューニングを繰り返す**と、見えてる坑井は“どれかのPF”が対応可能になる(ユーザー観測: PF追加でCV/LB改善、4本目で頭打ち)。
- v19 はその **PFバンク生成を自動化**。得た複数PFは後段(GBM特徴 or v18セレクタの候補)で使う。

## アルゴリズム
- **Round 0**: 物理PFを Optuna で `N_TRIALS=200` 探索(全well対象, overall RMSE最小化)→ 最良パラメータ。
- **Round r≥1**: 直前ラウンドの最良で全well推論 → per-well RMSE の**ワースト `WORST_K=200`** well を対象に、
  もう一度 Optuna 200探索 → その(対象wellでの)最良を採用。
- `N_ROUNDS=10` 回くり返し、各ラウンドの最良 = **PFバンク**。

## 物理PF(ベース = pf_tuning_gpu_phys)
- GPU forward PF(ancc, `n_seeds=8`)。状態 pos=TVT+Z, rate=dip。
- **物理尤度** `lk_phys = exp(-0.5*((rate − dip_prior)/phys_sig)^2)`、`dip_prior`=既知ゾーン回帰(リーク無)。
  `phys_sig` も Optuna で探索(大=拘束ほぼ無)。
- 探索空間は v9/pf_tuning より**広め**(init_pos_std〜2.5, gr_sig広め, jump有, resamp広め 等=壊滅対策の保守ノブを広く)。

## 再開可能性(要件)
- **Optuna は SQLite ストレージ**(`artifacts_v19/optuna.db`, study=`round{r}`, `load_if_exists`)→ trial 単位で再開。
- **ラウンド進捗は `artifacts_v19/state.json`**(完了ラウンドはスキップ)。各ラウンドの best_params/overall/worst/per-well RMSE を保存。
- **`artifacts_v19/pf_bank.json`**: 各ラウンドの最良パラメータと overall(all) を一覧(後段で読む用)。
- 1回起動で `N_ROUNDS` まで自動。途中で止めても再実行で続きから。

## ファイル
- [v19/iterative_pf_boost_v19.py](../v19/iterative_pf_boost_v19.py) … 本体(自己完結, 物理PFを内包)。
  - 実行: `rogii_claude/.venv/Scripts/python.exe v19/iterative_pf_boost_v19.py`
  - 設定: 先頭 CONFIG(`N_TRIALS, N_ROUNDS, WORST_K, N_SEEDS, WELL_CHUNK` 等)。

## 注意 / 既知の論点
- **過学習**: 各ラウンドは対象wellの overall RMSE を最小化する(in-sample)。見えてる坑井への過学習に注意。
  本番(隠しtest)転移は LB で確認。必要なら対象選定/評価を OOF(typewellグループ hold-out)に変更。
- **per-set oracle / シードまぐれ**: 得たPFバンクの価値は「選択器が活かせるか」次第([[v18-particle-selector]] の知見: 正解候補は consensus から離れた少数派, oracle にシードまぐれ混入)。
- 次段: PFバンクを v18 候補に合流 or GBM特徴に。各ラウンド追加の**限界LB/相関**を見て冗長なら捨てる。

## 結果
- **4本バンク(round0-3, seed 0/1000/2000/3000)のカバレッジ確認(`check_bank_oracle.py`, EVAL n=32, 2026-06-30):**
  - 各PF単体 overall ≈ 9.24〜9.48(>10 well数 141〜182)。
  - **4本 oracle(各wellで最良PF) overall = 6.510** ← **v9 LB 6.946 を下回る**。
  - 貪欲追加: 1本9.29 → 2本7.40 → 3本6.91 → 4本6.51。**>10 が 141→101→81→72 と減り続け＝まだ頭打ちでない**。
  - カバレッジ(oracle): rmse<3=28%, <5=60%, <7=78%, <10=91%。**未カバー(>=10)=72本**(最悪 91db7070=36.5, b8c49c1a=30.6…)。
- **パラメータ多様性は本物**(PF間正規化距離 5.3〜8.2, 近接重複なし)。分散軸=likelihood_scale/rate_clip/pn/rp/init/smooth/jump。固定軸=mom≈1, gr_sig_max/mult, resamp≈0.05。
  - **phys_sig は全PFで弱(2〜4)=物理ほぼOFF**。Optunaの判断は「物理OFFが良い」。
- 含意: **多様性は“使える”(別の坑井をカバー)。選択さえできれば4本で v9 超え**。続ければまだ伸びる。
  この oracle(6.51, 4 PF多様性)は v18 の 4.62(96=3×32シードでまぐれ込み)より**到達しやすい目標**。 [[v18-particle-selector]]
- 未解決: 未カバー72本(GR信号薄/構造ブレ?)。機構違いPF(窓NCC尤度/逆向き)or フォールバックが要る。
- **v9の3本(pf_1/2/3, 物理OFF)も加えた7本(`INCLUDE_V9=True`)**: oracle **6.510→5.761**, 壊滅(>10) **72→46**。
  - 貪欲順は v9とv19が交互(v9_pf3→v9_pf2→r2→r1→v9_pf1→r0→r3)=**両系統が相補**(別の坑井を救う)。
  - パラメータ空間では v9群とv19群は**重なっている**(群重心間距離3.58 < 群内平均5.3/6.1)。
    → **パラメータが似ていても被覆は別**(多峰wellは僅差＋物理ON/OFF＋seedでロック先が変わる)。**v9もバンクに入れる価値あり**。
  - 残る壊滅46本が中核(7本でも頭打ち気味)→ 機構違いPF/別生成器/フォールバックが要る。
- 注意: oracleは n_seed=32・in-sample・選択完璧の天井。**32はseed脆弱**(n_seed↑で悪化する=8という規模に適合)、実際は選択がボトルネック。LBで要確認。
- 次段: PFバンク(v19+v9)→ median床→ v18セレクタ(観測特徴ルーティング)。最終 LB: TBD(目標 v9 6.946 超え)。

## v19-aug ― 構造prior機構3種を追加した派生チューナー(2026-07-03)
> PFの「中身(アルゴリズム)は変えず、**特殊粒子/提案項を足す**」方針(jump粒子と同じ発想)。
> 診断済みの失敗モードに効き、かつ **GPUで異様に遅くならない=全部 elementwise** の機構だけ採用。
> ファイル: [v19/iterative_pf_boost_aug_v19.py](../v19/iterative_pf_boost_aug_v19.py)(v19本体のコピー+機構3種、別artifacts/別db)。

### 追加機構(各 0 で無効 → Optuna が不要なら勝手に切る)
| 機構 | 狙う失敗 | 追加パラメータ |
|---|---|---|
| ① **dip水平化**(目標dipを md_since で 0 へ decay) | dip外挿の行き過ぎ(cat4/[[error_anatomy]]最大の機構的失敗)。ラテラルは水平化するのに PF はヒールdip `ir` を延々外挿 | `dip_zero_lam`(0で無効,1で完全水平化), `dip_zero_md`(減衰スケールft) |
| ② **datumモード粒子**(一部粒子を毎ステップ ±off に構造再シード) | 双峰datum(Milankovitch ±層厚, worst10%=誤差40%)。早期に片モードへcommit→谷 | `datum_prob`(割合), `datum_off`(オフセットft≈層厚) |
| ⑤ **アニーリング**(序盤の尤度を gs 拡大でゆるく) | 早期の片モード賭け | `anneal_amp`, `anneal_md` |

### 除外(GPUで重い)
- **窓NCC尤度**(窓×粒子で尤度が10-30倍)、**固定ラグ平滑**(2-3倍・別tuner v23有)。

### 実装メモ / 注意
- 実装は `_pf_core` に `md_since=(cur-md[:,0])` を足し、物理項の目標dipを decay(①)/ jump後に ±off 再シード(②)/ gs を序盤拡大(⑤)。すべて (B,N) elementwise で **GPUバッチのまま**。
- **SEARCH/EVAL seed=32**(★推論と揃える。n_seed一致がLBで効く=[[scores]]の r0_seed32 7.098)。
- ★**目的関数は v19 同型の in-sample train overall**。**過学習しうる**(v22 per-cat 10.198 / v24 n_seed128 8.026 で実証)。
  本気で汎化させるなら **out-of-fold(GroupKFold by well)版が本筋**([[analog_competitions]] の grouped-CV-by-well)。まずは v19同型で機構の効きを見る。
- 実行: `.venv/Scripts/python.exe v19/iterative_pf_boost_aug_v19.py` → `artifacts_v19_aug/pf_bank.json`。
