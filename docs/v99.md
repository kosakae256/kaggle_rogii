# v99 方針（ロードマップ）— lag192検証 → full平滑 → 逆方向PF特徴

> v98(normal, smooth=192)の結果を起点に、**1変更ずつ入れて CV/LB で採否**を判断する。
> 詳細アルゴリズムは [v99_full_smoother.md](v99_full_smoother.md) を参照。

## 前提（v98 normal の位置づけ）
- 今の v98 normal = **combo(v96+v97, lag16 CV5.8881) に smooth=192 を入れただけ＋微差(v96 robust 4バンク・5seed)**。DA・逆方向PFは無し。
- なので v98 normal は実質 **「lag192 が combo(lag16) を超えるか？」の検証run**。
- lag192 は create が ~8倍重い（実測 normal だけで v96 7.9h + v97 数h）。効果が出ても**コスパ問題**が残る。

## ステップ（この順で1つずつ）
### Step0（進行中）: lag192 の効果確認
- v98 normal を完走 → **CV(通常OOF)** を combo(5.8881) と比較。
- 判断:
  - **明確改善** → lag192 は効く。ただし重いので **Step1(full平滑)で安く同等を狙う**のが本命。
  - **横ばい/悪化** → lag192 は割に合わない。full平滑や DA/逆方向PF に振る。

### Step1: full平滑（fixed-lag192 を置換）
- 系譜ベース全区間スムーサ（前方フィルタ＋単一backward祖先sweep）。**O(T·B·N)＝lag非依存**（lag192の8倍→2倍）。
- **pf_1 実証: fixed192=7.654 → full=7.306（−0.35改善）＝速くて精度も上**（要 全バンク・全井確認、tail退化チェック）。
- やり方・メモリ対策・検証計画は [v99_full_smoother.md](v99_full_smoother.md)。
- 位置づけ: 「lag192の利得を1/4コストで（or それ以上で）得る」置換。Step0で lag192が効くと分かれば最優先。

### Step2: 逆方向PF特徴（backward PF feature）を追加
- 「PF推論の終端(toe)から逆走するPF」を **特徴列**として追加（DA=学習データ増強とは別物）。
- **比較のため最初は入れない**（clean baseline を先に確定 → その後 ablation で +逆方向PF の純増分を測る）。
- 過去知見を踏まえた設計（[[v10-backward-pf-helps]]）:
  - v10逆方向PF: CV−0.44 も **LB悪化**。失敗理由は naive init でなく「**forward答えに条件付け＝準重複ビュー**（脱相関せず）」。
  - `cmp_/vs_fwd`（forwardとの比較特徴）は**有害** → 入れない。
  - ★**独立init の逆PF**（forward解に条件付けない）にして、forwardと脱相関する誤差構造を狙う。
  - build_backward_v93.py が土台（v93→v98パス化して create の特徴生成に逆PFパスを1本追加）。

### （別枠）DataAugmentation 復活
- 逆方向DA/順方向DA（学習データ増強）は `v98/SKIP_DA` 削除で即再開可（CSV・aug parquet・train側連結ロジック全保持）。
- Step0〜2 の clean 比較が済んでから、脱相関脚として再投入を検討。

## 比較方法（重要）
- **1変更ずつ**（lag192 → full平滑 → +逆方向PF → +DA）投入し、各段の CV/LB 差を記録。
- 逆方向PF/DA は「純増分」を測るため、**直前の構成を固定して +1 の形**で入れる。
- 評価は overall(全行プール) RMSE。fold間分散も健全性指標として見る（[[cv-lb-policy]]）。
