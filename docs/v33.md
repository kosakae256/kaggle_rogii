# v33 — PF出力の「モード推定」診断(選択路線の再訪・安い診断)

> **状態: 診断ノート実装済(未実行)。** ファイル: `v33/diagnose_modes_v33.ipynb`。
> **PF再実行なし・新規計算なし**(v28 parquet の参照9本 + v29b blend OOF + v32 hardcore_diag のみ)。

## 仮説
「32×6本のPF出力からどれを信用すべきかを学習する」は、**軌跡単位の選択(v18/v20)では死亡済**
(行単位best PF=順序統計のノイズ、GR尤度系信号は全滅)。しかし v32 で状況が変わった:

1. 誤差の正体は**井戸レベルの裏バンドルbias(峰間~28ft)** — 決定は実質「表か裏か」の1次元。
2. **GR尤度と直交する外部情報(self/nbr)が存在**し、手書きルール(vote-hedge)で既に OOF −0.075 を実証済。

→ 選択の単位を「192本」から「**井戸ごとの2〜3モード(datumバンドル)**」に潰せば、
~600井戸×2択の井戸レベル分類になり、学習可能なサンプル効率になる、という仮説。

## 手法(診断の設計)
- **参照 = 9本**: v28 parquet の `pf_ancc_1..3`(tw)/`pf_self_1..3`/`pf_nbr_1..3`(has ゲート付き)。
  井戸ごとに `d_r = median(ref − blend)`(+井戸後半だけの tail 版)を観測。
- **モード分解**: d_r の1Dギャップ連結クラスタ(GAP_LINK=8ft)→ 中心 c が 4〜60ft の候補モード + stay(0)。
- **3つの go/no-go ゲート**:
  1. **モードoracle**: 井戸ごと正解モードを選べた時の overall。**自由定数シフト上限**(井戸別最適シフト)
     と比べた回収率で「候補の質」を測る。回収率が低ければ候補生成(per-seed dump等)側の問題。
  2. **特徴AUC > 0.6**: 投票率(vote/ext_vote)・ソース多様性(has_nbr等)・**NN−GBM datum不一致の方向(gnn_align)**・
     seed分裂代理(std列)などの真値不使用特徴で、オラクルモードを当てられるか。
     **対照群として GR尤度系(pf_mean_gr_abs0等)も入れてある — これは死ぬはず(v20の再確認)**。
  3. **学習ゲート**: LGBM/Logistic を候補モード行で GroupKFold(5) OOF 学習 → soft posterior-mean
     (`out = blend + λ·p̂·c`)の overall が **vote-hedge 6.7960 を下回るか**。

## 結果(2026-07-06 実行済)
| ゲート | 判定 | 数値 |
|---|---|---|
| ① モードoracle | **候補不足が判明** | 6.8711 → oracle 6.2403。**自由定数シフト上限 4.4494 の 26% しか回収できない** |
| ② 外部情報AUC | **PASS** | **ext_vote 0.821** / vote 0.788 / n_pset 0.742 / stay_share 0.730。**GR尤度対照群は予定どおり死亡(0.53/0.55)=v20の教訓を再確認** |
| ③ 学習ゲートOOF | **PASS** | best **6.7492**(p_lgb hard λ0.4 p≥0.4)< vote-hedge 6.7960(−0.047)。OOF AUC: Logistic 0.801 / LGBM 0.768 |

- 分裂井戸 163本 / 候補モード230行 / 正解モード(動くのが正解)50本。硬い核27本中16本に候補あり、9本に正解あり(v32の「~10本は参照側に正解」と整合)。
- **正解モードのプロファイル**: ext_vote 中央値 0.833(不正解 0.167)、n_pset=3(全パラメータが支持)、**stay_share=0(=参照が全員blendから離れている時、blendが間違っている)**、|c| 中央値 7.2ft(不正解 13.8ft=大きいシフト提案ほど嘘)。
- 死んだ特徴(意外な方): gnn_align(NN−GBM不一致方向)0.514 / seed_std 0.512 / has_nbr 0.533。効くのは「nbrがいるか」ではなく**外部参照の投票率**。
- 学習ゲートの取り分 0.122 は モードoracleの取り分 0.631 の19% → 選択の改善余地も残るが、**主ボトルネックは候補生成(ゲート①)**。
- 注意: best則は14則グリッドを同一OOFで選択=軽い選択楽観。LBで確認するまで−0.047は割引いて見る。

## 含意
1. **★自由シフトoracle 4.449 が最重要の数字**: 井戸ごと定数シフトだけで理論上 −2.42。井戸レベルbiasはこのコンペ最大の単一レバーであることが定量化された。
2. モード推定の枠組みは機能する(AUC 0.8、hedge超え)。**次の投資先は候補を増やすこと** = per-seed 32本dump(seed実軌跡のモード)/ nbr MAX_DIST緩和 / 他ソース追加 → 回収率26%を上げてから同じゲートを再学習(v34)。
3. 学習ゲートは vote-hedge の置換候補(submit実装は数十行)。ただしOOF差−0.047は転移~4割則でLB−0.02級 → v32のLB結果を見てから判断が合理的。

## 判定後の分岐
