# CV/LB 解釈方針(このコンペの意思決定ルール)

> ユーザー方針(2026-07-08)。実験結果の採否は原則これに従う。関連: [overfit_policy.md](overfit_policy.md)。

## 大原則: **CV を信じる**
このコンペでは **CV(overall pooled RMSE, 全行プール)を第一の判断基準**とする。
CV が改善した施策は、原則として採用してよい。

## CV と LB の関係(解釈の細則)
1. **CV が大きく改善しても、LB が改善しない/逆行することは「起こりうる」。** これ自体は異常ではない。
2. **大きく逆行する場合** … 考察の余地あり。何かがおかしい可能性があるので**調査する**
   (例: リーク、CVとLBで分布が違う軸を踏んでいる、後処理の過学習 等)。
3. **微妙に逆行する程度** … **おそらく正常**。ノイズ・分割差の範囲。過度に気にしない。
4. **LB が逆行しなかった(維持 or 改善)場合** … その施策は **間違いなく改善している**と考えてよい。
   → CV改善 かつ LB非逆行 = 採用確定。
5. **特段の調整なしで CV も LB も改善**する施策は、**Private LB(PB)でも効いている**と考えてよい。
   - 該当例: **smooth pf / neighbor pf / self pf**。これらは無調整で CV・LB 同時改善 → PB でも効く族。

## 知見メモ(2026-07-08 追記, v39×v36 LB6.430 の考察から)
1. **smooth pf / neighbor pf / self pf は CV・LB のいずれも縮める**(両面で効く実証済みレバー)。
2. **空間的な構造(prior)を含むと CV-LB の関係が安定する可能性が高い**(v39×v36: 転移率0.98=CV≈LB)。
   逆説的に、**GRだけに頼る(priorなし)場合は CV-LB 関係が不安定かもしれない**
   (v36 の 0.84 増幅は「得」に見えるが再現保証のない増幅であり、PBで剥がれるリスクを含む)。
3. **このコンペでは CV を重視するべき。ただし CV の改善に LB が追随しない場合は原因解明が必要**
   (例: v39×v36 では「隠しtestに硬い核が少なくpriorのtail価値が薄まる」と解明済み)。

## 追加原則: fold間分散の低さは重要(2026-07-11 追記)
- **5-fold の fold間スコア分散が低いこと自体が、手法の健全性の重要指標**。
- 経験則(ユーザー観測): **LB が CV に先行していた時代は fold間スコアが大きく分散していた**。
  現在(v52系, CV 6.0台)は **fold間がほぼ分散しない** — CV が信頼できる状態の証拠。
- 解釈: fold間分散が大きい = 一部の坑井(tail)や分割の偶然にスコアが支配されている
  = CV の点推定が不安定で、LB/PB への転移も読めない。
  fold間分散が小さい = 改善が坑井横断で一様に効いている = 転移が素直になる。
- 運用: **新しい施策の評価では mean だけでなく fold別スコアの並びも見る**。
  mean が改善しても分散が跳ねる施策は警戒(tail偏重・分割依存の兆候)。

## 運用への落とし込み
- 施策の採否: **CV改善を基本ゴー**。提出できるなら LB を確認し、**逆行しなければ確定採用**。
- 微逆行で止めない(正常範囲)。大逆行だけ立ち止まって原因を見る。
- 「無調整で CV・LB 同時改善」= 最も信頼できるシグナル(PB耐性あり)。この形を狙う。
- マジックナンバー/後処理の過学習に注意する点は従来どおり([overfit_policy.md](overfit_policy.md))。
  = 「調整して初めて効く」ものは PB で剥がれやすい。無調整で効くものを優先。
