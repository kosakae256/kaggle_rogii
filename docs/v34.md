# v34 — per-seed 候補 + クロスソース採点(v33ボトルネック=候補生成への投資)

> **状態: 実装済(未実行)。** ファイル: `v34/dump_seeds_v34.py`(GPU dump)→ `v34/diagnose_modes_v34.ipynb`(診断)。
> **ユーザー指示: paramセットは PF_LIB の `pf_1/2/3` の3本だけ**(PF_BANKのr0系や他paramを増やさない=実験を汚さない)。
> **ソースは tw / self / nbr の3種すべて実行**(self/nbr含めて「どの出力を信用すべきか」を学習するのが目的)。
> → GPU実行 = 3param × 3ソース = 9本(v28 create のPFパートと同構成)。

## 目的(ユーザーの指示)
**1井戸につき 3param(pf_1/2/3) × 2系統(smooth平滑 / forward生) × 3ソース(tw/nbr/self) × 32seed = 576本**
のTVT軌跡が得られる。このうち**どれが正しいかを学習する** — 学習には「どのpfから得たか」「GRは
tw/nbr/selfのどれか」「smoothか forwardか」のメタデータと、軌跡生成中に得られるあらゆる特徴量を使う。

## 仮説
v33 の結論=モード推定の枠組みは機能する(ext_vote AUC 0.821 / 学習ゲート 6.7492 < hedge 6.7960)が、
**候補が足りない**(モードoracle 6.240 = 自由シフト上限 4.449 の26%しか回収できない)。
候補を576本に拡げ、外部証拠の測り方を「平均参照のオフセット一致」から「候補軌跡そのものを
self/nbr grid で採点」に強化すれば、回収率と学習ゲートの両方が伸びるはず。
※ v20の教訓(軌跡単位のbest当てはノイズで学習不能)から、**学習の単位は軌跡クラスタ=モード**とし、
軌跡ごとのメタデータ(pf/ソース/系統/seed重み)は**モード上の質量として集約した特徴**で入れる。
576本のどれを信じるかは「モード選択 × モード内ww加重」として表現される。

## 手法
### A. per-seed dump(`dump_seeds_v34.py`)
- `run_smoother_ext` と同一のRNG消費(同一seed/チャンク構成/井戸順=parquet順、nbr無し井戸も
  twフォールバックでnbrパスに参加=create同一)で、**平均する前の per-seed 平滑軌跡(ps, 32×T)と
  forward軌跡(pfw=平滑なし)・log尤度・seed重み ww(likelihood_scale温度softmax)**を tw/self/nbr
  各パスで吐く。コアは無改造 — per-seed も forward(pts_f)も `run_smoother_ext` 内に既に存在し捨てられていた。
- **自己チェック内蔵**: dumpのseed加重平均(smooth側)≒ parquet `pf_ancc_k` / `pf_self_k` / `pf_nbr_k`
  (median<0.5ftならOK)。ズレ大なら create の設定が artifacts_v28 構築時からドリフトしている合図。
- 出力: `artifacts_v34/seed_dump_pf{1,2,3}.npz`(`{well}|ps_{tw,self,nbr}/pfw_*/ll_*/ww_*/gg_*/meta/gr`)。

### B. クロスソース採点(ノート側)
- 各候補モードの軌跡(=メンバーseedのww加重平均、seedメンバー無しは blend+c)を
  **tw/self/nbr grid で採点** `mean exp(-0.5((GR−grid(traj))/gs)²)` し、**blend軌跡とのマージン** xm_tw/xm_self/xm_nbr を特徴化。
  ext_vote(2値投票)の連続値・軌跡版。nbr grid は近傍≥2本の井戸のみ。

### 診断(`diagnose_modes_v34.ipynb`)— v33と同一ゲート・同一クラスタ設定(GAP 8ft, |c|∈[4,60])
1. **ゲート1**: モードoracle を候補プール3種(平均9本のみ / per-seed 576本のみ / 併合)で比較。回収率26%→?と、
   seed候補による新規カバー井戸数(参照9本ではstayだった井戸)。
2. **ゲート2**: 新特徴の単変量AUC —
   - **seed事後質量系**: ext_seed_mass(self/nbr)/tw_seed_mass/sm・fw_seed_mass(smooth vs forward)/
     n_src_seed/n_pset_seed/n_flt(支持の多様性)
   - **クロスソース採点**: xm_tw/xm_self/xm_nbr(モード軌跡のGR一致度 − blendのそれ)
   - **物理・荒れ具合系(2026-07-06 ユーザー要望で追加)**: rough_ratio(2階差分の荒れ、blend比)/
     dip_dev(実効dip中央値 vs 既知帯dip prior ir)/ dip_absmax(|dip|の95%点)/ geo_jump(geo_z最大ジャンプ)/
     smfw_gap(同一seedのsmooth↔forward乖離=平滑がどれだけ直したか)/ edge_frac(twレンジ端への張り付き率)/
     tail_dev(井戸後半だけのオフセット整合)/ ll_margin(支持seedの尤度優位、z正規化。GR系=対照群寄り)
     ※物理系はseedメンバーを持つモードのみ計算(blend+c縮退値でAUCを汚さない)。dumpに md/z/ir を追加保存。
   - **長さ系**: md_len(評価ゾーンMD長)/ md_step(行間隔)/ n_rows
3. **ゲート3**: 学習ゲートOOF が **v33 の 6.7492** を下回るか。適用ルールは3種を比較:
   - `soft` = top1モードに λ·p·c(v33同一)
   - **`post` = 全モードの確率加重 posterior-mean**(ユーザー案「1本commitせずn本を信頼度加重平均」のモード版。
     stay重み=1−max p。※等重み平均は双峰の谷間に落ちる[v19/v22実証]ので必ず信頼度加重)
   - `hard` = top1に λ·c(閾値ゲート)

## per-trajectory ランカー(2026-07-07 追加実装・未実行)
ユーザー仮説「seed 1本ずつにスコアを付ければどれかは刺さる」の実装。`v34/train_ranker_v34.ipynb`。
- **1行 = 1軌跡**(井戸×~576 ≈ 33万行)。ラベル = `median|traj−true|` の**井戸内z正規化**(連続値。
  v20死因のargmaxラベルを回避)。特徴27個 = メタデータ(src/pset/sm-fw/ww/ll_z)+コンセンサス相対
  オフセット+モード文脈(mass/is_top/ext_mass)+軌跡単体のクロスGR採点(x_tw/self/nbr)+
  物理(dip_dev/dip_absmax/geo_jump/rough_ratio/smfw_gap)+井戸コンテキスト。
- 学習 = LGBM回帰 GroupKFold(5)。**学習ゲート = 井戸内Spearman(q̂ vs 実誤差順位)**。
- 集約 = softmax(−β·q̂) / top-n 平均の加重平均軌跡。**集約ゲート = 等重みコンセンサスに−0.05以上
  勝てるか**(oracle 1本=「刺さる本」の存在量も毎回表示)。勝てば「学習済み集約PF軌跡」として
  v35 の特徴列(m34_cons の上位互換)へ還流。
- 生成物: `artifacts_v34/traj_table.parquet`(q_oof込み・再利用可)/ `ranker_results.json`。
- **★結果(2026-07-07 実行済)**: 井戸内Spearman median **0.654**(89%正。ただし相当部分はd_abs=
  「コンセンサスに近いほど良い」の自明成分)。集約 = **softmax β0.5 で 7.9452 vs コンセンサス 8.1744
  (Δ−0.229)→ PASS**。**oracle(1本)= 4.147** — 「どれかは刺さる」仮説は強く実証(自由シフト上限4.449
  より深い=形も合う軌跡が存在する)。ただしランカーが拾えたのは oracleギャップ4.03の**6%**。
  テーブル40.9万行/773井戸。→ 還流: 学習済み集約軌跡(q_oof softmax加重)を v35 の `m34_lrn` 列
  (m34_cons=コンセンサス8.17の上位互換)として追加するのが次。純PF軌跡として7.95はv9 GBM raw(7.99)級。
