# v70 — GR多表現 × iTransformer(inverted attention) — PF不使用・struct on/offトグル

> 発端(2026-07-15 ユーザー): v69 が struct/PF錨依存で転移崩壊(CV6.25→LB7.43, +1.18)した反省 →
> **PFフリー**で組み直す。「iTransformer を v70 で。struct は on/off 切替。GR の表現(感覚を狭める=間引き/MA/
> self/neighbor)で相関が変わるので、それらを適用した入力を作る」。

## 仮説
LB を殺すのは struct/PF錨(CVレバー, [[cv-lb-policy]])。**転移するのは GR マッチ**。so **PF/錨を外し、GR の多表現
(相関が変わると実証済みの表現群)を全部チャネル化して、iTransformer に「どの表現を信じるか」を学ばせる**。

## 設計(`v70/itransformer_v70.py`)
- **PF完全不使用**。入力は GR 由来のみ。v68 の PFフリー cache(tw/self/nbr グリッド + struct + base_free)を流用。
- **GR多表現 = 22ch**:
  - well GR: raw / MA{3,7,15} / 間引き(MD-10 bin平均→補間)  = 5（"感覚を狭める/MA"）
  - 錨(struct or flat)での照合残差: (well − 参照@錨)/GR_SIG × {tw, self, nbr} + valid  = 5
  - **ローカル δ 照合(PF不使用の双峰シグナル)**: 各参照で δ窓の best/2nd-best コスト差(gap=双峰度)+ best位置  = 9
  - struct信頼度 + struct on フラグ + 行位置  = 3
- **struct on/off トグル**(`STRUCT=1/0`, v68 と共通 env): on=struct を δ 錨中心 + 信頼度ch / off=base_free(flat hold)錨・struct chゼロ・δ窓広く(v68 の DR_EFF)。
- **モデル = iTransformer核 + axial**: 純iTransformer は MD を token に畳む→行ごと予測に不向き。so
  **変数(表現)軸の self-attention(=inverted attention, どの表現を信じるか)** + **MD軸 TCN(dip連続)** の2軸。
- **出力 = δ分布→posterior-mean**(双峰を平均で潰さずヘッジ, error_anatomy §4)。TVT = 錨 + δ。
- **転移ガードレール = leave-field-out**(CV_MODE=field。NN脚のLB非転移を早期検出, v34/v62/v69)。

## 使い方
```bash
EVAL_STRIDE=4 .venv/Scripts/python.exe v68/gridfilter_v68.py cache      # 無ければ(v70はv68 cache流用)
CV_MODE=field STRUCT=1 .venv/Scripts/python.exe v70/itransformer_v70.py # struct有り(本命判定)
CV_MODE=field STRUCT=0 .venv/Scripts/python.exe v70/itransformer_v70.py # struct無し(完全転移安全側)
```

`ATTN_HEADS(4) TCN_LEVELS(4) DROP(0.1) LMR(30) LMS(3) N_WELLS(0=全)`

## PF入力オプション(2026-07-15 追加, `PF=1` 既定)
GR多表現だけだと錨から動けない(field_st: overall 9.67 ≈ struct基準 9.70 = ほぼ学習せず)。
→ **v28 の既存PF出力(再実行なし)を入力ch化**。`build_v28pf_v70.py` が v28 parquet(frac1.0)の pf_ancc/pf_ancc_std を
v70 cache 行に `::stride` で整列(検証: target=残差+lk が maxdif0)→ `v28pf_s{stride}.pkl`。
build_feats に **+4ch**: pf_δ(=pf_ancc−錨)/ log std(信頼度)/ PF位置でのGR残差(tw)/self残差。V=22→**26**。
- 逐次で解いた強い推定を渡すので「錨から動けない」を解消するはず(PF単体誤差は坑井4〜21ft, 錨9.7より良い)。
- ★ただしこれは v70 が避けていた PF(転移レバー)の再導入。**PF=1/0 を field-out で比較**して転移を測ること。
実行: `EVAL_STRIDE=4 python v70/build_v28pf_v70.py`(初回) → `CV_MODE=field STRUCT=1 PF=1 python v70/itransformer_v70.py`。

## ★PF-fusion(iTransformer_PF_fusion.md 準拠, `v70/pffusion_v70.py`)2026-07-15
「全特徴フラット化」でなく **PF単位トークン化 → per-PF Temporal Encoder(TCN) → cross-PF Attention → Gating/Fusion**。
時刻ごとに信頼度 α を出し **TVT = Σ α_k·pf_ancc_k**(convex fusion)。仕様の要点を全実装:
- per-PFトークン特徴 F=5: 合意からのずれ(rel_med)/log std/各PF位置のGR不一致(tw/self/nbr)。共有文脈=GR多表現z+disagreement+rowfrac(+struct任意)。
- §5 損失 = L_state(融合RMSE) + λ_o·**KL(soft-oracle q ‖ α)**(q=softmax(−誤差/τ_o)) + λ_s切替罰(既定0)。
- §8 residual Δx = 既定OFF(`RESID=1`で系統誤差補正)。§6 convex-oracle を毎回併記。
- **struct判断: 既定OFF**。融合出力は struct-free PF(v28 9本)で束縛→coreはstruct不要。`STRUCT=1`でgating補助文脈にs_tvt/s_sig(転移レバーなので任意)。

### §9 ベースライン/oracle(v28 9本, 全946k行, 実測)
best-fixed 9.008 / mean 7.588 / median 7.579 / inv-var 8.782(std重みは逆効果) / hard-oracle 3.675 / **convex-oracle 3.555**(融合の真の上限。真値がバンク範囲外=38.7%はconvex不可→Δx領域)。
現状の融合到達点(要 field-out): median 7.58 → **convex-oracle 3.56 まで ~4ft の余地**。
実行: `CV_MODE=field python v70/pffusion_v70.py`(struct無し融合) / `RESID=1`(残差も)。スモーク40坑井OK。
